- **范围：涉及 UI，但本轮只分析，不改代码。** 现有美工刀未提交改动未触碰；当前实现基线为 `a835efc`。
- **复验环境**：用户当前项目，`333` 个 React Flow 节点、`289` 条普通边，页面 `2560×1440`；桌面开发版同库打开。当前项目 `childEdges=0`，因此容器子边结论来自代码路径，不从这份项目数据冒充现场复现。
- **根因 1：拖动时只移动了节点外壳。** `useFlowNodeDragDomFollow.move()` 每帧只调用 `writeFlowNodeDragDomPositions()` 和 `writeFlowDragEdgePaths()`；前者只改 `.react-flow__node[data-id]` 的 transform。实测拖动 `180×120px` 当帧，节点位移 `180×120px`，标题 / 像素位移仍为 `0×0px`；松手后才一起跳到新位置。
- **根因 2：标题和像素是单独的 screen/header 层。** `FlowNodeHeaderLayer` 从 store graph 的节点坐标生成标签，而 store 在拖动中不逐帧更新。此前拖动时整层 `visibility:hidden`，`a835efc` 为满足“不隐藏外观”删除该规则后，没有补 DOM follower，于是旧问题从“标题消失”变成“标题留在原地”。
- **根因 3：端口层冻结旧图且没有拖动位移。** `FlowPortLayer` 在拖动时保留旧的 `sourceGraph`，只按视口 transform 定位，不消费节点拖动 delta。实测节点向上移动 `45px` 时，输入 / 输出端口命中块 `y` 坐标完全不变；大号 `+` 不是新增节点或错误端点，而是旧位置的端口可视化。普通连线已经接到节点的新边缘时，看起来就会跨过旧 `+` 或像发生分叉。
- **根因 4：容器 / 分组子边被刻意冻结。** `FlowChildEdgeLayer` 在 `store.getDraggingId() !== null` 时使用 `frozenGraphRef`，松手后才读新图；且该层路径只有 `data-edge` / `data-child-edge`，没有 `data-edge-source/target`，不会进入普通边 follower。涉及组、批量、容器子节点的连线在拖动中必然停在旧位置。

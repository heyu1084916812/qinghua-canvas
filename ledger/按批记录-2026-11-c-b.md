## 2026-11-23 · #1182 真实画布拖动首帧与灯箱偶发无动画

| 编号 | 状态 | 证据 |
| --- | --- | --- |
| 1182 | ✅ 已修复并完成真实画布与四组合复验 | `review/2026-11-23-1182-drag-lightbox/result.json` |

- **范围：涉及 UI**。在用户当前 332 节点、230 张真实图片项目上全屏复验；美工刀未提交改动未触碰。
- **拖动根因**：真实节点是顶层节点（`parentId=null`），但 ReactFlow 节点指针路径使画布表面的 React `onPointerDownCapture` 未执行，`data-direct-drag` 始终为空；节点只能等 RF 下一次 position 回调，用户看到整张图片追鼠标。参考线层 `pointer-events:none`，且不参与拖动状态，不是原因。
- **修复**：`FlowSurface` 改用表面原生 `pointerdown` capture 记录锚点；拖动态由 `useFlowNodeDragDomFollow` 的首拍直接写 DOM，RF 与 store 结算顺序不变。
- **灯箱根因**：原图 `useAssetMeta` 在重负载下可晚于 overlay 挂载；`[data-lightbox-media]` 缺失时，关闭逻辑命中同步兜底并直接 `closeLightbox()`，入场克隆也会停在原地。已用 pointer-time 缩略图作为同 hash 的首帧媒体，并在完整原图到达后替换；退场不再要求目标媒体节点存在。
- **实测**：全屏 2560×1392、约 45.6% 缩放下同屏 21 张真实图片。系统鼠标 4 段往返长拖（约 1000–1750px）首拍均进入直拖；松手位置最大误差 `0.2992px`，逐帧 32 次采样最大跟随差 `0.000427px`。连续 8 次双击开关灯箱均保留退场动画，结束时间 `402.1–417.1ms`，8/8 在 520ms 时已有媒体。
- **UI 门禁**：1440×900 / 1024×700 × 明暗四组合，灯箱 overlay / media 均存在，`pageOverflowX=false`，截图与 `result.json` 在 `review/2026-11-23-1182-drag-lightbox/`。
- **正式性能门禁**：先停止开发壳与 Vite 环境噪声后通过。300 节点 / 500 连线 / 150 张真实图片，pan P95 `13.9 / 7.4 / 7.3ms`，zoom `7.4 / 7.3 / 7.3ms`，drag `7.4 / 7.3 / 7.3ms`，三轮均恢复 `300/300`，150 图全部 decoded，page / console error 均为 0；证据 `.playwright-verify/canvas-perf-release-2026-11-23T13-42-11-045/report.json`。

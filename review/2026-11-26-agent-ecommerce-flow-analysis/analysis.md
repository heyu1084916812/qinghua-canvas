# 电商 Agent 工作流问题分析

## 结论

九个现象归到五条主链：

1. 请求分类没有稳定识别电商套图，任务计划与用户验收没有进入。
2. Skill 只能由 chip 显式注入，Agent 不能搜索用户库。
3. 计划落地缺少统一比例、文字排版和套图锚点的确定性检查。
4. 研发调研的词、来源和失败原因没有形成可解释的完整 UI。
5. 参考分析失败不阻塞，工具状态又在确认前提前显示完成。

## #1207 没有醒目的“验收中”提示（已修复）

- `runNode` 成功后只写 `resultsReadyAt`，计划卡里出现一个较小的“结果待验收”标签。
- 真正的用户验收卡仍要等模型再次调用 `requestTaskConfirmation(review)`；界面没有由 `resultsReadyAt` 自动弹出的“验收中 / 通过 / 需修改”卡。
- 用户不应该从过程日志里推断当前是否在等自己验收。
- 已修复：计划进入待验收时，直接显示 sticky 验收条与“验收通过，继续”；需要修改可直接在输入框说明。

## #1208 Skill 不自动加载（已修复）

- `agentTurnRequest.ts` 只把本轮 skill chip 交给 `resolveAgentSkillsForTurn`。
- 会话 `skillId` 没有 chip 也不注入；`allSkills` 不进入模型可见上下文。
- 工具目录没有搜索 / 读取 Skill 的能力。
- 已修复：新增 `chooseAgentSkillsForTurn`，无 chip 时按本轮正文与用户技能元数据确定性匹配；显式 chip 仍优先，自动命中显示真实技能名。

## #1209 文字排版缺失 / #1210 锚点不统一（已修复）

- 文字排版、主图组合、卖点层级规则主要在 `image-ecommerce` Skill；Skill 未加载时通用链没有同等硬约束。
- `seriesAnchors.ts` 只覆盖 Logo → 包装 → 海报；五张主图通常都判为 poster，不会形成派生锚点。
- 已修复：电商意图写入持久任务约束，`applyPlan` 前检查共享产品 / 首屏锚点、文字层级和非白底节点的排版字段；未写比例时整套默认 `1:1`。

## #1211 生成前比例已经错（已修复）

- 用户说的是生成前参数就带错了，不是生成完成后缺少检查。
- 计划落地会保留每个节点自己的 `data.ratio`；某张节点漏写时会继承渠道默认配方。
- 当前没有把“用户本轮明确要求统一 1:1”归一化成全组强制参数，也没有在 `runNode` 前拦截不一致。
- 视觉验收事后发现不一致只是兜底结果，不是解决方案。
- 已修复：从用户原话提取整组唯一比例；`applyPlan` 前写入全部新建图片生成节点，`runNode / runFrom` 前再次校验，不一致直接拒绝。

## #1212 问题卡文案错位（已修复）

- `questionCardText()` 只剥离题目回显，不检查模型 intro 中的题数、执行承诺或出图数量。
- 已修复：用户可见引导由真实题数确定性生成“开工前先确认 N 个关键点”，不再使用模型 `intro` 中的题数或执行承诺。

## #1213 调研词与来源原因（已修复）

- 查询词来自模型自由生成，`researchQueriesOf()` 只做 trim / 去重，没有电商中文平台模板。
- `siteStatuses` 已包含失败原因，但 `AgentPanel` 没有消费；图片模式收尾正文又被隐藏。
- 已修复：电商查询自动补主图排版、淘宝京东商品图、详情页卖点和英文商品图角度；结果卡展示真实检索词、目标 / 实收、每站数量与失败原因。

## #1214 图片数量（已修复）

- `designResearch.ts` 和工具 schema 都把 `imageMaxResults` 限制在 30–50。
- 已修复：默认目标 100，工具允许 100–120，对话最多保留 120；来源不足时显示目标、实收和各站原因。

## #1215 参考失败与提前完成（已修复）

- `reviewTurnReferences()` 失败后只记录 warning；`agentTurnRequest.ts` 仅 notify，不阻止后续 `applyPlan`。
- `conversation.ts` 在只看到工具调用、还没有结果或仍在等待确认时就用完成态 label；`runNode` 因而提前显示“已运行生成”。
- 已修复：显式参考分析失败写 `blockedIds` 并阻塞建图 / 生成；用户明确跳过后写 `skippedIds`。工具结果回来前显示“等待确认后生成”，不再提前说“已运行生成”。

## 建议修复顺序

1. #1207 + #1215：先让计划、验收和真实工具状态一致。
2. #1208–#1210：自动 Skill、文字门禁、电商锚点。
3. #1211 + #1212：比例硬门禁与问题卡文案。
4. #1213 + #1214：调研查询质量、来源可解释与 100 张目标。

# #1203 全局前端模型目录落点核对

## 当前结构

- 模型映射属于「当前渠道 + 当前 Key 分组」：每行把全局前端显示名绑定到该分组的上游真实模型 ID。
- 前端模型目录属于全局：`customModels` 保存新增模型，`uncommonModelIds` 保存常用 / 不常用状态。
- 「模型映射」标题右侧齿轮打开「前端模型目录」弹窗。弹窗已有显示名称、分类、图标和添加动作。
- 新增模型删除目前只出现在弹窗底部自定义模型的 `×` chip；映射行没有删除。
- `removeGlobalModel()` 当前只允许删除 `customModels`；内置 `PRESET_MODELS` 会被 store 明确拒绝。
- 映射表已显示「前端显示模型 / 真实模型 / 常用设置」，但已有模型名称不可编辑。

## 建议落点

### 推荐：齿轮弹窗升级为完整目录管理

弹窗分成两段：

1. 新增前端模型：显示名称、分类、图标、添加。
2. 已有前端模型：按分类过滤，每行显示图标、名称、常用 / 不常用、删除。

理由：删除、重命名、常用状态都影响所有渠道，放在全局目录里语义正确；映射表继续只负责“这个渠道怎么翻译”。

### 可选：映射行尾加操作菜单

在常用开关右侧增加一个 `…` 菜单，提供「重命名 / 删除」，只对自定义模型启用。

优点：入口离模型最近。

代价：同一模型会在每个渠道页重复出现，用户容易误以为只删除当前渠道的配置；窄屏也更拥挤。

### 不推荐现在做：独立全局页面

把前端模型目录拆成新的设置页最清晰，但会改动设置页信息架构，和当前“渠道设置里管理全局模型”的结构跨度较大。本轮做弹窗内目录即可。

## 待确认

1. 删除是否只针对新增的自定义模型，内置模型保留为不可删除？
2. 如果内置模型也要删除，是永久从目录隐藏，还是等同“设为不常用”？
3. “前端模型名称”是指新增时的显示名称已经够用，还是已有模型需要重命名？
4. 如果已有内置模型也要重命名，建议增加独立显示名覆盖，不能直接改逻辑 ID；否则旧节点、映射键和别名解析会断。

# Key 分组文件夹标签（#1144 二 / 三轮）

## 需求

**二轮（2026-11-17 上午）**：Key 分组改 folder tabs；去掉状态点与编辑 / 删除按钮，只保留一个文件夹标题；
点其他标题滑过去；文字与输入框随文字自适应且不能太长；选中态只有一个形状、里面只有文字与优先级；
未选中标题没有背景色；双击标题改名、右键标题出「编辑 / 删除」菜单。

**三轮（2026-11-17 下午，用户对着截图提的）**：

1. 形状要**圆角**的（不要斜切梯形），像现代浏览器标签页；
2. **选中的分组自动展示在第一列**，像文件夹那样；
3. 修 bug：加号和文字不在同一排（图二）；
4. 标签栏与下方表单容器重构成圆润的 Folder Tabs：沿用项目原有配色、选中标签与卡片**同色无缝**、
   未选中标签**有完整底色且比选中深一档**、顶部统一 10–12px 圆角、选中标签底部加**内凹圆弧过渡**、
   第一个标签选中时卡片左上角与标签左边缘对齐。

## 结果

- **形状就是参考图那条**：所有标签统一 44px 高、12px 顶角；两枚标签之间只隔 6px，
  再用「页面底色 + 1/4 椭圆」把标签上角啃掉（宽 16px、高 44px），啃出来的弧从顶边一路削到
  卡片顶边 —— 两枚标签的弧拼成参考图里那个 V 形缺口。
- **选中标签与下方卡片同底色、无缝相接**：`--bg-subtle`，底边直接落在卡片顶边上，中间没有边框或分割线；
  卡片左上角是直角、与标签左边缘垂直对齐，右侧与底部是 10px 圆角。
- **选中分组永远排第一列**：渲染时把当前分组提到数组首位，其余保持原顺序；点任意标签，
  它立刻挪到第一位（文件夹式）。因为选中项总在第一位，卡片左边缘天然与标签左边对齐。
- **未选中标签**是完整标签页底 `--bg-tab-idle`（浅色 #f2f2f2 / 深色 #1e1e1e，只比卡片深一小档），
  同样带 12px 顶角与两侧削边，所以两枚标签之间才会出现窄缝 + V 缺口。
- **加号与文字同一中线**：标签与按钮都按 44px 中线居中（34px 按钮 `margin-bottom: 5px`），
  实测三者中心完全相等。
- 其余口径不变：标题里只有名称与 `P<优先级>`，宽度自适应（上限 220px、超出省略号），
  双击改名（输入框按文字撑开、上限 160px），右键「编辑 / 删除分组」菜单内二次确认。

## 为什么这么做

- **为什么选中项排第一**：用户要「像文件夹一样」。同时它让选中标签永远贴左边，
  卡片左上角不用为「标签在中间」留圆角缺口，削边也只需要处理右边的缝。
- **为什么用「页面色 + 1/4 椭圆」啃角，而不是给标签画一圈边**：参考图的缝是页面底色透出来的，
  不是描边；啃角能把缝精确做成 V（顶部宽 16px×2+6，底部只剩 6px），且不用引入任何新颜色。
- **为什么标签等高（44px）**：上一轮试过「选中更高」，代价是文字基线与加号错开 —— 正是用户报的 bug。
  参考图实测两枚标签顶边齐平，等高后文字、加号天然同一条中线。
- **为什么 `--bg-tab-idle` 按主题各给一值**：两套主题亮暗方向相反（浅色页面白、卡片浅灰；
  深色页面更暗、卡片更亮），一条 `color-mix(…, var(--bg-canvas))` 在浅色下会算出比卡片还浅、
  几乎看不见的底。令牌仍集中在 `tokens.css`，不引入新色相。

## 复核要点（给用户）

- 点任意分组：它是否立刻挪到第一列，标签块是否跟着变宽 / 变窄；
- 看选中标签右下角那条内凹圆弧，以及它和下方「模型列表」卡片的接缝；
- 加号是否与标签文字在同一条中线；
- 明暗两套：浅色下未选中标签是浅灰（#ececec），选中标签与卡片同为 #f5f5f5。

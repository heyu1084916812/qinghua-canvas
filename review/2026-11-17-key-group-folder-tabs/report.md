# Key 分组文件夹标签（#1144 二 / 三轮）

## 需求

**二轮（2026-11-17 上午）**：Key 分组改 folder tabs；去掉状态点与编辑 / 删除按钮，只保留一个文件夹标题；
点其他标题滑过去；文字与输入框随文字自适应且不能太长；选中态只有一个形状、里面只有文字与优先级；
未选中标题没有背景色；双击标题改名、右键标题出「编辑 / 删除」菜单。

**三轮（2026-11-17 下午，用户对着截图提的）**：

1. 形状要**圆角**的（不要斜切梯形），像现代浏览器标签页；
2. **选中的分组自动展示在第一列**，像文件夹那样；
3. 修 bug：加号和文字不在同一排（图二）；
4. 标签栏与下方表单容器重构成圆润的 Folder Tabs：沿用项目原有配色、选中标签与卡片**同色无缝**、
   未选中标签**有完整底色且比选中深一档**、顶部统一 10–12px 圆角、选中标签底部加**内凹圆弧过渡**、
   第一个标签选中时卡片左上角与标签左边缘对齐。

## 结果

- **选中分组永远排第一列**：渲染时把当前分组提到数组首位，其余保持原顺序；点任意标签，
  它立刻挪到第一位（文件夹式）。因为选中项总在第一位，卡片左边缘天然与标签左边对齐，
  卡片左上角用直角、右侧与底部用 `--radius-control`（10px）。
- **圆润造型**：所有标签 12px 顶部圆角、统一 52px 高；选中标签由一块独立背景层画（和卡片同底色
  `--bg-subtle`），宽度取自真实 DOM（切换分组时 220ms 过渡）；未选中标签是完整标签页底
  `--bg-tab-idle`（浅色 #ececec / 深色 #1b1b1b），比选中深一档。
- **底部内凹圆弧**：选中标签右下角用 `::after` + `radial-gradient(circle at 0 100%, …)` 补一块卡片色、
  挖掉 1/4 圆，让标签右切线平滑过渡到卡片顶边；左边不画（它就在卡片左边缘上）。
- **加号与文字同一中线**：标签 52px 内文字居中，加号 34px 用 `margin-bottom: 9px` 抬到同一中线；
  实测两者中心完全相等（472 / 472）。
- 其余口径不变：标题里只有名称与 `P<优先级>`，宽度自适应（上限 220px、超出省略号），
  双击改名（输入框按文字撑开、上限 160px），右键「编辑 / 删除分组」菜单内二次确认。

## 为什么这么做

- **为什么选中项要排第一**：用户要「像文件夹一样」。而这同时消掉了两个麻烦：选中标签永远贴左边，
  卡片左上角就不需要为「标签在中间」留圆角缺口；内凹圆弧也只需要画右边一条。
- **为什么用一块独立背景层而不是给选中标签自己上色**：标签宽度随文字变，`background` 变化没有过渡；
  独立层的 `width` 可以过渡，切换分组时新旧宽度之间是平滑的。
- **为什么不给标签做高度差**：浏览器标签常见「选中更高」，但那样文字基线会和加号错开 ——
  这一轮用户报的正是「加号和文字不在同一排」。统一 52px 后三者共用一条中线，问题从结构上消失。
- **为什么新增 `--bg-tab-idle` 令牌**：两套主题的亮暗方向相反（浅色页面白、卡片浅灰；深色页面更暗、
  卡片更亮），一条 `color-mix(…, var(--bg-canvas))` 在浅色下会算出比卡片还浅、几乎看不见的底。
  所以在 `tokens.css` 里按主题各给一个值，不引入新色相，也不在组件里写死颜色。

## 复核要点（给用户）

- 点任意分组：它是否立刻挪到第一列，标签块是否跟着变宽 / 变窄；
- 看选中标签右下角那条内凹圆弧，以及它和下方「模型列表」卡片的接缝；
- 加号是否与标签文字在同一条中线；
- 明暗两套：浅色下未选中标签是浅灰（#ececec），选中标签与卡片同为 #f5f5f5。

## 2026-11-16 渠道设置反馈修复（#1139）

- 模型映射的产品起点是**当前 Key 分组能用的前端模型**：先按当前分组真实模型的分类筛前端模型，再在行内选择真实模型。不要改回“平铺整份全局前端模型目录”，否则用户会看到当前分组根本无法映射的行。
- “不常用”是全局前端模型开关，但必须在当前映射表即时体现：默认隐藏该行，映射数据保留；“显示不常用模型”负责恢复查看。按钮切换不是只改文字，必须让该行消失。
- API Key 行是四个独立几何：输入框（眼睛绝对定位在框内）、保存按钮、官网入口。输入 wrapper 不能吃掉右侧按钮；`tokenInput` 必须 `width:100%`、`box-sizing:border-box`、`padding-right` 给眼睛留位。
- RunningHub 的工作流入口由协议严格判定 `selected.protocol === 'runninghub-api'`，不能按渠道是否“看起来像 RunningHub”或对所有渠道显示。
- 设置页交互态继续走全局令牌：hover 用 `--bg-hover`，控件圆角用 `--radius-control`，胶囊才用 `--radius-pill`；不要引入局部 4/5/6/8/999px 或未定义 `--warning`。
- 验收口径：1440×900 / 1024×700 × 明暗四组，几何断言输入框/眼睛/保存/官网互不覆盖、可见方按钮圆角一致、无横向溢出、pageerror 0；证据见 `review/2026-11-16-channel-settings-feedback/after-v2/`。
- 长驻 Vite 进程热更新后可能残留同一 CSS Module 的旧哈希，导致 `:hover` 规则引用旧 `.item`，表现为拖拽手柄/三点按钮不出现。冒烟前先起全新 Vite 进程；本轮 g8/g44/g45/g74 四组 97/97 通过。
- 2026-11-16 #1140：模型映射按 `生图 / 对话 / 视频 / 配音` 分组；右侧常用状态用真正的 `role="switch"`，开=常用、关=不常用，关闭后默认隐藏、映射保留。分类与开关样式独立到 `SettingsModelCategory.module.css`，避免抬高映射主模块预算。
## 2026-11-17 模型映射分类过滤与渠道控件收口（#1141 / #1142）

- #1141：映射分类不能用纵向分组全部铺开。分类必须是单一 `tablist`，默认只渲染首个可用分类的 `tabpanel`；实测以“生图”和“对话”的 `data-route-map-category` 集合为判据，不能只数按钮。键盘左右键、Home / End 要一起验。
- #1142：渠道设置里的原生 `<select>` 是错误控件。快速测试改用 `ChoicePicker` 后，黑描边、箭头边距和菜单外观才与项目一致；运行按钮必须显式固定与选择器同高，不能只靠通用按钮内边距。
- 渠道优先级/权重属于名称行，不再单独占一整条带边框的说明行。普通 `openai-compatible` 的泛化长说明在渠道页隐藏；RunningHub 站点专用说明仍需保留，别把 `selectedProtocolNote` 一刀切删掉。
- API Key 下方重复“已保存”已移除；保存态由输入框尾号占位表达。通用输入、协议、Key 保存按钮和快速测试控件统一 34px，后续新增同区控件先对齐这个高度。
- 验收口径：1440×900 / 1024×700 × 明暗四组，量 bounding rect 而不是只看截图；本轮记录同排中心差 ≤4px、控件高 34px、箭头右距 13px、焦点环 2px、菜单圆角 10px。证据在 `review/2026-11-16-channel-settings-feedback/after-v4-category-filter/` 与 `after-v5-polish/`。
- 冒烟结果：#1141 后 `g74 48/48`、`g83 4/4`；#1142 新增几何断言后 `g74 52/52`、`g45 12/12`。全量 Vitest 6460 通过 + 1 跳过，`npm run check` / build / detector 通过。

## 2026-11-17 渠道设置全控件高度统一（#1143）

- 用户说“不只是这四组”后，不能再只修地址/协议、快速测试、底部按钮。渠道页标准矩形控件必须全量扫描，包含左侧搜索/添加、连接操作、分组标签、Key 保存/获取令牌、分组字段、模型按钮、分类标签、映射下拉、常用开关外框、快速测试和底部操作。
- 统一档位：标准矩形控件 34px；纯图标按钮 28px；输入框内嵌眼睛 26px；开关轨 20px；快速测试多行输入 85px。
- 视觉差值大于数值差的三个根因：① 页面原来混用 26/28/30/32/34 五档；② `content-box + padding/border` 会偷偷多出 2px；③ 同高控件使用不同底色/行高，视觉重心不同。标准控件必须固定 `height`、`min-height` 和 `border-box`，地址/协议等同类控件还要同底色同边框。
- CSS 变量建在渠道 `.form`：`--settings-control-height:34px`、`--settings-icon-control-size:28px`、`--settings-inline-icon-height:26px`、`--settings-switch-height:20px`。QuickTest 等外置模块使用带 fallback 的 var，避免离开渠道表单时失效。
- 验收不能只抽查几组，必须聚合全量标准选择器高度集合。本轮四组均为 `[34]`、异常 0；`g74 55/55` 已把该集合和例外档位写死。证据在 `review/2026-11-17-channel-control-heights/`。

## 2026-11-16 渠道设置反馈修复（#1139）

- 模型映射的产品起点是**当前 Key 分组能用的前端模型**：先按当前分组真实模型的分类筛前端模型，再在行内选择真实模型。不要改回“平铺整份全局前端模型目录”，否则用户会看到当前分组根本无法映射的行。
- “不常用”是全局前端模型开关，但必须在当前映射表即时体现：默认隐藏该行，映射数据保留；“显示不常用模型”负责恢复查看。按钮切换不是只改文字，必须让该行消失。
- API Key 行是四个独立几何：输入框（眼睛绝对定位在框内）、保存按钮、官网入口。输入 wrapper 不能吃掉右侧按钮；`tokenInput` 必须 `width:100%`、`box-sizing:border-box`、`padding-right` 给眼睛留位。
- RunningHub 的工作流入口由协议严格判定 `selected.protocol === 'runninghub-api'`，不能按渠道是否“看起来像 RunningHub”或对所有渠道显示。
- 设置页交互态继续走全局令牌：hover 用 `--bg-hover`，控件圆角用 `--radius-control`，胶囊才用 `--radius-pill`；不要引入局部 4/5/6/8/999px 或未定义 `--warning`。
- 验收口径：1440×900 / 1024×700 × 明暗四组，几何断言输入框/眼睛/保存/官网互不覆盖、可见方按钮圆角一致、无横向溢出、pageerror 0；证据见 `review/2026-11-16-channel-settings-feedback/after-v2/`。
- 长驻 Vite 进程热更新后可能残留同一 CSS Module 的旧哈希，导致 `:hover` 规则引用旧 `.item`，表现为拖拽手柄/三点按钮不出现。冒烟前先起全新 Vite 进程；本轮 g8/g44/g45/g74 四组 97/97 通过。
- 2026-11-16 #1140：模型映射按 `生图 / 对话 / 视频 / 配音` 分组；右侧常用状态用真正的 `role="switch"`，开=常用、关=不常用，关闭后默认隐藏、映射保留。分类与开关样式独立到 `SettingsModelCategory.module.css`，避免抬高映射主模块预算。

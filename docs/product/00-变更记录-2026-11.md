> **2026-11-10 轻画 Clipper 浏览器扩展正式版**：扩展已从基础发送器补齐为完整 MV3 工具：工具栏弹窗、
> `Ctrl+Shift+Y` / `Command+Shift+Y` 快捷键、网页与链接右键菜单、在线/离线/超时/令牌错误状态、
> 配对设置、令牌显示切换、最近发送记录和不可收藏页面提示。它只访问 `127.0.0.1:53684`，只发送
> 当前公开网页 URL、标题和配对令牌，不读取 Cookie 或浏览历史。
>
> 安装方式是 Chrome / Edge 开发者模式“加载已解压的扩展程序”；分发时运行
> `npm run package:clipper-extension` 生成 `release/qinghua-clipper-0.2.0.zip`。Lovart 的同类产品
> 在未安装状态使用“随处收藏灵感 / 一键把网页图片收藏进 Lovart”的空态与安装入口，轻画保留同一使用
> 心智，但把配对、检测和错误恢复放在扩展弹窗里，不依赖第三方账号。

> **2026-11-10 套件上下文、统一筛选、画布浏览器与免费联网调研**：参考面板和“我的素材”里的套件卡
> 都按整卡点击加入 Agent，生成一枚套件 chip；“打开”只负责进入套件详情。套件版本在点击时从仓库现取
> 最新版，不再依赖页面预加载是否已经完成。套件筛选和参考面板使用同一套来源/类型字段与匹配语义，
> 视频、文档、音频只在不适用的套件里显示为禁用。
>
> 网页收藏现在可以升级为画布舞台内的浏览器浮层：可输入公开 URL、拖动、缩放、重置、关闭，并把当前
> 地址的图片收藏到账号级网页收藏。Agent 调研保持“搜索候选 → 用户选择或后续明确加入 → 参考分析”的
> 边界，不会把搜索结果自动塞进生成。免费来源实接 Openverse 开放授权图片与 Wikipedia 内容；Lovart
> 实测流程还包含技能加载、分角度搜索、候选图片、参考分析、思考完成和生成，每轮搜索通常不超过两批。

> **2026-11-10 网页收藏、浏览器扩展配对与轻画浏览器首版**：“轻画插件”页签现在可输入公开网页地址，
> 采集页面图片到账号级网页收藏，并可逐张加入项目参考、Agent 对话或当前画布。桌面端同时提供本机接收端和
> 配对信息；用户可在 Chrome / Edge 开发者模式加载随仓库提供的 MV3 扩展，把当前网页 URL 与标题一键发送
> 到轻画。扩展只访问 `127.0.0.1`，不读取 Cookie。抽屉内可以预览可嵌入网页，拒绝被嵌入的站点可转到系统
> 浏览器；画布舞台内自由浮层仍属于后续交付。扩展必须由用户主动安装，不能在应用内静默安装。

> **2026-11-10 参考会自动分析 What 与 HowToUse**：使用品牌、产品、角色、风格参考或套件做生成/改图前，
> Agent 会先分析本轮真实参考。每张参考会记录客观素材说明、本次任务应如何借鉴或避开，以及风格、构图、
> 身份锚点或文字规范等用途。分析失败时只影响对应参考，不伪造结果；再次打开参考详情可以看到最新说明。
> 搜索结果仍只是候选，只有用户加入或当前任务参考台账命中的内容才会进入本轮生成上下文。

> **2026-11-10 Agent 免费联网调研与多图套件参考**：Agent 在用户没有提供链接时，也能对“搜索/联网/
> 查一下/最新资料”这类请求执行真实公开来源调研。当前免费来源是 Openverse Images 与 Wikipedia，
> 结果先作为候选展示，不会自动进入项目参考。用户明确把参考、套件或图片加入对话后，它们才按项目参考
> 台账进入当前任务；一个套件可以携带多张真实图片，不再只传主预览。参考栏与套件子面板使用同一套筛选
> 规则，避免两处选项和状态漂移。

> 自定义协议不再提供手动创建入口；用户只在接口格式不同时下载模板、交给 AI 生成协议 JSON，
> 再导入并绑定渠道。旧的手动创建数据继续兼容，已有渠道不会被删除或改指。

> **2026-11-01 自定义协议窄屏与格式定位（对账 #843）**：自定义协议面板在窄窗口也必须完整落在
> 编辑区的可见滚动范围内；“手动创建 / 导入 AI 协议”两个页签等宽并居中。协议导入属于高级
> 能力，普通中转站仍优先选择“OpenAI 兼容”。Cherry Studio 的现行实现也采用固定端点类型 +
> 自定义 Base URL / Key / 模型目录，而不是运行任意协议脚本；轻画保留更通用的声明式导入，
> 但不把它包装成普通用户的首选配置方式。

> **2026-11-01 自定义协议模板与 AI 导入（对账 #842）**：自定义协议新增“导入 AI 协议”。
> 用户可下载纯文本模板，把模板和目标站点 API 文档一起交给 AI；AI 返回一个
> `qinghua.protocol/v1` JSON。用户可粘贴或选择 `.txt/.json`，软件先检查格式并显示名称、
> 能力和鉴权摘要，再保存并绑定当前渠道。该格式支持常见 HTTP 模型目录、非流式对话 / 工具调用、
> 同步或异步图片、视频、多参考图和 multipart；不支持任意脚本、OAuth、WebSocket、签名算法
> 或跨域请求。导入页不保存 API 地址或 Key，也不发起付费生成；地址、Key 和模型验证仍在渠道层。

> **2026-11-01 自定义协议只填必要信息（对账 #841）**：普通中转站直接选「OpenAI 兼容」，
> 在渠道里填写 API 地址与 Key，不需要创建自定义协议。只有站点使用不同接口版本或请求格式时，
> 才打开自定义协议：默认只填名称和对话 / 生图能力；内部标识、短标签自动生成，接口版本从地址
> 自动识别，版本和文档地址折叠在高级设置。自定义协议不再重复填写 API 地址，也没有无上下文的
> 试连接；创建后立即选中并绑定当前渠道。

> **2026-11-01 SoonStudio Gemini 生图错误与自动协议兜底（对账 #840）**：
> SoonStudio 的 `gemini-3-pro-image` 在部分账号分组会先接受异步图片任务，再在任务结果中
> 明确要求 Gemini 原生格式。现在遇到这类明确错误会自动补走一次
> `/v1beta/models/{id}:generateContent`，不需要用户手改渠道协议；不会重新提交图片生成任务。
> 如果是模型未在当前分组开通、额度或其他上游错误，界面直接显示服务端 code / message，
> 不再显示成“请求可能已被上游接收”。`nano-banana-pro` 等同款上游 ID 也使用相同参数能力。

> **2026-11-12 Agent 设计调研结果流（对账 #1025–#1029）**：找风格、海报、包装等视觉参考时，联网调研固定从 Pinterest、Behance、Dribbble、Are.na、The Dieline、Packaging of the World、World Brand Design Society、Pentawards、站酷、古田路9号、花瓣、小红书检索；Tavily 没有 Key 或这 12 个站点无结果时，不静默回退到无关开放来源。Agent 对话里的调研步骤不再直接铺三列缩略图，而是显示“网页来源”和“查看图片搜索结果”两个入口。网页来源打开右侧链接抽屉，点击条目交给系统浏览器；图片入口打开瀑布流，悬停图片可发送到对话，右上角加入参考要二次确认，双击图片打开大图，下载入口在悬停动作和大图中都可达。桌面 1024×700 与 1440×900 均不得出现整页或对话流横向滚动。

> **2026-11-14 RunningHub 工作流与「来源」口径（对账 #1104–#1107，仅调研、未实施）**：生成节点的接入来源定为三档 —— **API 渠道**（现有 HTTP 渠道，行为不变）、**RunningHub**（AI 应用 / 自建工作流）、**本机 CLI**（Codex / 即梦 / Gemini / rh）；不新建节点类型，来源是生成节点上的一行选择。RunningHub 侧三条接口路线分清：标准模型走金额、AI 应用走 RH 币、自建工作流（`workflowId`）走金额。参数「暴露 / 隐藏」分两层：**AI 应用的开放字段由作者在 RunningHub 网页端决定**（接口只回这些）；**自建工作流没有暴露机制**，由轻画拉全量参数后默认全部隐藏、再由用户在后台勾选暴露。节点上只呈现已暴露的字段，隐藏字段不下发。详见 `轻画-RunningHub工作流与三来源渠道调研.md`。

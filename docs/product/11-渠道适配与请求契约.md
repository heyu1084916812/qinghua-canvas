## 11. 渠道适配与请求契约

### 11.1 适配器接口

每个渠道协议实现统一接口：

```ts
interface ChannelAdapter {
  verify(config: SafeChannelConfig, signal: AbortSignal): Promise<VerifyResult>
  listModels(config: SafeChannelConfig, signal: AbortSignal): Promise<ModelCapability[]>
  generateImage(request: ImageRunRequest, signal: AbortSignal): Promise<GeneratedAsset[]>
  generateVideo(request: VideoRunRequest, signal: AbortSignal): Promise<GeneratedAsset[]>
  completeText(request: TextRunRequest, signal: AbortSignal): Promise<TextResult>
}
```

- UI 只传渠道 ID 与结构化请求给平台层，不直接拼 URL，不读取明文 API Key
- OpenAI 兼容生图默认端点为 `/v1/images/generations`；协议适配器可按渠道覆盖，并在设置页显示最终端点
- **M6-12 起按输入分叉**：请求**带图像输入**（上游图 / 角色参考图）时改走 `/v1/images/edits`（multipart 上传，一次最多 4 张、按内容去重）；**不带**图像输入时仍走 `/v1/images/generations`。图像素材**读不到**（尚未落库 / 已清理）时退回 `/v1/images/generations`；端点不支持 `edits` 则**如实报错**，不静默降级为忽略参考图
- 默认首选生图模型为 `gpt-image-2`：仅当拉取的模型列表包含该 ID 时自动预选，不存在时保持未选择并提示用户
- 返回可接受 Base64、远程 URL 或二进制；远程 URL 下载后转存本地素材，画布不长期依赖临时 URL

**OpenAI 兼容协议的请求组装（生图）**

| 我方参数 | 送达字段 | 规则 |
| --- | --- | --- |
| 比例 `ratio` | `size` | 映射为**像素**而非比例字面量；**由比例 + 画质档位共同决定**：按档位定总像素预算（1K = 1024²、2K = 2048²、4K = 4096²；4K 的 1:1 特批 `2880x2880`），再按比例解出两边并**吸附到 16 的倍数**。约束：最大边 ≤ 3840、长短边比 ≤ 3:1、总像素 ∈ [655360, 8294400]，超界按规则钳制。比例字面量超 3:1（如 22:7）**不发 `size`**（文档明确拒绝），比例解析失败也**不发**（不猜） |
| 质量 `quality` | `quality` | 仅 `auto` / `low` / `medium` / `high` 透传；其余档位**不发**（发了就是 400） |
| 画质 `resolution`（1K / 2K / 4K） | —— | **刻意不发**：OpenAI 图像协议没有档位参数，像素尺寸由模型与 `size` 共同决定。把一个 2K 档猜成 `2048x2048`，在多数中转上直接 400，比「档位不生效」更糟 |
| 数量 `count` | `n` | 直接透传 |
| 上游图像 | 端点分叉 | 有图像输入 → `/v1/images/edits`（multipart）；无 → `/v1/images/generations` |

- **Base URL 归一**：地址结尾的版本段与斜杠会被剥掉（`https://x/v1` → `https://x`），再由适配器补一次 `/v1`。这是为了让「文档写 `https://api.openai.com`」与「后台直接给 `https://xxx/v1`」两种常见写法**都成立**——原实现无条件拼 `/v1`，地址已含 `/v1` 时就成了 `/v1/v1/models`，一律 404，而报错只会说「端点不存在」，用户根本猜不到是自己多贴了一段。
- **产物宽高**取自请求的 `size`（如 `1024x1536`）；`size` 不可知时不写宽高，**不用 512 这类常量编造**。
- **产物 id（hash）取产物字节的内容指纹**，不取请求维度（理由与规则见 §8「产物的 id 一律是内容哈希」）。`b64_json` 与远程 URL 两条解码路径**都必须**走同一口径。

**OpenAI 兼容协议的请求组装（对话 / 文本）**

| 能力 | 端点 | 规则 |
| --- | --- | --- |
| 验证 / 模型列表 | `GET /v1/models` | 与生图协议同源（共用超时、鉴权、错误分类与模型表识别） |
| 文本 | `POST /v1/chat/completions` | `messages` = system（按动作取：优化 / 翻译 / 反推）+ user |
| 图像输入 | `content` 消息数组 | 无图时 `content` 是**字符串**；有图时是数组：`{type:'text'}` + 每张图一个 `{type:'image_url', image_url:{ url: 'data:<mime>;base64,…' }}`。素材读不到的项**跳过**（不因一张图缺失让整单失败） |
| 生图 / 生视频 | —— | 显式抛「不支持」，不静默返回空结果 |

- **响应取 `choices[0].message.content`**：缺失或非 2xx 都按渠道错误抛出，带可读原因；不让空字符串冒充「模型回了空答案」。
- 图像上限 4 张、按 `assetHash` 去重（同一张图被两条线引来只发一次）。

### 11.2 请求验证

| 项 | 规则 |
| --- | --- |
| URL | 生产默认仅允许 HTTPS；地址规范化（含**结尾版本段归一**，见 §11.1）但不猜测路径 |
| 超时 | 验证 10s、模型列表 20s、图片 180s、视频 20min；均可取消 |
| 重试 | 仅网络中断、408、429、5xx 可重试；401 / 403 / 404 与参数错误直接失败 |
| 退避 | 1s、2s，叠加 0–250ms 抖动；响应带 `Retry-After` 时以其为准 |
| 响应限制 | JSON 20MB、单图片 50MB、单视频 500MB；超限中止并说明限制 |
| 重定向 | 最多 3 次；跨域重定向不转发 Authorization，除非目标与已保存渠道同源 |
| 日志 | 记录请求 ID、状态、耗时、模型和脱敏错误；密钥、完整图片 Base64 与完整提示词不落入日志 |

### 11.3 能力驱动参数

- 模型能力由 `ModelCapability` 描述：输入类型、输出类型、比例、分辨率、质量、数量、时长、参考图上限
- 参数面板只显示模型明确支持的字段；能力未知时使用最小参数集
- 切换模型后，不兼容参数保留在节点历史中但不发送；UI 显示「2 个参数不适用于当前模型」并允许查看

### 11.4 浏览器网络边界与代理

浏览器直连中转站受同源策略约束，因此请求路径按环境区分：

| 环境 | 路径 | 说明 |
| --- | --- | --- |
| 开发态（`npm run dev`） | 浏览器 → Vite dev proxy → 中转站 | proxy 目标由 `.env.local` 的 `VITE_PROXY_TARGET` 指定，不进版本库 |
| 生产静态部署 | 浏览器 → 中转站 | 需要中转站开放 CORS；未开放时设置页「验证地址」给出明确分类提示 |

- 请求默认只接受 `https://` 地址；本机回环地址用于本地代理调试时例外放行
- 跨域重定向不转发 `Authorization`，除非目标与已保存渠道同源
- 「验证地址」能区分 CORS、DNS、TLS、超时与 HTTP 状态错误，并在提示中说明当前环境该走哪条路径
- **协议是被验证的一部分**：验证 / 拉取 / 探测前先把表单配置落库，状态行标注本次使用的协议名（见 §7.3）。若协议仍是 mock，则无论地址填什么都会「通过」——这一情况必须在提示里显式说明，不能让它伪装成一次成功的联调
- **「自动选中协议」必须建立在真信号上**：候选协议表剔除恒成功的离线协议；地址为空不发请求（空串会退化成相对当前页的路径，被 SPA 的 200 兜底页判成「通了」）；200 响应还要求体内真有一份模型列表才认成功。三处任一处放松，探测都会变成「任何地址都命中」的假动作
- 凭据由 WebCrypto `AES-GCM` 加密后存于本机 shared-store，密钥由本机随机盐派生，只在本机可解
- 后续接入桌面壳后，请求改由原生网络层发出，本节规则其余部分保持不变

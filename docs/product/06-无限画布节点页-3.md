### 6.12 批量节点 · ✅ 已实现

批量节点是一个可迭代的素材集合：把多个同类素材收进去，逐个处理，为每个素材生成一份结果内容。

| 规则 | 说明 |
| --- | --- |
| 可收纳 | 图片 / 视频素材，或提示词素材 |
| 二选一 | 两种类型互斥，已放入一种类型时另一种类型拖入被拒绝并给出弱提示 |
| 拖出 | 内部节点拖出后不再作为创作面板的缩略图 |
| 自动排列 | 拖入 / 拖出后按 3 × 3 行优先网格自动排列，保留 16px 间距，不重叠 |
| 内部拖动 | 直接拖动内部节点改变顺序，位置由排序吸附决定；缩略图排序与节点顺序双向同步 |
| 尺寸 | **贴住内容**（2026-10-06 第 13 批第 7 条）：尺寸 = 内容包围盒 + **四边等距 20px**（空容器 `240 × 192`），不再归一 5:4；子节点增删时容器跟着收放，「装得下就不动」——手工拖大的框与打组的包装框都留住。向内拖缩放手柄时停在"内容 + 四边留白"上 ⇒ **不会遮住子节点** |

固定比例容器布局规则与分组节点一致（§6.11）。

**创作参数面板**：与生成节点结构一致，第一部分显示内部素材缩略图（带编号 + 隐性小眼睛，拖出才移除）。面板内拖动缩略图排序时，批量节点内部对应素材的实际排列顺序同步改变。

**第二部分的两种用法**

| 收纳内容 | 提示词框的作用 |
| --- | --- |
| 图片 / 视频素材 | 填写本次生成的提示词，作用于内部每一个素材 |
| 提示词素材 | 留空 → 直接用内部提示词批量文生图；填写处理指令（如「优化这段提示词」）→ 先用 LLM 处理，结果写回内部每个提示词素材的文本，本次不出图 |

**作为上游：集合卡**

批量节点作为上游连到生成节点时，在下游面板第一部分不展开，而是显示一张集合卡，标注内含素材数量（隐藏的素材不计入）。下游生成时遍历集合内的每个素材，各生成一次。集合卡可与其他缩略图拖动排序。

> **集合成员 = 内部素材 + 外部连线的素材（2026-09-17）**
>
> 此前只有「放进批量节点内部」的素材算集合成员，从外面连进来的被当成
> 「每次迭代都附带的共同输入」——于是「批量节点是空的、两张素材从外面连进来」时
> 会退化成**一次调用、两张图一起丢给模型**（出一张「两个人一起吃饭」）。
> 批量的定义是「素材集合，逐个处理」，那么**素材从哪儿进来不该改变这件事**。
> 外部连线的**提示词**仍是共同输入（它不是素材，不该被拆开迭代）。
> 面板集合卡上显示的数量也随之把外部素材算进去——卡上写 0 而实际跑 2 次，
> 比没有卡片更误导。

**提示词拼接顺序（2026-09-17）**

`素材自带的描述` + `外部共同提示词` + `批量节点自己的提示词`

批量节点面板写的那句是对这批素材**统一生效**的指令，故放在**尾部**；
放最前会被素材描述冲淡。「素材自带」只取**本次这一项**的描述——
把所有素材的描述全拼上会让第 1 次调用也带上第 2 张素材的描述，两张图互相污染，批量就退化成分组了。

**参数合并规则（2026-10-16）**

一次调用真正发出去的参数 = **批量节点面板设过的** 覆盖 **素材那一项自己的**。与提示词同源：
批量面板上写的 / 选的是「对这批统一生效」的东西。

| 批量面板上 | 结果 |
| --- | --- |
| 留空（不指定） | 每一项按**自己那份**走 —— 素材节点上选过 9:16，这一项就出 9:16（「内部有素材就跟随素材」走的就是这条路） |
| 选了某一档 | **盖掉**里面各不相同的值 ⇒ 整批统一。想把里面那些图**都改成同一个尺寸**，在批量面板选一次比例即可 |

两条边界：**张数**在图片档永远由批量面板决定（那是"每项出几张"的旋钮，跟着素材自己的历史张数走会让结果数翻倍）；素材项**读不到**（已删 / 不认识的类型）时退回批量自己那份，不让整批失败。

**四种典型场景**

| # | 输入 | 操作 | 结果 |
| --- | --- | --- | --- |
| 1 | 批量节点内 2 张图 | 在批量节点面板填提示词 + 参数，点生成 | 右侧出 2 个结果 |
| 2 | 批量节点内 2 张图（猫、狗）+ 外部 1 张衣服图，共同作为上游 | 生成节点面板写「图一穿上图二的衣服」，点生成 | 生成节点右侧出 2 个结果 |
| 3 | 批量节点内 3 条提示词 | 在批量节点面板或右键点生成 | 批量节点右侧出 3 张图 |
| 4 | 批量节点内 3 条提示词 + 外部 1 张图，共同作为上游 | 生成节点面板或右键点生成 | 右侧出 3 个结果 |

**生成入口**：创作参数面板的「生成」按钮；右键批量节点 → 生成。

**生成入口去哪（分发器语义，2026-09-24）**

批量节点与循环节点同属**分发器**：自己不产图，把集合交给下游。
因此「生成」按钮的去处**按下游是否存在**二选一，按钮文案同步说明：

| 情形 | 按钮文案 | 点下去做什么 |
| --- | --- | --- |
| 下游**没有**配好的生成节点 | 「生成当前节点」 | 批量自己按集合展开出 N 份（就是上表场景 1 / 3） |
| 下游**有**配好的生成节点 | 「生成下游节点」 | 驱动那个下游生成节点跑一趟，**用它自己的提示词与参数** |

第二条正是用户 2026-09-24 的口径：「批量节点的下游需要链接生图节点，
所用的参数就是生图节点的参数，点击一键生成的时候参考普通节点生成的逻辑」。
产物铺在**下游生成节点**右侧（不是批量节点右侧），连线也从下游生成节点画出 ——
这次生成属于它，参数也是它控制的。

> ⚠️ **实现坑（改这块前必读）**：批量自跑一次后会产出载体节点，
> 它们带着渠道 / 模型、又和批量连着一条线。若下游判据不排除它们，
> 「生成」按钮会被劫持到那个**空提示词**的载体节点上，点下去毫无反应。
> 排除依据是落位时打的 `__carrierOf` 标记（父节点关系与连线关系都不可靠，见对账清单）。

### 6.14 连线规范 · ✅ 已实现

| 项 | 规则 |
| --- | --- |
| 端点位置 | 每个节点左右中间位置各一个：左 = 输入，右 = 输出。**视觉直径固定 42px**；高倍率下命中区为 91px，低于 35% 时透明命中收回到圆点附近，避免盖住缩略节点。数字浮层打开时端点命中暂停，避免盖住浮层按钮 |
| 端点颜色 | **按主题取反色**：统一使用 `--accent` / `--accent-text`，始终与画布背景形成强对比；不要改回会随表面融掉的 `--bg-surface` |
| 端点浮现 | **鼠标进入端点附近的感应圈**时淡入并**吸附到指针**（跟随指针移动）；指针离开感应圈后**弹回原位并淡出**。节点被选中时端点常显，不参与吸附回落 |
| 感应与磁吸 | 以**屏幕像素**判断：距节点边缘 50px 内完全展开，50–70px 线性收回；指针到端点圆心的磁吸半径同为 50px。判定用指针几何，不是 DOM `:hover`，避免「看不见却已生效」 |
| 建立连接 | 从输出端点拖出平滑贝塞尔曲线；松手在目标端点上或落在下游节点范围内均完成连接；也可从输入端点向外拖出，在空白处选择上游节点或直接落到上游节点完成连接 |
| 空白松手菜单 | 在画布空白处松手时，于指针右侧 12px 打开菜单，受可视区边界约束。菜单只包含「新建并连接」。输出端拖线只列合法下游，输入端反向拖线只列合法上游；新建节点后按当前方向自动建立连接。连接已有节点仍通过直接拖到目标节点完成 |
| 菜单项图标 | 与新建节点菜单**同一套线性图标**（用户 2026-09-19）：「新建并连接」按**要建的节点类型**取图标，与工具栏面板逐字同形 |
| 菜单项合法性 | 两个分区都只列**真的连得上**的项：类型能否作对端一律走 `canConnect` 判定（对比这类连不上的类型不出现），不存在「建好了却连不上」的死项。「新建并连接」的建点与连线合成**一步撤销** |
| 菜单关闭 | 指针离开菜单范围后立即关闭，菜单关闭不改变已有节点和连线；菜单打开期间画布指针事件不触发平移、框选或节点选择 |
| 拖线状态 | 从按下端点到连接完成、取消或菜单关闭期间，当前节点下方的创作面板保持隐藏 |
| 连接反馈 | 可连接时下游节点呈现选中状态，连接成功后取消选中 |
| 约束 | 输出端点连输入端点；输出↔输出、输入↔输入拒绝（拖拽中连线变 `--danger`） |
| 单击连线 | 线条变为区别于其他连线的颜色，进入可删除状态 |
| 节点选中时 | 该节点的上下游连线同时变色，每条相关连线上出现一个删除按钮 |
| 双击连线 | 直接删除 |
| 常态 / 高亮 | `#C9C9D1` 1.5px / 高亮色 2px |

### 6.15 选中与框选 · ✅ 已实现

| 操作 | 结果 |
| --- | --- |
| 单击节点 | 选中，适用节点同时出现创作参数面板 |
| 单击画布空白 | 取消选中，收起面板 |
| `Ctrl/Cmd` + 空白拖拽 | 自由框选，拖拽结束命中节点矩形框的纳入多选 |
| `Alt` + 拖动节点 | 复制出新节点，保留上下游连线 |
| `Shift` + 单击 | 增减选中（在提示词节点 textarea 内部同样生效） |
| 多选状态 | 隐藏创作参数面板 |

拖动期间：节点从按下进入拖动判定后，当前节点与其他选中节点的创作参数面板立即隐藏；发生过**位移**的拖动，松手后面板保持隐藏，直到下一次显式选中节点（重新单击即可恢复）；原地点击（未移动）不算拖动，面板照常出现。

#### 6.15.1 多选浮层（虚线框 + 功能栏 + 左右共有端点） · ✅ 已实现（2026-10-05）

选中 **≥ 2 个**节点时，除了「隐藏创作面板」，选区外面还多三层东西：

| 层 | 内容 | 行为 |
| --- | --- | --- |
| 虚线框 | 圈住**整个选区**（不是单个节点） | 纯指示，不吃任何指针事件——框内照样能继续框选、点节点 |
| 功能栏 | 排列与整理 / 保存到资产 / 创建副本 / 打组 / **批量** / 下载 / 添加到 agent | 挂在选区上沿之上，图标 + 常驻中文（与单选跟随栏同一套视觉与锚点口径）。**批量**（用户 2026-10-06 第 13 批第 5 条：「需要加一个批量的功能」）把选中的收进一个**批量节点**，与打组共用一份实现；提示词与素材**混装时整批拒绝**并说明原因（与 `canAcceptIntoBatch` 同一条口径） |
| 共有端点 | 左（连上游）、右（连下游）两只 | 拖出**一条**草稿线，落在一个节点上 = **每个**选中节点各连一条 |

> **外扩量（用户 2026-10-05 第 6 条：「虚线框要大一点，不要遮住节点的名称还有左右的端点」）**：
> 框相对选区外扩 **上 30 / 左右下 22**（上边多出来的 24px 是节点标题带，见
> `followBarAnchor.NODE_TITLE_BAND`）；端点居中到框沿、并补掉上下不对称带来的中点差；
> 功能栏挂在**框的上沿之上 6px**。这三个数**共用一份常量** `MULTI_BOX_INSET`
> （写两处一定会出现「框放大了、端点还在原地」）。
> 同一条反馈里还有「节点的跟随栏也遮住了节点名」—— 跟随栏与节点的间距由 10 提到 **30**
> （= 标题带 24 + 6），并由单测钉住「栏底必须落在标题带之上」。

几个边界写死在这里，别在别处再实现一遍：

- **互斥**：多选浮层与单选跟随栏不同时出现（跟随栏只在 `selection.length === 1` 时渲染）。
- **复用既有命令**：排列整理 = 底部工具栏那份 `useArrangeTools`（一次排列 = 一个撤销单元）；保存到资产 = `saveAssetToLibrary`；创建副本 = `node.duplicate`；打组 = `groupNodes`、批量 = `batchNodes`（两者共用 `wrapSelection`；打组也就是 `Ctrl/Cmd + G` 那个函数）；下载 = 现有 `downloadAsset`。
- **添加到 agent** = 把选中的节点交给对话窗做素材：对话窗自己打开，ids 落成**正文里的引用 chip**（与「取选中当素材」同一条口径，不另起一行标签）。
- **端点逐个独立判定**：多选里某个节点已经连过同一个目标时，只跳过它，**不是整次拖拽作废**——否则用户会看到「草稿画了、松手什么都没多」。
- **拖线时每个源各画一条草稿**（用户 2026-10-05 第 3 批：「框选多个节点的时候进行连线的时候里面的节点不是全都有拉出线条」）：落地本来就对（每个选中节点各一条边），但过程里只画一条草稿 ⇒ 读起来像「只连了一个」。`LinkDraft.alsoFrom` 记下其它源的固定端，`FlowDraftLayer` 为每个起点各画一条（终点共用指针位置）。
- **空白松手菜单也要连上整个选区**（用户 2026-10-05 第 4 批：「框选多个节点新建节点然后连接，新建的节点只连接了一个上游」）：拖到**已有节点**上由 `useEdgeDrag` 直接连；**空白松手**会把这次拖拽交给 `LinkMenu`（另一个组件里建边）—— 所以 `also` 必须一路带进菜单状态，三条路（拖到节点 / 菜单选目标 / 菜单新建）**共用同一个 `wireAll`**。各写一份的结果就是「这条能连全、那条只连一个」。
- **创建副本要让开**（同批：「创建副本……不要遮住画布上的节点」）：`node.duplicate` 只吃 `dx/dy`，位移由 `features/canvas/duplicatePlacement.ts` 给 —— 先放选区右侧一格（间隔 40），撞上别人就按「右 → 下 → 右下」继续找。原先三处入口都写死 `+24/+24`，240×240 的节点会重叠 216×216 = **46656 px²**。

### 6.16 尺寸与缩放 · ✅ 已实现

| 对象 | 规则 |
| --- | --- |
| 画布 | 10% – 500%，滚轮以鼠标为锚点 |
| 创作参数面板 | 桌面端约 840px 宽、高度自适应，不随画布与节点缩放变化 |
| 节点通用 | 无需选中即可缩放，鼠标移到节点右下角直接拖动 |
| 提示词节点 | 自由缩放，最小 `240 × 160` |
| 图片 / 视频节点 | 空态自由缩放，默认与最小 `240 × 192`；有内容按原始比例锁定，容器与内容同步 |
| 同上 · 素材变化时 | 上传 / 生成写回 / 从容器拖出或复制出，都按产物真实像素（`naturalSize`）重算尺寸 |
| 对比节点 | 按内容比例锁定，默认与最小 `240 × 192` |
| 分组节点 | **贴住内容**：尺寸 = 内容 + 四边等距 `20px`（空容器最小 `240 × 192`）；内部单元固定 `200 × 160`（2026-10-06 起不再锁 5:4） |
| 批量节点 | 同分组节点 |
| 融合节点 | 自由缩放，最小 `280 × 260`。**内容跟节点**：预览区吃掉剩余高度，两块预览填满各自格子（不写回尺寸） |
| 循环节点 | **只跟横向位移**缩放（纵向位移整份丢掉）；高度**由内容决定**，视图每帧按内容写回（面板开合 → 378 ↔ 125） |

> **锁比的代码化（M6-28）**：缩放锁由 `resizeLockOf` 按上表解析——生成节点有产物取 `naturalSize` 真实比例，缺像素信息退回**按下时**的容器比例（不猜）；分组 / 批量**自由缩放**（容器贴住内容，尺寸边界交给"内容 + 四边等距 20px"的动态最小尺寸；2026-10-06 第 13 批第 7 条之前是 5:4 锁比）；对比节点锁按下时比例；提示词自由。拖动全程保持锁定比例（主导轴定尺寸、另一轴跟随），松手提交最后一帧矩形——一次撤销回滚整段缩放。

> **高度归内容的节点（`heightFromContentOf`，2026-09-30）**：循环节点是**参数卡**，高度跟着内容走，所以缩放**不夹它的最小高度**、也不吃纵向位移 —— `NODE_MINIMUMS.loop.h = 380` 是**开箱默认尺寸**而非缩放下限，若在缩放里夹它，用户一碰右下角就会看到节点「跳」到 380（内容自适应已经把节点收到 320）。缩放交互里唯一的不变式是**松手之后尺寸不再变化**：自由跟指针、锁比等比、高度归内容只跟横向，三类都必须满足。

### 6.19 执行引擎 · 🧩 部分实现

「生成」是节点类型的内置动作，**不同节点类型的「生成」含义不同**——它由 `NodeDefinition.generate` 定义，不在执行引擎里硬编码。执行引擎负责调度、失败重试与进度反馈，并暴露两种执行模式供用户在不同诉求下选择。

#### 6.19.1 单点执行模式（2026-09-30 收敛）

画板节点下线后，画布只保留单点生成；`Alt+R` 不是第二种模式，而是单点生成的修饰键。

| 模式 | 入口 | 范围 | 适用场景 |
|---|---|---|---|
| 单点生成 | 右键 / 创作面板 / `R` / `Alt+R` | 触发节点本身 | 单次实验、参数调优；想停下来看效果 |

**单点生成**：只跑触发节点本身，下游完全不动。结果按 §6.19.3 空槽位规则落位——**落在空槽上**；没有空槽就新建（命名 `原节点名的输出1`）。触发节点自己是空槽时落在自己身上；它已有内容时（图生图等）不再被当作槽位，改为复用下游空槽或新建承载节点。`N ≥ 2` 时并列备齐 N 个空槽，N 张图各落一个。按住 `Alt` 时的行为与普通单点生成一致（都是新建承载节点）。

**容器运行已随画板节点下线**：分组 / 批量仍可作为生成主体执行，但不再有“跑一整个画板子图”的独立入口。

**`Alt` 是修饰键不是模式**：按住 `Alt` 触发的单点生成，行为是「保留旧内容、在拓扑方向铺新下游节点承载新结果」，其余与单点生成一致。架构侧不把它列为第三种模式，而是在构建执行计划时解析成一个布尔开关（架构文档 §5.5 `RunPlan.newDownstream`）。

> ## 已下线：三种覆盖式重跑 + 陈旧标记（2026-09-17 用户拍板）
>
> **下线的**：右键「整条流程重新运行」(`P`)、右键「仅刷新陈旧节点」(`Shift+R`)、
> ~~顶栏「仅刷新陈旧」、顶栏「全图重跑」(`Ctrl+Enter`)~~、右键「清除陈旧标记」，
> 以及驱动它们的**橘色陈旧标记**本身。
>
> **为什么**：三者都是**覆盖式**重跑——产物写回原节点，旧结果被冲掉。
> 而落位改成「每次生成新建一个右侧节点」（§6.19.3）之后，用户要的是
> 「出一份新的、旧的留着对比」，覆盖式重跑正好与之相反。留着只会让人误点丢结果。
> 全图重跑更是会把整张画布的历史结果一次冲掉，即便有二次确认也不该留。
>
> **橘点为什么也删**：它的判定是「当前指纹 ≠ 上次成功生成的指纹」。但在新落位
> 模型下——新节点本就没有基线、旧节点指纹也不曾变过——**它既不会出现在新节点
> 上，也不会出现在旧节点上**，已经没有触发场景。留着一个永不亮起的信号，
> 比删掉更容易误导后续维护者。
>
> **替代做法**：要保住旧结果又想重出一版时，**复制节点链**即可
> （§4.2 复制保留连线，再清掉副本上的素材重跑）。这比覆盖式重跑更可控，
> 且天然保留了可对比的旧版本。

#### 6.19.2 节点生成语义

每类节点的「点生成」行为：

| 节点类型 | 怎么跑 | 下游槽数公式 | 结果落点 |
| --- | --- | --- | --- |
| 提示词节点 | LLM 改写文本（1 次调用） | — | 自己的文本框（覆盖） |
| 图片生成节点 | 调生图 API × count | count | count 个空槽位 |
| 视频生成节点 | 调视频 API × count（异步轮询） | count | count 个空槽位，异步逐个落 |
| 批量节点 | **遍历内部素材** × count（每素材一次 API） | **count × 内部素材数** | 空槽位 |
| 分组节点 | **1 次 API 调用**（所有素材一起进） | **创作面板的「生成数量」参数** | 空槽位 |
| 对比节点 | 不可生成 | — | — |

**批量 vs 分组的精确差异**：

- 批量节点：内部素材 × count = N 个独立 API 调用，每次传 1 个素材；产出 N 张独立图
- 分组节点：1 个 API 调用，所有素材一起进，请求由 API 内部聚合；产出张数由创作面板的「生成数量」参数决定

#### 6.19.3 空槽位规则（仅单点生成生效）

> **本节于 2026-09-16 按用户口径重写。核心是一条：产出永远落在「空槽」上；没有空槽就新建空槽。**
> 旧口径里「触发节点自己有内容时跳过它、往下游找空槽」只对了一半——漏掉了「源节点的图被当作**输入**」那种情形（见下 B）。

**「空槽」的定义**：一个**还没有产物**（`assetHash` 为空）的图片 / 视频生成节点。它可以是触发节点自己，也可以是下游节点。

**A. 触发节点自己是空槽 → 落在自己身上**

最常见的首次生成：画布上只有一个生成节点，创作面板里写了提示词、选好参数，点生成 →
结果**落在这个节点自己身上**（节点从占位框变成那张图）。

**B. 触发节点自己有内容 → 它不再是槽位，另起承载节点**

源节点一旦已有素材，它的本体就是**输入 / 参考**，不再是「等着接结果的空槽」。
两种走法，取决于下游有没有现成的空槽：

| 情形 | 结果落位 |
| --- | --- |
| 源节点有图，且**下游没有空槽** | **新建一个承载节点**（命名「原节点名的输出N」），product 落它身上；源节点与旧产物都不动（方案 1：并列铺开，不挪动已有节点） |
| 源节点有图，且**下游已有空生成节点**（方式二） | **复用那个空槽**，结果落它身上 |

**方式一 / 方式二**（用户原话，两条并列的常见动线）：

- **方式一**：还在原来那个生成节点的创作面板里写提示词。此时上游素材 = **该节点自己的图** + 提示词内容。点生成 → 源节点已有内容、又没有下游空槽 → **新建节点**承载结果（新节点处于生成中状态）。
- **方式二**：把「已有图的生成节点」连到一个**空的生成节点**上；提示词可以来自单独的提示词节点，也可以直接在空槽的创作面板里写。点这个空槽生成 → 它自己是空槽 → **结果落在它自己身上**。

**C. count 与空槽数量的对应**

| 生成数量 | 结果落位 |
| --- | --- |
| `N = 1` | 落在**一个**空槽上（复用已有空槽，或新建一个） |
| `N ≥ 2` | 需要**N 个空槽**：先按 BFS 找现成的空槽，不够就**并列新建**补足到 N 个（首尾不相接，都挂在源节点下游），产出的 N 张图各落一个槽 |

**承载节点的尺寸与排布（2026-09-17 定稿）**

| 项 | 规则 |
| --- | --- |
| 尺寸 | 新建承载节点按**请求的比例与像素档位**预估尺寸（如 16:9 → 341×192）；产物返回后以**产物真实像素**重算（§6.16），节点框 = 产物框，`object-fit: contain` 不再露出白边，灯箱与节点所见一致 |
| 排布 | 多个承载节点**复用 §6.9 的格位规则**（N=2/3 单行、N=4 为 2×2、5–8 每排最多 4 个，间距 16 / 内边距 16，整体在源节点右侧）；且步长按**节点实际边界**计算——格位若小于节点实际高，相邻行必须按 `实际高 + 16` 错开，否则会出现「轻微重叠」 |

**触发节点本身是否参与 BFS**：参与——但它**只有在自身为空时**才是候选槽位；
它一旦有内容，就从候选里排除（这正是 B 的判据）。

**撤销事务（§9.4 补充，2026-09-17）**：一次生成产生的命令分两类落账——

| 类别 | 命令 | 事务 |
| --- | --- | --- |
| 结构变更 | 新建承载节点、连线、runPlan.execute | **生成事务**（multi-step），Ctrl+Z 整体撤销 |
| 产物写回 | `asset.put`、`node.updateData`（patch 带 `assetHash`） | **独立事务**（standalone「生成结果」），**不随生成撤销回滚** |

> 理由：智能节点模型里**产物就是节点的一部分**。产物写回若混进生成事务，用户按 Ctrl+Z 会把已生成的图从节点上抹掉（表现为「图变没了」）——这不是用户期望的界面级撤销。素材本体本就常驻 `assets` 表；此处进一步保证**节点上的显示结果不被撤销抹除**。

#### 6.19.4 边界条件

| 情况 | 行为 |
| --- | --- |
| 触发节点空 + 下游空 | 触发节点优先被填（它是 BFS 第一个候选槽位） |
| 触发节点有内容 + 下游第一个空 | 跳过触发节点，落在那个下游空槽（方式二） |
| 触发节点有内容 + 下游全满 | **新建承载节点**（命名「原节点名的输出N」），与旧节点并列、不覆盖也不挪动旧的 |
| `N ≥ 2` | 并列备齐 N 个空槽（先找现成的、不够再新建），N 张图各落一个 |
| 按住 `Alt` 点生成 | 与普通单点生成一致（都新建承载节点，旧节点不动） |
| 容器运行执行期间 | 不弹菜单、不响应 `Alt`、不响应 `R`/`Alt+R` |
| 容器运行执行期间节点参数被改 | 当前节点继续按冻结快照跑，新参数在下次执行生效；不影响当前任务 |
| 执行期间链路有环 | 启动前已检测阻止，触发时立刻报错；运行中环检测在调度入口一次性校验 |

#### 6.19.5 视觉标记

单点生成与容器运行各有自己的视觉标记体系，两类独立渲染，互不干扰。

| 状态 | 触发条件 | 视觉 |
| --- | --- | --- |
| 空闲 | 节点未被任何执行模式选中 | 无标记 |
| 选中 | 鼠标点击或键盘 Tab 选中 | 黑色边框（唯一长期静态标记） |
| 单点生成执行中 | `R` / `Alt+R` / 右键「生成」期间 | 淡绿描边（`--success`）+ 节点中心进度 |
| 失败 | 任一执行模式产生失败 | 红框（`--danger`）+ 错误图标（点击展开详情） |

> **标记按「本节点是否参与本次执行」判定，不按「画布是否有任务在跑」**：节点只在它是本次计划的一员时才进入排队 / 生成中（由执行宿主按 `nodeId` 反查任务态注入）。
> 未参与的节点**一律无标记**——「全局有任务在跑」这件事只体现在**生成按钮**上（§6.8：按钮变旋转 `LoaderCircle` 并禁用），不体现在节点本体。
> 早期实现把「全局运行中」也画成了节点本体的居中转圈，于是跑任意一个节点时全画布未参与的节点都跟着转圈，用户看到的是「我没让它生成，它却在生成」。

> **陈旧标记已下线**（2026-09-17，理由见 §6.19.1 末的说明框）。
> 指纹本身**保留**：它现在服务于「同一节点多次生成的输入是否相同」

#### 6.19.7 工具函数：`traverseDownstream`

`traverseDownstream` 是不暴露给用户右键 / 快捷键的内部工具函数，供批量节点 / 分组节点 / Agent 内部使用，遍历从某节点开始的所有下游。

```ts
// src/domain/canvas/graph/traverseDownstream.ts
export function traverseDownstream(
  startNodeId: NodeId,
  graph: GraphSnapshot,
  callback: (node: NodeSnapshot, depth: number) => boolean | void
): void
```

**约定**：

- 深度优先遍历，返回 `false` 终止遍历
- 仅供 `NodeDefinition.generate` 的内部实现与 Agent 工具调用层使用
- 不绑定 UI 入口，不绑定快捷键，不暴露给右键菜单
- 与 §6.19.3「空槽位规则」配合使用——批量节点展开 N 个素材后，每个素材各跑一次时，按此规则找下游空槽位

**典型用例**：批量节点「遍历内部素材 × count = N 次 API 调用」时，每次调用前用 `traverseDownstream` 找到当前可用的下游空槽位，避免 N 张图全部落到同一个下游。

### 6.21 画布版本历史 · ⏸ 已下线（2026-09-16 用户拍板）

**画布侧不再提供「节点版本历史」与「画布时间轴」两个功能入口**（右键「版本历史」、`Ctrl/Cmd + H`）。

**为什么下线**：画布的生成语义是**产出落在空槽上**（§6.19.3）——源节点已有内容时，
产物落到**新建的承载节点**上。于是「按节点攒版本、再回退」这条动线自相矛盾：

- 记录若挂在**源节点**：源节点攒的是它并不持有的图，而真正持有产物的新节点**一条记录都没有**；
- 记录若挂在**新节点**：新节点只跑过一次，永远只有 1 版，历史无从谈起。

两种挂法都讲不通，而「重新生成同一版」这个需求本身也已被「再生成就铺一个新节点」取代——
用户要对比两版时，**两张图就在画布上并列摆着**，比翻历史面板直观。

**保留：`runRecords` 表与写入照旧，只下线两个界面入口。**

> 这一点必须写清楚：**日志面板（§6.18）与陈旧标记都还依赖 `runRecords`**——
> 日志面板的数据源就是这张表（每条含状态 / 平台 / 模型 / 耗时 / 像素 / 提示词 / 缩略图），
> 陈旧标记的「成功基线」也取自它（§6.19.5）。因此**不能停写**，只是不再用「版本历史」这个产品概念呈现。

| 项 | 处置 |
| --- | --- |
| 右键「版本历史」入口 | 移除 |
| 画布时间轴（`Ctrl/Cmd + H`） | 移除 |
| `runRecords` 表 / 写入 | **保留**（日志面板 + 陈旧基线继续消费） |
| `VersionHistoryPanel` / `CanvasTimeline` 组件 | 移除（含版本预览、版本恢复） |
| 版本恢复（`node.runRecord.restore`） | 随入口一并移除 |

> **comic（分镜格）侧不受影响**：分镜格的产物**确实写回格内**（`panel.setAsset`），
> 「一格一图、可回溯到上一版」在那里语义自洽，故 `ComicPlacement.record` 与
> 格内 `runs` 版本回退（§6.21.1）**保持原样**。

**替代能力**：产物本身既是结果也是「上一版」——旧节点不会被覆盖或删除，
两张图并列在画布上，可直接对比、分别作为后续生成的输入。

#### 6.21.1 格版本历史（comic，M6-15）

分镜格与画布生成节点同属「生成类主体」，因此 **「从不删除」这条规则同样适用于它**。差别只在**住哪儿**与**粒度**：

| 规则 | 说明 |
| --- | --- |
| 留痕住在格内 | `ComicPanel.runs`，随项目文档一起读写（comic 是单聚合对象、单写通道，不为留痕另开表；画布因是「图 + 补丁流」双存储，才必须分表） |
| **版本号由历史自身推出** | 取该格已有最大版本 + 1，**不由调用方给**。留痕载荷类型刻意**不含 `version`**，从类型上堵死「两条 v3 / 跳号」这类**界面上看不出来**的错误（行数对得上，要等回退到 v3 却回到另一版才暴露） |
| **只增不减** | 任何操作都不删留痕。删一条 = 那一版产物变孤儿（字节还在 `assets` 表里，却再没有指针指向它） |
| **回退本身追加为新版本** | 回退把目标版本的输入与产物写回，**再追加一条新留痕**，而不是把指针拨回去。历史永远是一条只增的时间线，没有「重写历史」这种状态，也就不需要 undo 栈兜底（comic 目前无撤销栈） |
| 快照口径 | **只记影响画面的字段**：画面描述 / 景别 / 机位 / 出场角色 / 渠道 / 模型 / 参考图 / 指纹 / 产物。**不含对白贴纸**（不烘进图，回退画面不该动对白）与**转场**（「与上一格的叙事关系」不是画面输入，回退时保留面板当前的转场） |
| 失败也留痕，但不能回退 | 只有「成功且有产物」的版本可回退。失败 / 取消那次没有画面，把它写回等于「回退到一张不存在的图」；而「恢复配置 ≠ 恢复画面」又是另一种语义——混在一条路径里会让「回退」一次表示两件事。因此失败版本**如实留痕但界面灰掉**并写明原因 |
| 「当前」怎么算 | 版本号最大且**有产物**的那一条。注意它与 `assetHash` 的分工：`assetHash` 是**画面**的真相（渲染只看它），「当前」标记是**历史**的真相；二者正常一致，唯一分叉场景是「某次成功但渠道没回图」——画面为空而历史仍指向上一个真正出过图的版本 |
| 入口 | **格属性面板第 ⑥ 段「版本历史」**：倒序列表（缩略图 / `v号` / 状态徽标 / 时间 / 张数与参考图数）；当前版本用**黑描边 + 「当前」标记**（沿用选中态规范），它的回退按钮禁用（自己不需要回退）；点缩略图开**大图浮层**看清这一版（再点或 `Esc` 关闭） |
| 画布三条访问方式的覆盖情况 | comic 只做第 1 条（格内列表）；**时间轴 `⌘H` 与日志面板不适用于 comic**（comic 没有画布时间轴与日志面板这些形态） |

### 6.22 循环节点 · 🚧 本轮落地（2026-09-22）

**一句话**：循环节点自己不产出任何东西。它把上游的一批素材按轮次**分发**给下游，让同一段下游链路跑 N 次；下游节点完全不知道自己在循环里。

> 需求来源：用户 2026-09-22 参照「大雄无限画布」的 `smart-loop` 提出。
> 那份实现（`static/js/smart-canvas.js`）的核心机制已逐段核对。本文抄的是**概念**，
> 实现按轻画的分层与命令式架构重写。

#### 数据模型

| 字段 | 含义 |
| --- | --- |
| `count` | 循环几轮 |
| `loopStart` | 从上游素材的第几张开始（1 起） |
| `batch` | 每轮取几张素材 |
| `mode` | `serial` 串行 / `parallel` 并行（并行受执行层并发上限约束） |
| `useImageInput` | 是否把上游素材当输入分发（关掉则只循环提示词） |
| `usePrompt` | 是否启用提示词（关掉则下游用各自的提示词） |
| `prompts` | 本节点的本轮变量提示词，**多条**：按轮次取模轮换后追加到上游上下文 |
| `lastRoundIndex` / `lastRoundPrompt` / `lastRoundAssets` | 最近一轮实际使用的轮次、完整提示词与图片，供节点回看 |

#### 输入：怎么取上游

| 项 | 规则 |
| --- | --- |
| 素材 | `useImageInput` 开着才取。收集**直接上游**所有图的并集，再按轮次**切片**：`refs.slice(start-1 + (轮-1)*batch, 长度=batch)` |
| 提示词 | `usePrompt` 开着才取。所有上游提示词作为**每轮共享上下文**保留；本节点 `prompts` 按轮次取模，作为本轮变量追加在后。最终文本按内容去重，同一段上游文案只出现一次 |

**素材用切片、提示词上下文常驻**：素材取完就没有了（第 4 轮不该再拿第 1 张图）；
上游提示词描述的是整套任务，不能在中途丢掉。本节点变量提示词按轮次取模，
例如「现在生成第 [计数] 张主图」每轮都要参与最终请求。

#### 输出：它给出什么

它输出的是**本轮分到的那份输入**。下游照常取上游素材、拿到的是循环节点，循环节点回答「本轮我分到这几张」，于是下游**零改造**地跑 N 次。节点同时保留最近一轮的提示词与图片缩略图，便于确认循环实际用了什么。

#### 变量（提示词里可写）

两种写法都认（全角书名号 / 半角方括号）：

| 变量 | 输出 | 例（第 3 轮 / 共 10 轮） |
| --- | --- | --- |
| `《计数》` `[计数]` | 当前轮次 | `3` |
| `《总数》` `[总数]` | 总轮次 | `10` |
| `《进度》` `[进度]` | 进度 | `3/10` |

界面上提供「计数」按钮插入变量芯片（不让用户手打符号）。

#### 执行：怎么接进 runEngine

**不新增执行引擎**。一轮 = 一个 `RunTask`，N 轮 = 同一个 `RunPlan` 里 N 个任务：

| 项 | 做法 |
| --- | --- |
| 轮次标识 | 复用既有的 `seq`（同主体第几次调用）与 `callCount`（本主体总调用数） |
| 依赖 | 每轮的下游链路各建一份 task，`dependsOn` 保证串行；`mode==='parallel'` 时下游任务互不依赖 |
| 产物溯源 | 复用 `collectionItemId` 记「第几轮」，落位与溯源不必新增字段 |
| 参数传递 | 每轮把 `{index, total}` 塞进该轮任务的 `params`，供提示词替换时读取 |

**为什么不做成引擎的循环原语**：`runEngine` 是共享层（canvas / comic 共用），
循环是画布的产品概念。塞进引擎等于让 comic 也背一个它不用的概念——
与「由第二个消费者定义接口边界」的教训相反。展开成多个 task 后引擎零改动。

#### 与现有规则的关系

| 规则 | 说明 |
| --- | --- |
| 产物落位 | 每轮各自建承载节点并排铺开（沿用 §6.16「每次生成新建并列承载节点」），互不覆盖 |
| 撤销 | 整次循环运行 = **一步撤销**（与批量运行同口径：`beginPlan` / `endPlan` 包住） |
| 中断 | 停止后已完成轮次的产物保留（不回收），未开始的轮次不再发起 |
| 连接合法性 | `accepts.upstream` 与其它节点一致推导；循环节点可被下游当普通上游连接 |
| 环检测 | **禁止把循环节点接回自己的上游**，否则展开时会无限递归。沿用 `topoSort` 的环检测 |

#### 交互与视觉定稿（2026-09-28）

| 项 | 定稿 |
| --- | --- |
| 图片 / 提示词选中态 | 统一使用 `--node-contrast-bg` / `--node-contrast-text` / `--node-contrast-hover`：浅色黑底白字，深色反转为浅底深字；不得用会在深色主题失去对比的固定黑色 |
| 左侧编号角标 | 圆心压在文本输入框**左上角顶点**上；角标以输入框顶点为定位基准，再用 `translate(-50%,-50%)` 反向平移自身半径 |
| 右侧删除按钮 | 圆心压在文本输入框**右上角顶点**上；按钮以右顶点为定位基准，再用 `translate(50%,-50%)` 反向平移自身半径 |
| `+` / `×` 图标 | 使用对称矢量 SVG，不使用文本字形；圆钮容器用 `grid + place-items:center`，确保图标中心与圆钮中心重合 |
| 提示词输入 | 直接点击输入框任意空白处即可获得焦点并输入，不要求先点「计数」；编辑器根节点带 `nodrag`，避免画布节点拖动抢走 `pointerdown` |
| 新增提示词 | 提示词变量行右侧的圆形加号与「计数」按钮同高，当前为 `28×28`；不要缩成低于同行控件的小点 |
| 数字面板 | 点触发器打开，**不自动关闭面板**。快捷数字直接提交；自定义输入右侧的 `24×24` 加号是步进器，点击后把当前自定义数字加一并立即提交，不再承担“应用 / 勾选”语义。只有点击面板外部、再点触发器或按 `Esc` 才关闭 |
| 数字面板的弹出方向与边界 | 默认自控件**向上**浮出。**节点内上方装不下时改为向下弹**（下方是空白画布，不会撞上任何浮层）；**横向收进画布视口**（贴边时留 8px）；两个方向都装不下时保持向上，不许来回翻。判据只有一条：**8 个快捷档位、自定义输入与加号都必须完整可见且点得到** —— 越界的浮层被裁掉后连点击都会失效（2026-11-14 #1100：节点包装层的 `content-visibility` 把它裁到框内，`1`、`5` 两格点不到） |
| 运行键禁用态 | 保持 `--node-contrast-bg` / `--node-contrast-text` 的黑底白字（深色主题反转为浅底深字），不用灰色替换；仅通过 `disabled` 与 `cursor:not-allowed` 表达不可运行 |
| 画布缩放清晰度 | 画布世界层不得写 `will-change: transform`。它与节点内部 `container-type` 在非整数缩放下共同作用，会让节点模糊或只有一部分清晰；保持 `will-change:auto`，缩放时由浏览器正常栅格化 |

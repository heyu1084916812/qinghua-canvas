## 7C. 页面六：本机 CLI · 2026-10-06 新增

**「全局设置」浮层的第二栏**（紧跟在「渠道配置」下面），不再是每个渠道页面里的一个协议选项。
用户口径：「CLI 可以单独设置在全局设置里面了，**就在渠道配置的下面**，重新设计界面，保持整体的
风格统一，当前是在每个渠道的页面里面」＋「我的要求和目的就是**链接后能用里面的额度调用模型生成
图片或者视频，或者对话**，RunningHub 也要，**需要真的能跑本机的 cli**」。

### 为什么单独成栏

CLI 与「某个站怎么连」无关：它花的是**用户自己那台机器上的登录态与额度**，与渠道的
baseUrl / 令牌是两回事。写进渠道就会出现"同一台机器上的 Codex 要在三条渠道里各配一遍"
（与 §7B 图床同一条理由）。

### 一栏里有什么

| 元素 | 规则 |
| --- | --- |
| 工具 | 四个默认：**Codex**（原 GPT CLI 改名）/ 即梦 / Gemini / RunningHub。目录在代码里（`domain/shared/cliTools.ts`），库里只存"用户改过的字段" ⇒ 以后加第五个不用迁移 |
| 命令名或完整路径 | 用户自己填。填 `codex` 就按 `PATH` + `PATHEXT` 找（Windows 上 `codex` → `codex.cmd` 也认）；填带分隔符的路径就直接判那个文件 |
| 检测 | 只看**文件在不在**，不执行任何东西。找到回绝对路径，找不到回"确认名字，或者改填完整路径" |
| 参数模板 | 空格切词、引号可包住含空格的一段；占位符 `{prompt}` `{out}` `{model}` `{workflow}` 跑前替换，**没给值的原样留着**（好在输出里一眼看见缺什么） |
| 超时 | 默认 2 分钟（各工具 5~20 分钟），壳里再夹一次 [1s, 30min] |
| 测试运行 | 真起子进程，把**退出码 / stdout / stderr / 耗时**原样贴出来；超时写"已掐掉"、被取消写"已取消" |

### 版面：**只有按钮**（用户 2026-10-08 第 3 条）

原话：「cli 面板那边的介绍内容太多了，用户是不会去看的，反而影响排版，不需要文字介绍，
只需要按钮，按钮的功能要确实要生效」。于是：

- **删**：面板导语两段（"这里配的是你本机装着的命令行工具…"、"每张卡顺序就是你要做的事…"）、
  每张卡的工具介绍段（`note` 改成名称上的**悬停提示**：信息还在，但不占版面）、
  按钮旁的静态说明；
- **留**：卡片头（名称 + 能力小标 + 文档链接）、全部按钮、「高级（命令与参数）」、
  以及**按动作出现的结果**（检测结果 / 登录消息 / 状态输出 / 安装提示）；
- 额度提示压成**一行**（顺手去掉文案里那对没被渲染的 `**`）。冒烟 G97 钉住：
  面板里 `desc` / `note` 两档计数为 0、每张卡文案 ≤ 200 字、每张卡都有「登录方式」框。
- **唯一的例外：登录方式那一行**（2026-10-08 用户给的第 1 张参考图：那张卡把
  "怎么登录 + 主按钮"放进一个浅底小框里）。它**留在版面上**而没被收成悬停提示 ——
  理由与参考图一致：它直接决定用户按哪个按钮。写成 `CliTool.loginHint`（一行，≤ 40 字），
  框里的按钮是这张卡的登录主动作（能开窗口登录的用「一键登录（打开窗口）」，
  只能写配置的用「用密钥登录」）。

### RunningHub 的登录：**由壳写它自己的配置**（同一条用户口径的后半句）

用户：「runininghub 的 cli 是在 github 上找的，看看 github 上能不能把目前实现不了一键自动安装的
cli 给做好」。查清的事实（读官方 CLI 源码，`rh_cli`）：

- 安装：`python -m pip install git+https://github.com/HM-RunningHub/RH_CLI.git`（一键安装可用）；
- 登录：`rh auth set-key <KEY>` 的 Key 是**位置参数** —— 与"密钥不进 argv"的约定冲突，
  所以**不能**在应用里调它（打开一个窗口也没用）；
- 但它自己认**配置文件**里的 `api_key`（`config.py` 的 `resolve_api_key`：argv → 环境变量
  `RUNNINGHUB_API_KEY` → `%APPDATA%\rh\config.toml`）⇒ **壳直接写那一行**，
  与用户手敲那条命令等效、**且持久**（他自己终端里的 `rh` 也立刻是登录态）。

面板上就是：粘 Key → 「用密钥登录」→ 壳写配置 → **当场跑一次 `rh --json check` 验证**。
写配置的路径由壳自己拼（前端给不了路径），所以借这个能力动不了别的文件。

### 安全与边界（写死在代码注释里，免得以后被"改成 shell 更灵活"）

1. **不经过 shell**：`Command::new(program).args(args)` —— 没有 `cmd /c`、没有 `sh -c`，
   参数是一个数组、不拼字符串 ⇒ 提示词里带引号 / 分号 / 美元符号都不会变成命令注入。
   命令由**用户自己**在设置里填，等价于他自己开一个终端：壳这边不加白名单，也不替他拼字符串。
2. **浏览器里如实说"用不了"**：`CliPort` 是**可选端口**，缺席时界面照旧显示（用户要的
   "桌面专属能力也要看得见"），但两个按钮禁用并写明"只在桌面应用里可用"——**不假装能跑**。
3. **渠道页留出口**：`jimeng-cli / gpt-cli / gemini-cli / runninghub` 四条协议已
   `kind: 'hidden'`（**条目不删** —— 老渠道存的就是这些 id，删了会变「未知协议」），
   新渠道的协议下拉里不再出现；渠道页给一行**能点**的「去『全局设置 → CLI』配置」，
   点它直接落到那一栏。

### 已经接进执行层（2026-10-06 补齐）

画布上的生成节点**真的能调本机 CLI 产出素材**了：选一条 CLI 协议（例如「即梦（本机 CLI）」）
→ 面板里选中它报出来的模型（`即梦图片` / `即梦视频`）→ 点生成，命令按「全局设置 → CLI」里那份参数模板跑起来，
产物（`{out}` 指向的文件）被读回来当素材落库。对话走同一条路（stdout 即正文）。**类型按字节魔数认**、超时与取消都能真掐掉；浏览器里同一条协议回落"访问自建网关"。


### 「一键设置」与额度怎么显示（2026-10-06 第 13 批第 2 条补齐）

用户原话：「如果查不了额度，**我如何显示额度**，我要解决这个问题，还有**我如何使用**的问题，
我不太懂怎么设置这个 cli，我希望是我**一键设置**，然后输入密码或者其他的就可以**保持登录**」。

于是每张卡按**用户会问的顺序**排（命令与参数收进「高级」，默认折起）：

| 步骤 | 界面 | 说明 |
| --- | --- | --- |
| 装没装 | 「检测」 | 只看文件在不在；没装就贴一句"怎么装"（含官网 / 安装命令） |
| 登录 | 「一键登录（打开窗口）」 | 在**可见控制台窗口**里跑它自己的登录命令（浏览器授权 / 输密码都行）；壳**不捕获输出、不等待** —— 交互登录没有"跑完"这一说，完成后回来点「检测 / 查状态」确认 |
| 登录（密钥） | 粘贴密钥 + 「用密钥登录」 | 密钥走 **stdin**（`login --with-api-key` 这类）：不进 argv、不进历史、**不落我们的库**，用完即清 |
| 查状态 / 额度 | 「查状态 / 额度」 | 跑工具自己的命令，**原话照贴（含 stderr）**；查不到就直说，并写明额度去哪儿看 |

**额度这条要说清现实**：多数 CLI **不报余额**（实测 `codex --help` 里没有 usage / quota 类子命令，
只有 `login status` 能回「Logged in using an API key - ***」，而且那句在 **stderr** 上）。
所以：能查到什么就显示什么（原话），查不到的由 `quotaWhere` 说明**去哪儿看**
（即梦 = App / 网页的「我的」；Gemini = Google 账号用量页；RunningHub = 网站个人中心）—— **绝不编一个数字**。

两条边界：**网页上的登录态读不到**（那是浏览器 profile 里的 cookie，命令行工具用它自己的登录）；
**官方没有 CLI 的工具**（即梦 / RunningHub）只能给"怎么自备一层封装"的指引，界面如实说，不假装能装。

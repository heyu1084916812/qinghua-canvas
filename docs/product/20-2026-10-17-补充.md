## 2026-10-17 补充：灯箱双入口、融合原因条、对比左右口径

- **灯箱框选**：图片的「提取选区」和「裁剪」是两个独立入口，但进入同一个灯箱后，底部模式条必须**同时显示两者**。从哪个入口进入只决定默认选中项；用户可在灯箱里直接切换，确认文案、产物标题和是否携带选区上下文随模式变化。框脸只在明确要求框脸时显示。
- **融合失败原因**：除按钮 `title`、toast 和运行日志外，融合节点卡片内还要直接显示一句短原因。短原因由结构化原因码生成：完整图边界 / 无上游 / 上游不是局部图 / 多选区冲突 / 缺原图 / 缺局部修改图。完整原因继续保留在 `title` 与日志中，短句不另造事实。
- **对比节点左右顺序**：左右取自直接上游的连线先后顺序；**先连接 = 左 A（底图）**，**后连接 = 右 B（覆盖层）**。节点标签必须把该顺序写清，而不是只写泛化的 A/B；改动较小时，用户拖动中间竖线查看差异。
- **对比节点灯箱语义**：对比节点用 `compareKind: 'pair'` 打开灯箱，三档是「A·左 / 对比 / B·右」，不得出现“原图/结果”；分割模式下 A 为左半底图、B 覆盖右半。融合结果仍用 `compareKind: 'result'`，保持「结果 / 对比 / 原图」和“左原图、右结果”的方向。
- **Nano Banana 2.1（2026-10-17）**：节点前端显示名为 `Nano Banana 2.1`，已知官方上游 ID 为 `gemini-nano-banana-2.1`。参数口径按 Google 官方图片生成文档：14 档宽高比、1K/2K/4K，不支持 512；适配器走 Gemini 原生 `generateContent`。模型下拉、后台映射和 Agent 生图清单都来自同一固定目录，不能只加其中一处。
- **选模型必须同步节点渠道记录（2026-10-17）**：用户界面不选渠道，但节点仍需要 `channelId` 才能进入执行计划。若只改 `model`，创建时的旧渠道会留在节点里；执行层虽然会按模型重新选路，日志却会出现“节点记录的是 ModelScope，实际发到 Comfly”的假冲突。选模型时用 `channelIdForLogical` 同步到真正可路由的渠道，并与模型一次落库；日志写“节点记录的渠道”，不写“节点选的渠道”。
- **普通画布自动命名（2026-10-17，100 组矩阵升级）**：Agent 节点名来自模型生成的 `title`；普通生成节点使用确定性命名器，优先级固定为「手动标题 > 来源/Agent 标题 > 素材文件名 > 业务用途 > 预设 > 提示词摘要 > 图片/视频兜底」。素材名会去掉扩展名、路径、副本后缀和括号序号；`IMG_1234`、微信图片、截图、纯 hash 等泛化名不参与命名。提示词会清理中英文命令词、标签、引号、mention、代码块和 Midjourney 参数；英文长句优先在单词边界截断，并移除 `on / with / at` 等残留连接词。同一来源多张使用 `-01`、`-02`；重名按大小写不敏感顺延。全程不调用 LLM，不增加费用和延迟；下载文件继续复用节点标题加 8 位内容哈希。
- **链式默认名与旧数据修复（2026-10-17）**：`image / img / photo / untitled / screenshot` 与中文默认名同属泛化名；`的输出N / output N / -01` 可递归剥离，因此 `image的输出1的输出2-01` 会被识别为系统名，不再当作手动标题继续套娃。项目水合时执行一次幂等修复：有产物的同 prompt 旧结果按 `-01/-02` 成组改名，空生成节点改成无序号主题名，手动标题和无可读语义的节点保持不动；修复结果直接写回 `nodes` 表。
- **桌面单实例与窗口恢复（2026-10-17）**：桌面壳接入单实例插件，第二次启动不会新开一套应用，而是恢复已有主窗口并聚焦。启动与恢复统一执行 `show → unminimize → focus`；窗口 label 查找失败时回落到当前任一 WebView，避免手动构建窗口的版本差异导致回调空转。Windows 最小化时 `(-32000,-32000 / 160×28)` 只用于恢复，不得作为正常几何落盘。
- **桌面托盘、呼吸心跳与白屏恢复（2026-10-17）**：桌面常驻托盘，左键恢复窗口；菜单提供“打开轻画 / 重新加载界面 / 退出轻画”。关闭按钮在有托盘时只隐藏窗口，生成任务和系统通知继续运行；真正退出走托盘菜单。React 挂载后每 5 秒上报 `ui_heartbeat`，窗口可见但 20 秒无心跳视为 WebView 卡死，自动重载，生产环境再次失败则重启。当前 WebView2 Runtime 对 Vite dev URL 存在渲染进程崩溃，但 release 自定义协议加载内置 `dist` 正常；桌面联调与交付不得把 Vite dev URL 白屏当作业务页面错误。

> **2026-10-18 状态补充（对账 #580）**：漫剧台词已接入真实 TTS 链路 —— 渠道模型类别新增 `audio`，OpenAI 兼容协议走 `/audio/speech`；每句台词可单独选音色、语速、生成 / 重配与试听，产物字节落 `assets`，行上只存 `audioHash`。时间轴预览按字幕同一条时间线播放配音，FFmpeg 合成包把逐句配音按起点延迟后与 BGM 混入。仍欠口型同步；TTS 能力取决于用户渠道是否提供兼容的 speech 模型。

> **2026-10-18 状态补充（对账 #581）**：电商用途新增「爆款复刻」。它要求产品图 + 至少一张参考图，默认出 4 张；只复刻参考图的构图、机位、光影、色温与版式节奏，产品本体始终以产品图为准，不复制品牌 Logo、商标、水印、人物身份与不可核实文案。逐张脚本仍按多镜头展开，避免把复刻做成同一张图重复抽卡。

> **2026-10-18 状态补充（对账 #582）**：电商结果卡新增「AI 编辑这一张」。它是结果图的后续动作，不属于新建任务的第六个用途：用户逐张写修改要求，系统先把结果复制成独立画布节点，再创建 `usage: 'edit'` 的单张任务。新产物进入新的历史批次，原任务、原结果 hash 与提示词都不被覆盖，因此失败或效果不满意时可以回退。空指令与多张编辑在领域层直接拦截，不产生付费请求；编辑提示词只锁“未点名内容”，允许用户明确要求修改产品颜色、材质等局部属性，但仍禁止编造参数、认证、功效与价格。表单用途与左侧草稿继续只认主图 / 白底图 / 详情页 / 套图 / 爆款复刻五档。

> **2026-10-19 状态补充（对账 #583）**：漫剧逐镜视频支持首尾帧衔接。第一镜出图后可先生成单首帧视频；下一镜也出图后，按钮明确提示「首尾帧」，重出时复用原视频节点并把下一镜作为尾帧接入。视频节点记 `videoMode: 'first-last-frame'`，分镜记 `videoEndNodeId` 以便换镜时只断旧尾帧；模型明确不支持首尾帧时回落单张首帧。重出统一走 `inPlace`，不再给每次重出新建一个无人认领的承载节点。

> **2026-10-19 状态补充（对账 #584）**：漫剧每镜新增「视频提示词（运镜 / 动作）」字段，专门描述推进、拉远、摇移、人物动作与节奏；视频请求仍带静态画面和角色 / 场景资产块作为一致性基准。未填写时自动补一条自然连续运动约束；首尾帧模式再追加从当前镜向下一样画面自然过渡的要求。这样不会再把静帧提示词原样当成运镜提示词。

> **2026-10-19 状态补充（对账 #585）**：漫剧工具栏新增「这一集出视频」。它只补“已出图但缺视频”的镜头，按分镜顺序串行生成，已有有效视频不重跑；视频节点被删时也会重新补。每镜继续复用首尾帧、独立运镜提示词和原视频节点复用规则。按钮标题显示待补镜头数，全部完成后自动置灰，批量状态分别报告成功与失败数量。

> **2026-10-19 状态补充（对账 #586）**：漫剧工具栏新增「补齐本集配音」。它只处理有台词文本、但还没有音频的句子，按分镜顺序逐句生成；已有配音不会重跑。按钮标题显示待补句数，没有可用 audio / TTS 模型时禁用并说明原因。批量完成后分别报告成功与失败句数，单句重配仍走原来的逐句入口。

> **2026-10-19 状态补充（对账 #587）**：电商「AI 编辑这一张」增加清理杂物、纯白背景、统一光线、翻译画面文字四个常用模板。点击只把约束填进可编辑输入框，不会直接扣费；翻译目标语言复用当前电商文案语言。模板是提示词层能力，不宣称具备独立的抠图、超分或 OCR 模型；实际效果仍由当前生图模型决定。

> **2026-10-19 状态补充（对账 #588）**：电商结果区支持多选已完成图片并执行「批量 AI 编辑」。确认弹窗按选中数量明确报告真实用量，提交后逐张执行：每张都有自己的独立画布副本、编辑任务和结果记录，不把多张塞进一个任务，也不覆盖任何原结果。批量模板与单张编辑共用，便于一批图统一换背景、清理杂物或调整光线。

> **2026-10-19 状态补充（对账 #589）**：电商 AI 编辑任务会保存来源任务、来源结果与原图 hash。编辑结果卡据此出现「对比原图」，弹窗左右并排展示原图和编辑结果；窄屏自动改为上下单列。普通生成任务没有来源字段，不显示这个入口，也不通过节点反推不存在的对比关系。

> **2026-10-19 状态补充（对账 #590）**：漫剧分镜支持“转场到下一镜”的淡入淡出（黑场）。该字段属于前一镜这一条边，避免相邻两镜各存一份后冲突；只有前后两段都真有素材时才进入时间轴。浏览器预览用同一份 `fadeIn / fadeOut` 标志播放 CSS 动画，FFmpeg 合成包生成对应 `fade` 滤镜；系统开启减少动态效果时预览不做动画，导出仍保留转场。

> **2026-10-19 状态补充（对账 #591）**：电商 AI 编辑支持可选参考图。单张和批量编辑弹窗都能上传、预览、更换或移除一张参考图，提交后写入 `referenceNodeIds`，继续复用画布生成节点“连线即 inputs”的链路。批量编辑时每张结果的独立任务都会保存该参考图引用；参考图只存节点引用，不复制图片字节，也不改变原结果。

> **2026-10-19 状态补充（对账 #592 / #620）**：漫剧工作台增加桌面专属「本机合成成片」。共享库通过本机回环 `/asset/:id` 向 FFmpeg 提供真实素材字节，图片、视频、BGM 和逐句配音都按原 hash 读取；FFmpeg 用参数数组启动、不过 shell，黑场转场和整集时间轴直接进入命令。成片写入桌面 `cli-out` 后再走系统保存对话框交付。浏览器没有子进程，不显示该入口。桌面安装包现在随包提供经过 SHA-256 校验的 FFmpeg 9.0.2，优先使用包内资源，其次才回退系统 PATH；用户不再需要自行安装。

> **2026-10-19 状态补充（对账 #621）**：电商详情页长图的每一段现在都有逐张编辑入口。打开 / 裁剪 / 标注 / 旋转直接复用结果卡与画布灯箱的同一条链路，编辑前仍复制为独立画布节点；长图本身继续只负责挑选、排序、预览与导出，不保存第二份像素结果。

> **2026-10-19 状态补充（对账 #622）**：长图每一段再补「AI 编辑」与「AI 超清」。两者不在长图里复制一套状态，而是触发结果卡已有的编辑 / 超清弹窗：编辑模型、参考图、超清方案、倍率、真实用量提示和提交逻辑全部同源；AI 超清只处理当前段。工作台任务运行中入口同步禁用，避免重复付费。长图仍不复制图片字节，原结果与原任务不会被覆盖。

> **2026-10-19 状态补充（对账 #623）**：电商与漫剧项目页都改为“画布节点 / 连线水合完成后再开放工作区”。此前表单先可操作、后台后水合，用户快速上传的产品图节点可能被旧快照覆盖；界面只剩一张 pending，日志报源节点不存在。现在水合前只显示项目读取状态，失败原因也会明确显示。

> **2026-10-19 状态补充（对账 #593）**：电商结果多选现在是通用批处理入口，不再只服务 AI 编辑。可以全选已完成结果、取消选择，并串行下载所选图片；批量 AI 编辑继续复用同一份选择状态，没有第二套“已选”概念。

> **2026-10-19 状态补充（对账 #594）**：漫剧淡入淡出转场支持 0.1–1.0 秒自定义时长。字段只挂在“到下一镜”的前一镜上，时间轴同时给前后段写入同一时长；浏览器 CSS 动画和 FFmpeg `fade` 滤镜读取同一值。切换回硬切会清掉时长，避免留下不可见残留字段。

> **2026-10-19 状态补充（对账 #595）**：电商结果多选新增「收藏所选」。它复用同一份结果选择状态，只处理完成且可收藏的结果，逐张写入现有素材库；不复制素材字节，也不创建第二套收藏目录。批量编辑、下载、收藏和取消选择现在共享同一组选中项。

> **2026-10-19 状态补充（对账 #596）**：漫剧每镜的 `durationSec` 现在同时写入视频生成节点。字幕、配音、预览时间轴和视频请求使用同一目标秒数；具体模型若不支持该档位，仍由既有视频能力表夹取到合法值，页面不绕开渠道规格。

> **2026-10-19 状态补充（对账 #597）**：电商结果卡新增只读「详情」，展示这张图实际使用的模型、比例、生成时间、任务要求和完整提示词，并允许复制提示词。它不重新请求模型、不改结果，只把已落库的信息摊开，方便判断差异与复用。
> **2026-10-19 状态补充（对账 #599）**：生成节点创建时按实际 `mode` 选择默认模型类别，图片档只从生图模型里取，视频档只从视频模型里取，批量节点沿用同一规则；提示词节点仍只取对话模型。修复前同一渠道把聊天模型排在第一位时，图片节点会显示并保存聊天模型，执行层不会启动图片请求。现在默认模型的选择和节点用途一致，不再依赖渠道模型列表顺序。
> **2026-10-19 状态补充（对账 #598）**：漫剧桌面「本机合成成片」现在把本集 SRT 内嵌为 MP4 的 `mov_text` 默认字幕轨，不再只把字幕写进合成包。字幕文件由桌面壳写入受限的 `cli-out` 单文件目录，应用只允许 `.srt`、非空且不超过 2MB，并拒绝路径与控制字符。手动合成包也要求保存同名 `.srt` 并生成相同的内嵌命令，两条导出路径不再分叉。真实 FFmpeg 9.0.2 短片验证了字幕轨存在、默认标记生效，反解文本与时间轴一致。
> **2026-10-19 状态补充（对账 #600）**：漫剧分镜工具栏新增独立「导出 SRT」。它直接复用当前集预览与内嵌字幕轨同一条时间轴，下载 `${剧名}-第N集-字幕.srt`，因此外部剪辑软件导入的字幕与应用内成片字幕不会出现两套时间点。没有台词的集按钮置灰；没出图的镜头不占字幕时间轴，避免字幕与画面错位。
> **2026-10-19 状态补充（对账 #601）**：漫剧角色新增默认音色与语速。台词没有单独选择音色或语速时，自动继承说话角色的默认值；台词显式选择仍然优先，句级 `1.0x` 也能覆盖角色的非 1 倍速。单句生成、整集补配音都走同一套 `speechSettingsOf`，已有配音不会因为修改角色默认值而被删除；用户要换声线时仍按原入口重配。

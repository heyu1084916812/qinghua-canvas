## 12. 数据生命周期与迁移

### 12.1 存储布局

业务数据落在本机 shared-store 资源根，由 `manifest.sqlite` / `manifest.json`、`media/` 与 sidecar 组成。JSON V1 目录库只用于旧数据、测试和隔离探针：

```
shared-store  data-v2（SQLite V2 / JSON V1 迁移兼容）
  projects      项目元数据与视口
  nodes         节点
  edges         连线
  channels      渠道配置与模型缓存
  tasks         任务日志（按项目上限 500 条，超出滚动裁剪）
  runRecords    执行留痕（日志面板的数据源；从不删除）
  assets        按内容哈希去重的图片与视频（Blob）
  assetLibrary  手动收藏关系与保存时的冻结元数据
  credentials   加密后的凭据密文与盐
  presets       UI 偏好：生成预设（新建节点默认的渠道 + 模型）
  builtinSkills 内建技能与默认正文（只读）
  skills        用户技能（可编辑 / 导入 / 复制自内置）
```

- 素材字节落在资源根的 `media/`，`assets` 行保存内容 hash 与元数据，节点只持有内容哈希；`assetLibrary` 只记录“用户收藏了哪张”，取消收藏不删字节
- `tasks` 与 `runRecords` 的分工：`tasks` 是运行日志，有 500 条上限、可裁剪，服务于排障；`runRecords` 是**执行留痕**，**永不裁剪**，是日志面板逐条回看的数据源（曾经的「版本历史」功能已下线，见 §6.21，但这份留痕保留）。两者不可互相替代——留痕若依赖 `tasks` 会被日志滚动裁掉
- 每条 `runRecords` 记录携带本次执行的指纹（§6.19.6），节点当前生效的 LiveFingerprint 取该节点最新一条成功记录
- 导出 `.flow.json` 是项目备份与迁移通道；完整媒体建议同时使用素材导出或数据目录备份
- 数据目录由本机磁盘承载，设置页提供「打开数据目录」与备份入口；清理网页缓存不会删除 shared-store 业务库

**「全局设置 → 存储」那一栏说什么**（2026-10-06，对账 #261 / #285 / #293 / #297）。四块：
存储概况 / 数据目录 / 网页缓存 / 素材文件夹（选目录 · 打开目录 · 导出素材）。三条口径：

- **文案要人话**：用户追问过「那那个清理缓存不就对我的画布没啥用吗？」，所以缓存那一块
  **如实写**「**只省磁盘 / 不会让应用变快 / 不会动你的项目、素材与令牌**」。实测那堆是
  `Cache` / `Code Cache` / `GPUCache` 是网页缓存；而 shared-store 数据目录才是项目、素材与收藏的本体，
  **不在清理白名单里**。清理网页缓存不得删除业务库或 `media/`。
- **不做「JavaScript 堆内存」进度条**：参考应用图里那条（71.0MB / 4288.0MB）对本应用没有指导意义 ——
  内存大头是素材解码位图，不是能"一键回收"的托管堆；给一条会跳的数字只会误导。
  改成「缓存占用 + 一键清理（不影响项目与素材）」。
- **桌面专属功能在浏览器里也要看得见**：数据目录 / 缓存这两块的入口照样渲染，
  点了如实说"桌面版才有"（用户："不管是桌面才可以用的，但是 ui 需要给我显示出来"）。
- **版面只留「数字 / 路径 + 按钮」**（用户 2026-10-08 第 4 条：「存储面板也是介绍文字这么多，
  我也是只需要有用的，无用的文字介绍都给我删掉，帮我重排一下 ui」）：原来的四段解释**全撤**，
  改成一行一式（路径或数字在左、动作在右）；只保留三句**会影响决策**的一行小字 ——
  「自动保存：改动约 0.8 秒后落库，关窗前再落一次」／「项目、令牌与素材库都在这里；卸载不会删它」／
  「只省磁盘，不会让应用变快；不动项目、素材与令牌」／「放回画布：画布空白处右键 → 从素材文件夹加载」。
  冒烟 G97 钉住：`desc` 那一档计数为 0、面板总字数 < 400。
- **存储概览与素材页同口径**（2026-10-25，对账 #744）：素材 / 图片 / 视频 / 音频按
  「生成历史 ∪ 收藏」的 hash 并集去重，并排除用户从素材页隐藏的记录；不再统计底层
  `assets` 文件行。真实库验证 `存储 222 = 素材页全部素材 222`，图片 221 / 视频 1。
- **⚠️ 桌面壳里这两块是"真的可用"**（打开数据目录 / 清理网页缓存）：2026-10-08 真机探针抓到一处
  **装配漏转** —— `createWebPlatform` 收下了 `storageAdmin` 却没放进返回的 `PlatformKit`，
  于是**应用里**这两块也一直显示"仅在桌面应用可用"。已修 + 补单测（见对账 #374）。

**素材可以放在本地文件夹**（用户 2026-10-05：「把素材放在什么位置上，加载什么文件夹的内容」）。三档，同一套规则：

| 档 | 素材在哪 | 适用 |
| --- | --- | --- |
| **内置库**（默认） | 只在 `assets` 表 | 不想管文件、就用应用自己的库 |
| **本地文件夹** | 用户选一个目录，素材按 `<hash>.<ext>` 落盘，同时仍在 `assets` 表留**索引行** | 要能备份 / 多设备搬 / 打包成桌面应用后数据不丢 |
| **外部只读文件夹** | 别人的目录，**只引用不搬运**（扫既有图片，按内容哈希引用） | 已有图库，不想复制一份 |

- **命名用内容哈希**（`<hash>.<ext>`），不用原名：同一张图重复导入天然幂等，不会堆出「图 1(1).png」；可读性交给应用内的节点名与素材库，不交给文件系统
- **`assets` 行是索引，文件夹是字节**：读素材先查行拿 mime（文件名要它才拼得出），再向目录要文件；命中用磁盘那份，未命中回落内置库。远端产物（只有 url 的视频）直接用地址
- **写盘是"落库成功之后"的镜像**，且 `has` 命中即跳过（内容寻址幂等）——落库失败不该因为写盘失败而失败；写盘失败只记日志
- **文件被外部删掉/移走时如实说**：节点上显示「素材缺失」+ 它**本该在的位置**（`<目录名>/<hash>.<ext>`；没选目录就不给路径、mime 未知就写 `<hash>.*`，不猜），**不留永远转圈的骨架屏**、也不假装还有图
- **「导出素材到文件夹」（2026-10-05）**：画布左下角一枚入口，把内置库里的**全部**字节一次性写进已选目录（带进度：`导出中 12/48…`），结束时一句话说清「导出几个 / 盘上已有几个 / 只有远端地址搬不动几个 / 失败几个」。**幂等**：同名即同内容，再点不会写出第二份。用途是备份与换机器（含打包成桌面应用后的数据搬迁）——**"搬不动"的数量要当真报**：视频成片那类行里只有远端地址、没有本地字节，它们不会跟着文件夹走
- **选择 / 更换目录可以一步同步（2026-10-16，对账 #516）**：设置 → 存储里的主按钮是「选择并同步素材」（已有目录时叫「更换并同步」）——选完目录立刻把现有素材按同一套幂等规则复制过去；旁边保留「只换位置」用于确实不想复制的情况。这里始终是**复制，不是 move**：`assets` 表是主副本，文件夹只是镜像；删除主副本会让应用依赖外部目录是否还在。取消系统目录选择时明确停在原地，不拿旧目录冒充同步成功。
- **封装成桌面应用后是同一个端口换实现**（浏览器 = File System Access；桌面壳 = 原生目录读写），前端一行不改；详见《轻画-桌面封装方案.md》
- **"记住目录"这一条按环境分**（2026-10-05）：**浏览器里刷新后要重新选**（浏览器不允许静默恢复目录权限）；**桌面壳里记住**（路径存在应用自己的数据里，启动时重新授权）——不然每次开应用素材都先显示「缺失」，等于把"把素材放在文件夹里"做成摆设。目录被移走 / 拔盘时如实回落「内置库」并把这项记忆清掉

### 12.2 保存与恢复

| 场景 | 规则 |
| --- | --- |
| 自动保存 | 编辑事务提交后 800ms 写入；采用事务，项目元数据、节点与边要么全部成功要么全部回滚 |
| 素材清理 | 只删除「画布活引用」为 0 且超过 7 天的素材；清理前显示数量与空间。**版本历史（`runRecords`）持有的引用不计入计数**——否则永不删除的版本历史会让引用计数恒不为 0，这条规则将永不生效。清理后恢复旧版本时若素材已不存在，提示「该版本素材已被清理，需重新生成」，不静默失败 |
| 容量预警 | 素材总量 > 5GB、磁盘剩余 < 2GB、< 500MB 三档提示 |
| 手动备份 | 导出结构或完整项目；完整项目使用 ZIP 容器时必须标注格式版本 |
| 异常退出 | 启动时比较最后提交与恢复点，向用户说明时间和差异数量 |
| 中断恢复 | 启动时发现任务仍处于 `validating / queued / running / retrying` 时，保留来源节点、提示词、参数与承载节点，将任务改为失败状态，记录「上次运行因页面关闭中断，可重新生成」；恢复流程不自动重发模型请求 |

### 12.3 Schema 迁移

- 数据库使用整数 `schemaVersion`；每次升级只允许向前迁移，迁移前自动备份
- 迁移失败时回滚并允许导出诊断包
- `.flow.json` 包含 `formatVersion`、`appVersion`、`createdAt`、`checksum`；未知新版本只读打开
- 导入时重建 UUID 并维护旧→新 ID 映射，保留合法父子关系与连线

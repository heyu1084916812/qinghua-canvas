### 6.3 画布视口 · ✅ 已实现

| 能力 | 规则 |
| --- | --- |
| 平移 | 空白处拖拽；空格 + 拖拽；中键拖拽（无视当前是否选中节点）；触控板双指 |
| 缩放 | 滚轮，以鼠标位置为锚点，范围 10% – 500%。指针位于节点或面板文本框内时，滚轮归文本框处理 |
| 锚点坐标 | 以画布可视区左上角为本地原点；窗口坐标先减去可视区 `left / top` 再换算世界坐标。缩放前后同一世界坐标落在同一本地位置 |
| 网格 | 无。画布背景为纯色 `var(--bg-canvas)`，不绘制网格（用户 2026-09-28 拍板去掉） |
| 坐标系 | 节点存世界坐标，视口只做 `transform` |
| 重置视图 | `Z` 键或工具栏按钮，缩放至全部节点可见 |
| **导入素材** | 三种入口落到同一条链路：① 画布底部水平工具栏的「导入素材」按钮选文件，落在**当前视口中心**；② 从系统**拖入**图片 / 视频文件到画布空白处（拖到节点上不算），落点即拖放位置；③ 从系统**剪贴板粘贴**（`Ctrl+V`，2026-10-16 / 对账 #551），落点取鼠标位置、没动过鼠标则取视口中心。多个文件**横向依次排开**（间距 24px），一次导入 = 一次撤销步骤。只收图片 `png/jpg/webp` 与视频 `mp4/webm/mov`，其余文件跳过并提示「跳过 N 个文件：只支持图片 / 视频素材」；拖入期间画布显示 1px 虚线内描边提示 |
| **导入的即时性** | 选完文件到图片出现在节点里应当**几乎无感**：素材立即落库（不等自动保存防抖）、内容哈希走原生 `crypto.subtle`（不占主线程）、宽高读文件头（不为两个数字解码整张图）。连传多张时每一张都必须显示出来——「传上去了但一直是空白」属于故障，不是性能问题 |

> **拖放这条链路的判据只能是 `dragover` 的 `types`，不能看 `files`**（2026-10-16 / 对账 #551）：
> `dragover` / `dragenter` 阶段浏览器**不给** `dataTransfer.files`（安全限制，恒为空），
> 用「文件数」判断就会直接 `return`、不 `preventDefault` ⇒ 浏览器认定这里不接收
> ⇒ **`drop` 永不派发**。症状是「从软件外面一次都拖不进来」，而用合成事件写的冒烟**全绿**
> （合成的那份 `dataTransfer` 自带文件列表，正好绕开这一步）。
>
> 粘贴那条同理：**剪贴板里没有媒体就放行**，否则用户粘文字 / 粘路径会被一起吞掉；
> **文本框内一律放行**（节点正文里粘字才是用户的本来意图）。

### 6.4 小地图 · ✅ 已实现

- 右下角，约 200 × 140，距边缘 16px
- 渲染节点简化矩形（`#D8D8DE`）+ 视口矩形（半透 `#16161A` 描边）
- 视口框 clamp 在小地图边界内
- **视口框圆角与外框同心**（用户 2026-09-19）：视口比内容大时会铺满整框，此时视口框圆角必须等于外框圆角（10px）；此前写死 `rx=2`，方角戳进 10px 圆弧，看起来「描边不是同一个圆角、有东西被遮住」
- 点击 / 拖拽跳转视口中心，支持键盘导航
- 无边框，带轻阴影

**实现口径**（M6-27 落地，几处需要写清否则会被读错）

| 项 | 口径 | 为什么 |
| --- | --- | --- |
| 范围 | **只由内容决定**（顶层节点与容器；无内容时才退化为视口） | 若把视口并进范围，一边拖一边改视口会反过来改缩放，同一个光标位置映射到的世界坐标越拖越远——是个会自我放大的回路。范围与视口无关，映射就恒定 |
| 视口框越界 | **保尺寸、挪位置**钉回框内（比框还大时铺满整框） | 用「求交」会让框变小、读成「看得更少了」，而它真正的含义是「已经偏出去了」 |
| 忽略的节点 | 容器内子节点的 x/y 是局部坐标，**不进小地图** | 与「重置视图」「框选命中」同一口径（见 §6.3） |
| 键盘 | 方向键平移（Shift 加速 ×3）、`Home` 复位视图 | `Home` 与 `Z` 键共用同一份「缩放至全部节点可见」语义 |
| 不进 Tab 序列 | `tabIndex={-1}`：**点击后**才获得焦点，方向键 / Home 随即可用 | 画布的 Tab 已被 §6.3「逐个选中节点」占用（`preventDefault`），小地图挂 `tabIndex=0` 只是多一个永远走不到的停靠点，却会在焦点从应用壳进来时吃掉一站 |
| 让位规则 | 焦点在小地图内时，画布那套方向键 / Tab 导航**整体让位** | 否则一次按键会同时改视口和选中节点 |
| 滚轮 | 在小地图上滚轮**不缩放画布** | 它是导航控件，不是画布的一部分 |
| 层叠 | `z-index: 18`——高于工具栏（15/16）、**低于创作面板（20）**与日志 / 参数 / 版本面板（30） | 它与右下角的创作面板物理重叠；同级时后渲染的小地图会盖住面板「生成」按钮，用户点不到。规则是**常驻环境控件让位于临时作业面** |

### 6.5 工具栏 · ✅ 已实现

**形态：一条竖向长胶囊**（2026-09-19 改版）

| 规则 | 说明 |
| --- | --- |
| 外形容器 | 一条胶囊（`--radius-pill`），容纳全部按钮；**功能之间没有分割线** |
| 唯一常驻实色 | 只有**第一个**按钮（新建节点）是常驻实色圆（`--accent` 底 + 反色图标），其余都是隐性按钮 |
| 隐性按钮 | 常态只有图标、无边框无底色；**鼠标进入该按钮范围**时右侧浮出对应名称 |
| 名称标签 | 圆角矩形浮层，贴在该按钮右侧；容器与按钮都是**圆形**（`--radius-pill`），不用圆角矩形按钮 |
| 配色 | 两套主题各给一套（同 `--accent` / `--bg-surface` 的翻转口径） |
| 主按钮图标 | 第一个（新建节点）的 `＋` **比其它图标明显大**（它按"按钮盒满铺 + 留白"成像：2026-10-07 缩回 1× 后是 36 的盒减两侧 6 = 字形 24，其它图标 18）：它是这条工具栏唯一的主操作，该是视觉焦点 |
| 主按钮是矢量图标 | 第一个按钮的加号是 **SVG**（不是文本 `＋`）。文本字形的**位置由字体决定**——全角 `＋` 在字体盒里偏上偏左，旋转时会绕一颗**偏心的点**，看起来「没绕自己中心转」；SVG 的笔画由坐标定义，几何中心即字形中心，旋转精确。**旋转挂在图标本体上**（不是按钮上），绕的正是图标自己的中心 |
| 浮层可点性 | 按钮与浮层之间留一条**不可见延伸区**，且离开后延迟 160ms 再关；否则从按钮移向浮层的途中（中间有 8px 空隙）浮层会先关掉，**永远点不中** |
| 与容器同心 | 第一个与最后一个按钮的圆形必须与胶囊外轮廓**同心**：胶囊内边距左右相等、按钮宽度也相等，三者同宽时才可能同心。此前按钮与容器各用一套内距，首尾两个圆看起来「偏出去一点」 |
| 四边间距相等 | 胶囊内距**四边取同一个值**（6px）。此前上下用 `--space-3`(12px)、左右 6px —— 圆角同心了，**间距却不匀**，第一个按钮距顶 12px 而距左右只有 6px，肉眼读成「和顶部的距离偏大」（用户 2026-09-19 第二次反馈）。同心与间距匀是两件事，必须同时满足 |
| 图标形态 | 统一走 **线性图标**（描边、不填充），与参考产品一致；用仓库内的内联 SVG 图标模块，不引第三方图标库。**所有图标一律内联 SVG，禁用文本字形**（`▶ ■ ✎ ⧉ ▣ ⬇ ✕ ⌄ ⚙ ◌` 这类）：字形的落点、宽度、基线由**用户机器上的字体**决定，换台机器就偏 —— 节点跟随栏那 8 个动作图标原先就是字形，2026-09-30 已全部换成矢量（见 §6.9） |
| 整体尺寸 | **1× 口径**（2026-10-07，第 13 批 #6：用户「画布区域左边的工具栏可以缩小三分之一了」）。沿革：2026-09-19 用 `zoom: 1.5`「加大一半」（48×280 → 72×420、按钮 36 → 54）；2026-09-22 为修"加号旋转偏心"（半像素取整）取消 zoom、改成**显式尺寸** 54 / 27 / 9 / 12；2026-10-07 又整体 ×2/3 **回到 1×** —— 按钮 **36**、图标 **18**（比例仍 0.5）、内距 **6**、间距 **8**，菜单 240/6 → **160/4**、菜单项 padding **8/12**、菜单图标槽 **16**，名称与菜单文字从换算值 18px 回归 **`--fs-label`**。⚠️ 上面那条「首尾同心」是**三处尺寸凑出来的等式**（容器宽 = 按钮 36 + 左右内距 6×2 = 48，半宽 24 = 按钮半径），手改任意一个数就会重新偏心 —— 要改就整组一起改（冒烟 G17 有三条断言守着：按钮 36、四边内距相等、图标/按钮比例 0.5） |

**② 排列与整理**（≥ 2 个节点选中时可用，2026-09-19 合并）

工具栏一个按钮，鼠标进入其范围时在右侧浮出面板（**每项前方带线性图标**）。
面板内含三种排列方式 + 整理节点，**按选中集合就地重排**，未选中节点完全不动：

| 排列 | 规则 |
| --- | --- |
| 宫格排列 | 按接近正方形的列数铺成网格，行列间距统一 24px；保持原相对顺序（先上后下、先左后右） |
| 水平排列 | 全部排成一行，垂直方向居中对齐同一中心线，水平间距 24px |
| 垂直排列 | 全部排成一列，水平方向居中对齐同一中心线，垂直间距 24px |
| 整理节点 | 按**上下游连线**做分层布局（无上游 = 第 1 层，层级从左到右，同层纵向排列）；存在环时提示「存在循环依赖，无法整理」 |

**为什么合成一个面板**（用户 2026-09-19）：四者同属「按某种规则重排选中节点」，
差别只在规则——三种排列纯按位置，整理节点看连线。拆成两个按钮只是让工具栏更长，
合并后用户在一个面板里按需求挑一个即可。整理节点**保留原实现**，只换入口位置。

**整体锚点**：排列后整块的**包围盒中心保持不动**——不许排一次就把整组甩到画布别处。
**撤销**：四种各是一次可撤销事务（共用同一条事务边界）。

**③ 重置视图**：等同 `Z` 键

**④ 撤销 / 重做 / 导入素材**：与之前一致

> **8 种对齐已下线**（用户 2026-09-19）。理由：对齐只改一个方向的坐标，
> 而「排列」已经覆盖「重排成网格 / 行列」、「整理节点」覆盖「按连线层级重排」，
> 三者并存时按钮墙太长、语义互相重叠。`domain/canvas/layout/align.ts` 及其调用一并移除。

**通用规则**

- 标题统一浮在节点外左上方，双击重命名（单击已被「在节点任意位置按下 = 选中 + 拖动」占用，见 §6.15）

- 分组 / 批量内部的节点端点隐藏。**批量**只能通过容器自己对外连接（它就是一个集合）；**分组**的右端点拖出来 = **组内成员各连一条**到目标（组本身不产出，见 §6.11）

#### 素材缩略图的语义与操作

**上游链接 ≠ 节点内容**。上游链接的素材是本节点的输入，节点自身上传或生成填入的素材才是内容。两者在缩略图区共存，语义与操作不同。

| 缩略图来源 | 操作 | 说明 |
| --- | --- | --- |
| 上游链接的素材 | 小眼睛隐藏 / 启用 | 隐藏后变灰、降低透明度、缩略图仍在原位、不参与本次生成；取消与上游的链接时才移除 |
| 节点自身内容 | 删除 | 删除后节点失去该素材；删掉唯一内容时节点回到空态 |
| 全部缩略图（含集合卡） | 拖动排序 | 顺序决定生成时的「图一 / 图二 / 图三」编号 |

小眼睛与删除图标隐性，鼠标进入缩略图范围时浮现。

### 6.7 提示词节点 · ✅ 已实现

#### 节点本体

- 标题浮在节点外左上方
- 上游可连接图片/视频节点与提示词节点
- 上游连了提示词节点时，文本输入区上方出现胶囊容器「上游已链接提示词节点」
- 外部容器保留细圆角边框；内部文本容器与底部操作容器为无描边、无填充的透明容器。选中时只改变外部容器边框颜色
- 文本超出容器高度时显示内部滚动条；指针位于提示词节点范围内时滚轮只滚动正文，不选中节点、不进入编辑态，滚到顶/底也不穿透为画布缩放；滚动条贴节点内侧右沿
- 正文 textarea 默认 `readOnly`，普通状态单击只触发拖动；双击进入编辑态，自动 focus + 选中全文；编辑态中 `Ctrl/Cmd+A` 全选当前文本，`Esc` 退出
- 全屏编辑通过右键菜单「全屏编辑」打开灯箱
- **正文格式工具栏**（用户 2026-09-21）：选中提示词节点时，跟随栏换成格式按钮——`H1 / H2 / H3 / 正文 | 粗体 / 斜体 / 无序 / 有序 / 分隔线 | 复制 / 全屏`。**只有线性图标、不带文字标签**（完整名称走 `title` / `aria-label`），且工具栏**自身无边框**（跟随栏已有 1px 描边，自带框会形成「框里有框」）。按钮作用于**节点正文**，底层写的是 **Markdown**（`#` 标题、`**` 粗体、`-` 列表、`---` 分隔线）。
- **显示层隐藏 Markdown 符号**：节点本体按 Markdown 渲染（标题变大、粗体加粗），用户**看不到** `#` `**`。底层保持 Markdown 源码——图像模型能读懂这类标记，而 HTML 标签对它是噪音且白占 token。
- **文本编辑灯箱**：跟随栏「全屏」或右键「全屏编辑」打开。观感同素材灯箱（**居中大面板、四周留白、不能移动**），左侧编辑（带符号的真实文本，保住原生光标与输入法）、右侧预览（隐藏符号后的效果）。`Esc` / 点面板外关闭。
- **双击的两种状态**（用户 2026-09-21 明确）：**非编辑态**双击 → 进入节点内编辑态（出现输入框，可直接打字）；**编辑态且正文非空**时再双击 → **全选正文**。编辑态里 `Esc` 或失焦退出。长文本编辑仍走文本编辑灯箱。
- 底部分两段：左侧字数裸放在节点背景上，右侧「优化」「翻译」「反推」三个按钮放在浅灰圆角容器内
- 自由缩放，最小 `240 × 160`；上方文本容器随节点高度缩放，底部容器高度固定、宽度跟随

#### 创作面板

**第一部分 — 上游素材**：上游图片缩略图；编号角标在左上角（显性），小眼睛在右上角（隐性）；取消上游链接时缩略图才移除；可拖动排序。

**第二部分 — 文字输入**：多行文本输入，输入区无框，占位「输入提示词（下游生成节点读的就是这里）」；溢出时内部滚动。右下角只留**字数**。

> **面板输入与节点结果分离**（用户 2026-10-23 重新定稿，取代 2026-09-24 的“面板直接写正文”）
>
> 面板下方是**LLM 输入草稿**（`data.draft`），节点上方是**结果正文**（`data.text`）。
> 面板只读草稿，**不回退显示正文**；节点手写因此也不会反向同步到面板。
> 面板输入不再实时覆盖节点正文；不提供「写入节点」按钮。
> 优化 / 翻译 / 反推 / 技能的结果写 `text`；节点正文仍可双击手写，也继续作为下游
> 读取的提示词（`promptSpec.collectInputs()` 只读 `text`）。
>
> **点「生成」时，草稿就是 LLM 请求**（用户 2026-10-23 补充）：正文为空、草稿非空时，
> 执行层先调文本模型生成正文，再跑下游。**compose 是“执行用户请求”，不是“把请求
> 改写成提示词”**：用户要故事就写故事，要提示词才写提示词，要分析 / 改写 / 翻译就照做；
> 只有草稿明确要求反推 / 描述图片 / 写提示词、且连着上游图时，才套「反推」指令。
> 正文已有内容时**不覆盖**，直接拿现有正文跑下游；想重新生成需先清空正文。
> 模型失败或返回空会明确提示并中止，不会写空正文，也不会继续跑下游。
>
> 下游生成节点没有提示词、上游提示词节点 `text` 也为空时，直接报「还没有写提示词」。
> 预设 / 情绪会拼进提示词，所以空正文 + 有预设也算有内容。普通生成 / 批量节点的
> `prompt` 行为不变。

三部分之间只通过留白区分，不出现边线、阴影或聚焦下划线。节点正文本身仍可双击直接编辑。

**第三部分 — 模型与生成**：只有模型选择（**没有平台 chip**，用户 2026-09-27 第 8 轮：「提示词节点也不需要平台的配置了，只需要模型即可」）；最右侧为生成按钮。渠道不再由用户手选 —— 面板的解析链会把**真能提供这个模型**的那条渠道写进节点（`channelIdForLogical`：映射优先、同名直配兜底），文本调用从节点的 `channelId` 取渠道。文本模型候选项**只有固定显示名**（GPT-6 Astra / Sol / Luna、Gemini 3.8 Flash），渠道拉回来的对话模型不进这个列表（2026-10-08 方案 A，见 §6.8）。

> **模型 chip 一律可点**（同轮）。旧口径是「该渠道没勾对话模型 → 置灰并显示『暂无可用文本模型』」；
> 但下拉里现在永远有固定显示名，那个状态已经不存在，置灰只会让用户以为功能坏了。
> 默认值是固定清单的第一个对话名（`GPT-6 Astra`）—— 此前渠道勾选顺序里排第一的
> `advanced-voice` 成了默认，用户明确否掉（「目前需要一个默认的显示，不是 advanced-voice」）。

> **这里也走逻辑名映射**（2026-09-27 修）：此前文本调用把**显示名原样**发给上游，
> 用户配了映射也不生效 —— 而生成节点那条路早就走映射了。两条路各写一份必然分叉，
> 现统一经 `modelMap` 解析成该站真实 ID 再发。

**「技能 / 优化 / 翻译 / 反推」放在这一排的尾部**（用户 2026-09-24）：

```
[新建渠道] [mock-chat-1]  |  技能  优化  翻译  反推        (↑)
```

- 它们与渠道 / 模型 chip **同形**：同高、同圆角、同字号字重、**无边框、透明底**，
  只在 hover 时浮现背景。此前是「24px 高 + 1px 描边 + 全圆角」的小胶囊，
  与旁边的参数 chip 并排时明显是两种控件。
- 两组之间**只用一条竖线**分隔（`1px`，与参数行同高居中）。
- 字数单独一行，紧贴参数行上方（此前它与工具行两端对齐，中间会空出一整条）。

### 技能 = 设定；优化 / 翻译 / 反推 = 动作（2026-09-24 定稿）

这两类东西**长得像、机制不同**，此前被当成同一类（点一下都立刻跑一次 LLM）。

| | 技能 | 优化 / 翻译 / 反推 |
| --- | --- | --- |
| 本质 | **设定**（这次生成用哪段系统指令） | **动作**（预设好的处理，点完即跑） |
| 点击后 | 只是**选中**（按钮显示技能名），不发请求 | **立刻**调文本模型并把结果写回正文 |
| 生效时机 | **点「生成」时** | 点击那一刻 |
| 存在哪 | 节点上的 `skillId`（存 id，不存正文） | 无状态 |

为什么技能存 **id** 而不是正文快照：技能在技能库里可以随时改。
存正文等于把「选中那一刻的版本」固化进节点，之后改技能老节点不会跟着更新 ——
用户会以为改了没用。

为什么「点生成才生效」要放在**执行层**而不是面板按钮里：「生成」的入口不止面板一个
（右键菜单、快捷键 `R`、跟随栏），放在执行层才能保证**所有入口一致**；
放按钮里则只有面板那条路会跑技能。

技能找不到时（在技能库里被删）**不静默跳过**：清掉节点上的选择并提示，
否则用户会以为技能生效了，实际发出去的是没处理过的正文。

### 面板高度与文字框滚动条（2026-09-24）

| 项 | 规则 |
| --- | --- |
| 面板高度 | **跟着内容走**（`min-height: 360px` 保住原来那块「大面板」的观感）。不再钉死 360px —— 那是「文字一多面板里就出滚动条」的根因 |
| 高度上限 | 由**锚点下方还剩多少空间**决定（`--panel-available-h`，执行层按视口算出）。空间够 → 面板长高；不够 → 面板停住、自己滚，**生成按钮始终留在可视区内** |
| 文字框滚动条 | 沿用全局细滚动条，**无上下箭头**；位置在文字框自身的内边距之内，不在右边另加容器 |
| 文字框滚动条（2026-10-25 定稿） | 宽 **4px**；**不要**标准 `scrollbar-width`，只用 `::-webkit-scrollbar-*`；箭头 `display:none`；滚动时轨道取 **`--bg-surface`**（与节点内部同色），空闲 1 秒后轨道与拇指都透明 |
| 拖拽手柄 | **去掉**（`resize: none`）。面板已按内容定高，手动拉高的小三角既没用又占着文字框右下角；且它不随面板的 `zoom` 缩放，时灵时不灵。 |

> ⚠️ **滚动条为什么必须只用一套机制**（2026-09-24，踩坑后定的）
>
> 现代 Chromium 一旦看到标准的 `scrollbar-width`，就切到**内置滚动条**渲染，
> 并**整组忽略 `::-webkit-scrollbar-*`** —— 包括那条「隐藏上下箭头」的
> `-webkit-scrollbar-button { display: none }`。所以「我写了隐藏箭头、用户那边箭头还在」。
> **要自定义箭头/轨道/宽度，就必须完全不写标准属性。** 两套混写会互相打断。
>
> ⚠️ **量滚动条必须开有头浏览器**：Playwright 默认的 headless Chrome 用
> overlay scrollbar —— 浮动、不占布局宽（`offsetWidth - clientWidth === 0`）、
> 且忽略 `::-webkit-scrollbar`（实测注入 `width: 40px` 也毫无效果）。
> 在 headless 下**测不出**滚动条宽度与箭头，会得到「已修好」的错误结论。

#### LLM 行为

三个 LLM 按钮**同时存在于节点本体与创作面板**。面板按钮以草稿为输入，结果写节点正文；节点本体按钮直接作用于正文。节点正文始终是下游读取的那一份。

| 模型能力 | 效果（面板与节点本体一致） |
| --- | --- |
| 纯文本 LLM | 「优化」改写提示词并写回；「翻译」中英互译并写回 |
| 多模态 LLM（支持图像输入） | 「反推」把**上游图片**发给文本模型，反推出绘画提示词，覆盖当前文本 |

- 「优化」的目标是提升清晰度、结构与可执行性
- 「翻译」检测到中文时译为英文，检测到英文时译为中文，无法判断时就地说明
- 「反推」的输入是**上游图片**而非文本：本节点上游连着已出图的生成节点时才可点（无图时禁用并在悬浮说明里直说要先连图），有图即可点——哪怕一个字都没有。多张上游图一起发出，上限 4 张（按连线顺序取前 4）
- 节点本体的三个按钮固定在文本区右下角，图标 + 文字，默认弱化，hover / 聚焦 / 文本区选中时显形；
  **创作面板里的那一排**位于参数行尾部（见上），与渠道 / 模型 chip 同形
- 请求期间进入进行中状态并可取消；成功结果覆盖当前作用域的文本并保留撤销记录，失败保留原文并显示可重试原因

#### 输出到下游

连线到生成节点时，下游提示词区不自动带入正文；上游提示词在素材条里显示为一枚 `TXT` 图标，与上游图片缩略图同尺寸、同编号规则。点击该图标会选中并打开对应提示词节点；小眼睛控制它是否参与本次生成，删除角标只断开这条上游连线。

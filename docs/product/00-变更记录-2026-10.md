# 轻画 · 产品设计文档 · 变更记录 2026-10

> 2026-11-14 从原文件**原样拆出，正文逐字未改**（只去掉尾部空行）。

> **2026-10-31 Agent 画布巡检改为按需工具（对账 #837）**：画布巡检默认关闭，不再作为固定流程。
> 用户可在「全局设置 → Agent → 工具 → 主动能力」打开；打开只表示把 `visualReview` 工具提供给模型，
> 不会定时扫描或在后台持续巡检。只有当前消息明确要求“巡检 / 检查作品 / 验收一致性”时才允许调用。
> 开关偏好可以保存；巡检任务本身不持久化、不排队、不在离开页面后继续运行。

> **2026-10-28 文本工具模型与 SoonStudio 参考图（对账 #790）**：提示词节点的“优化 / 翻译 /
> 反推”必须使用当前仍由启用渠道提供的模型；用户在设置里没有勾选的模型即使曾被拉取缓存，
> 也不能被当成当前渠道可用。旧节点会自动重新解析渠道。SoonStudio 的 Gemini 参考图任务
> 改为异步提交和轮询，用户不会再看到“请求已提交但长连接中断、结果未知”这种不可恢复状态。

> **2026-10-28 Agent 单步计划、结果验收与队列直发（对账 #788 / #789）**：
> 任务计划一次只推进一个步骤，完成一步不会自动启动下一步；每个有产出的步骤生成完成后进入
> “结果待验收”，必须先让用户确认满意，才允许进入下一阶段。计划要单列未经确认的前提，
> 确认卡按目标、前提、步骤产出和验收要求分层显示。Agent 忙碌时发送消息一律先排队；
> 队列项提供“引导 / 删除 / 更多”，更多里只有“编辑消息”。点“引导”会立即把该消息送入当前
> 对话：运行中原子转为 steering，停在确认卡时则取消尚未执行的动作并以新用户回合发送。

> **2026-10-28 Agent 任务计划与长任务进度（对账 #786）**：复杂任务不能只显示一个“正在执行”。
> Agent 要先分析意图、已有输入和缺口；关键信息缺失时先问用户，信息足够后提出可确认的分步计划。
> 用户确认后，Agent 面板上方显示持久计划卡：标题、总进度、当前步骤、每一步的待开始/进行中/
> 完成/失败状态与勾选。步骤需要用户选择或批准时，任务暂停并出现确认卡，确认后从当前步骤继续。
> Agent 输出中的图片可点击放大。视觉验收只显示生成图片名称，不显示内部节点 id；项目没有绑定
> 品牌、产品、角色或自定义套件时，不检查、不提示、不报告相关缺失。

> **2026-10-27 Agent 确认取消与停止（对账 #785）**：用户点确认卡“取消”表示结束当前任务，
> 不是让模型换一种方案继续做。取消后必须停止当前 AgentJob、清掉持久确认卡、保留一条
> “用户已取消、工具未执行”的配对结果，不续跑模型，也不新增节点。用户点“停止”同样要立刻
> 收口确认卡、检查点、排队活动锁与旧请求回写；重开 Agent 或刷新页面不能复活已经停止的任务。
> 写操作确认批准后按合法状态链先回到规划，再进入等待生成，不能跨状态直接执行。

> **2026-10-27 视觉验收与只读子代理（对账 #783）**：用户要求检查图片、Logo、文字、产品结构、
> 角色身份或整套一致性时，Agent 可以调用视觉验收子代理。它读取真实目标图片和当前项目绑定的
> 套件素材，返回通过 / 需修改 / 无法验收三种结论，并逐条给出问题、画面证据和修改建议。
> 视觉验收只读：不写画布、不删除节点、不自动重跑付费生成；用户确认问题后，再由主管 Agent
> 执行下一步。不能识别图片或无法确认的内容必须如实列入“未检查”，不能编造问题。

> **2026-10-27 角色与自定义套件（对账 #782）**：套件库固定分为品牌、产品、角色、自定义
> 四类。角色套件以身份、外观、服装、体型和跨画面一致性为指南，并用角色主图与参考素材锚定
> 视觉身份；自定义套件承载不适合归入前三类的长期规范。四类都支持不可变版本和项目固定版本
> 绑定，项目发布新版本后仍读取绑定时的旧版本，直到用户显式升级。

> **2026-10-27 总日志与漫剧日志（对账 #781）**：全局设置「数据」组提供跨项目总日志，
> 可按项目、工作台、状态和记录来源筛选；漫剧工作台提供只读取当前项目的日志抽屉。
> 两种视图读取同一份运行记录，不产生第二份日志数据库。每条记录至少显示状态、工作台、
> 模型、渠道、耗时、时间、项目、失败原因与路由尝试摘要；提示词只显示两行，完整内容仍可查看。
> 日志抽屉可点遮罩、按 Esc 或「关闭」收起；列表分页读取并保留加载、空态和错误态。

> **2026-10-27 电商恢复保存与中断状态（对账 #780）**：模型已经生成、但素材写入本地库失败时，结果卡必须显示“已生成，待保存”，只提供“重试保存”，不得让用户误以为模型失败而重新扣费。重试保存只处理同一份已生成产物。批次内各结果是无依赖的独立请求，应并行执行，不人为串行。应用重启后，没有活动执行租约的旧 `running` 批次必须显示“上次生成被中断，请重新生成”，不得永久停在“排队中”，也不得自动重发付费请求。

> **2026-10-27 个人记忆五层作用域与 Agent 确认（对账 #779）**：个人记忆分为全部工作台、单个工作台、当前项目和当前会话四种作用范围。Agent 只能在用户明确要求“记住 / 以后 / 每次 / 长期”或确认稳定规则时提出一条候选记忆，必须由用户在确认卡中点“保存记忆”后才落库；一次性要求不得保存。记忆可设置主题键、来源和有效期，同作用域同主题出现不同值时必须解释冲突并停止付费调用。设置页支持查看来源、项目 / 会话名称、主题、修订和到期日，并可一键“忘记”。上下文只装入本次作用域内必要片段，硬约束、事实和项目决定优先，低优先级偏好受字符预算限制。

> **2026-10-27 LibTV 正文完整恢复（对账 #778）**：LibTV 原始目录保持 1472 条，可执行正文从旧的 704 条修正为 **764 条**。恢复必须按模板 UUID 与原始导入清单一一对应，不能按名称、净化后的文件名或正文相似度猜测。详情中的 `SKILL.md` 与附件必须全部非空；列表只展示有真实正文的条目。对源站仅有公开介绍、没有主正文的 708 条，必须如实保留在目录但不展示“使用”，不能伪造正文。

> **2026-10-27 “Agent 与记忆”输入框与写入方式（对账 #777）**：“Agent 与记忆”是用户的主动长期偏好面板，不是聊天记录自动沉淀器。用户输入并点击保存后才会写入；一次性要求、普通对话和模型自己的猜测都不能自动成为长期记忆。已保存记忆按作用范围进入 ContextBundle，停用后不再参与。新增与编辑记忆的文本框必须始终落在卡片边界内，不能因 padding、border 或窄窗口向右溢出。

> **2026-10-27 Agent、Skill、品牌字体与记忆图谱（对账 #776）**：桌面版聊天请求遇到不支持 CORS 的中转站时，应直接走应用原生 HTTP，不能再把跨域拦截误报成“地址解析失败”。路由范围先按渠道分组，默认只显示渠道和分组数量，用户展开后才看该渠道的 Key 分组。LibTV 只展示有真实 `SKILL.md` 正文的 704 个可执行技能，不删除原始目录和正文。品牌套件的 Font 必须从字体文件或本机字体库添加，卡片可编辑显示名、重新上传文件、删除套件引用。品牌套件绑定到项目后，每次 Agent 对话及项目内公共文本调用都会读取固定版本：设计指南、颜色、字体名/用途作为提示约束，Logo 与 Reference 图片作为真实视觉输入。Agent/文本规划新建的生成节点会保存本轮套件素材快照，最终生图请求按 Logo 优先直接附图，之后重跑沿用；旧 Agent 节点在当前 Agent 回合也会临时注入。用户手建节点直接点生成仍不会无条件下发字体文件或套件图片，需经过 Agent/文本规划或显式连线。个人记忆提供关系图谱：中心连接偏好、事实、硬约束、已确认决定，类型节点再连接具体记忆；图谱只读，不替代列表编辑。

> **2026-10-27 品牌套件与颜色选择器（对账 #775）**：品牌 / 产品套件按 Lovart 的信息层级展示：顶部是拖拽上传、本机图片与 URL 导入；下面是单一“设计指南”，再按 Logo、Color、Font、Reference 分区添加内容。Logo 与 Reference 直接保存图片；Color 用统一弹层命名和取色；Font 记录字体名、字重或用途。界面不再要求用户填写 `key: value` 结构化事实，但旧套件事实保留且继续进入上下文。项目绑定仍固定明确版本，保存新版本不会自动影响旧项目。画布、节点、套件与电商换色中的自定义颜色统一使用带饱和度/亮度区、色相条、HEX 输入和确认动作的取色器。

> **2026-10-23 无限画布日志抽屉（对账 #718）**：点击日志面板外任意遮罩区域立即收起；点击面板内部不关闭。每条日志的提示词正文最多显示两行，超出用省略号；完整提示词不丢失，点击正文仍复制全文。

> **2026-10-23 生图已扣费却显示超时（对账 #717）**：上游已经完成任务时，不能因为结果图片 URL 下载卡住就把整张图判成生成失败。图片下载应使用更短的独立超时，并通过桌面原生请求或响应里的备用 Base64 继续取图；只有所有产物源都失败时才报错，且必须说明“图片已生成”并给出真实 URL / 原因。POST 生成请求超时不再向壳重发，避免重复扣费。

> **2026-10-23 电商任务向右排列与完成态优先（对账 #716）**：电商工作台每次生成新任务时向右开一列，同一任务内部继续竖向排列；新任务列应避开用户已经移动或拉宽的旧对象。已完成的数据库结果不能被旧的内存生成中状态覆盖，刷新或实时合并后应立刻显示真实产物。

> **2026-10-22 电商结果补账与工作台手势（对账 #715）**：生成已经成功时，结果必须从 RunRecord 自动恢复真实产物，不能因为结果行暂时没有 `assetHash` 就永久显示“素材不存在”或停在生成中。电商工作台的操作与无限画布一致：空白左键拖动平移画布，`Ctrl / ⌘ + 左键拖动`框选，Shift 增选；中键、抓手工具和空格拖动也都可平移。框选碰到对象即可选中。

> **2026-10-22 电商套图以统一代替微操（对账 #714）**：整套图只需要统一视觉风格、排版语言、字体气质与文案体系，具体镜头、景别、背景和构图由模型根据商品与用途创作。提示词不要求百分比、像素、固定网格、字号倍率或统一机位；微距和细节图也不得被通用规则强制成“商品完整可见”。AI 自审负责删掉重复、过量与冲突的约束，修正后的提示词不应更长或更复杂。

> **2026-10-22 对话模型固定清单（对账 #713）**：电商与画布 Agent 的“对话模型”下拉都保持前端固定清单，不按渠道是否可用增加或删除选项。渠道只决定所选名称实际能走哪一条；若没有任何已启用渠道勾选并提供对应的真实 `chat` 模型，应用必须在请求前立即提示去渠道配置，不能把请求发出去等 60 秒超时。提示必须显示在“生成”按钮附近的可视区，不能藏在滚动表单底部。仅有模型映射、但映射目标不属于该渠道的 chat 模型时，不算配置完成。

> **2026-10-21 4K、失败重试与工作台快捷键（对账 #686）**：用户选择 `4K` 后，生成请求必须按模型能力真正下发 4K 像素，不得因 `4K / 4k` 大小写不同静默降成 1K；下载或落库的图片必须保持原始二进制，不能把 PNG / JPEG 当文本转码。电商失败卡提供“重新生成”，点击后立即进入生成中，完成后回到成功结果；电商无限工作台在非文字编辑状态下支持 `Ctrl+Z` 撤销、`Ctrl+Shift+Z` 重做、`Z / 0` 显示全部素材。左侧画布 / 电商 / 漫剧三个一级入口在已有当前项目时，都打开当前项目的对应工作台，不再跳回空项目引导页。刷新或重启电商页时，首屏必须以 RunRecord 对账后的终态显示，不能把已经失败 / 完成的任务继续显示成生成中。

> **2026-10-21 SoonStudio 常驻渠道（对账 #685）**：渠道配置新增 SoonStudio 站点协议，默认地址为 `https://soonstudio.ai`，覆盖对话、生图和视频；内置渠道列表新增一项 SoonStudio，始终置顶且不可删除，用户只需填写自己的密钥并勾选模型。SoonStudio 的 Gemini 模型如果被服务端要求使用 Google 原生格式，应用会自动改用 `/v1beta/models/{id}:generateContent`，不需要用户手写协议字段。需要如实区分两类失败：400 `gemini_native_request_required` 表示请求格式已自动切换；切换后若仍返回 404 “模型未在当前分组配置”，则属于 SoonStudio 账号或分组未开通该模型，不是前端选路错误。

> **2026-10-21 电商出图先分析商品再写最终提示词（对账 #684）**：商品套图、主图、详情页和爆款复刻不再把“套图结构 / 输出张数 / 同批 / 硬约束”等策划文字直接交给生图模型。用户确认生成后，系统先调用所选对话模型读取真实商品图和要求，返回商品外观分析，再为每一张写不同的最终视觉提示词；生成节点只保存这些可直接执行的画面描述。白底图仍是同一提示词多次抽卡，定向编辑仍只执行用户点名修改。复杂商品图如果商品分析或逐张提示词失败，系统会在产生生图费用前停止并给出真实原因。点击生成后，参数栏按钮下方持续显示当前阶段：分析商品原图、整理逐张提示词、创建工作流、生成第 x/N 张、完成或失败；确认框也提前说明会先做商品分析。

> **2026-10-21 电商工作台新批次进入视口、小地图与画布框选（对账 #681–#683）**：新生成批次的底部定位只参考当前可见结果，已隐藏 / 已删除的历史对象不再把新批次推到画布深处；新批次对象出现后，视口自动适配到这批对象，用户不需要再手动寻找占位。电商无限工作台左下角提供小地图，显示当前对象分布、选中对象和视口范围，点击可快速移动视口。工作台支持空白处拖框多选，Shift 追加选中；多选对象可整体拖动，Delete 一次删除选中项，框选与单选共用同一套选择状态。

> **2026-10-21 素材框选、工作台删除与图片参数（对账 #678–#680）**：素材页进入选择模式后，可在内容区空白处按住鼠标拖出选框，框内素材直接进入本次选择；被单张卡遮挡的位置不会误触发框选。电商工作台删除生成图片时，删除的是“这张结果在工作台中的展示”，结果行与运行日志仍保留；记录写入 `hiddenAt` 后刷新、切换批次或继续生成新任务都不会再被自动补回，撤销删除会恢复显示。图片生成参数在电商右侧栏新增“分辨率”，选项与无限画布共用以 `imageParamsFor(model)` 为源的模型能力；GPT Image 另显示“质量”，GPT Image 2 为自动 / 低 / 中 / 高，GPT Image 2.5 为自动 / 低 / 中 / 高 / 超高 / 极致。用户选中的值和参数会一起写入任务 `EcommerceRequest` 与内部生成节点，不再只停留在提示词文本里。

> **2026-10-21 电商失败收口与素材 Delete（对账 #675–#677）**：电商结果与任务必须以 `runRecords` 的每次调用终态为准，不能只看执行宿主的内存节点状态。一次 API 调用失败后，对应工作台节点立即显示真实失败原因并停止转圈；电商日志按每次调用列出状态、模型、渠道、耗时、像素与完整错误，而不是只给整批任务一条摘要。用户在失败卡点「移除记录」后，该结果行和工作台对象必须永久移除，后续运行任何新任务都不得把它带回。素材页的 `Delete / Backspace` 同时支持“普通单击选中一张”和“显式选择模式多选”，两者都先弹二次确认，确认后才从素材页移除记录。

> **2026-10-20 电商工作台本轮修正（对账 #664–#674）**：电商工作台的滚轮行为与无限画布统一为“滚轮直接以指针为锚缩放”，平移只走空格、中键或抓手；点击对象选中，点击空白取消选中。选中对象加载原图，四边手柄拉伸图片本体，四角仍等比缩放。底部不再保留无意义的“网格与吸附”开关，背景点阵只作为画布环境并随缩放变化。生成任务一创建，运行中或失败占位就进入最终纵向位置；每张完成后单独替换，不再在左上角堆状态条，也不等整批结束才落位。上传对象和生成结果都只提供电商自己的下载 / 收藏动作，不再出现任何“在画布中打开”、裁剪、标注、旋转等跨工作台入口。素材页选择模式中，连续点击卡片即可多选，Delete 仍先二次确认。

> **2026-10-20 电商无限工作台（对账 #653–#659）**：电商中央区现在是独立无限工作台，不再按当前功能过滤历史结果。滚轮平移、Ctrl/⌘ + 滚轮缩放；单击图片显示像素尺寸、四角等比手柄、四边自由手柄、下方旋转柄与浮动功能面板。生成结果按任务纵向自动排列，任务间距 96px，后续生成只追加。底部工具栏提供选择、抓手、上传、文字、撤销、重做；右侧电商日志只存在于中央工作台，不覆盖参数区。顶部功能和左侧品类只切换右侧参数，不清空工作台。商品原图可打开大图预览并用方向键切换。未接入的 AI 动作明确禁用。

> **2026-10-20 素材与回收站 Phase 0（对账 #660 / #662）**：素材页提供“选择”模式，支持 Shift 连续范围、Ctrl/Meta 追加、Delete 二次确认与批量移除。移除记录只从素材页隐藏并删除收藏关系，不删除仍被画布引用的资产字节与运行记录；再次收藏同一素材会恢复显示。项目回收站提供复选框、全选、Shift 范围、还原所选、彻底删除所选；批删使用单事务，处理中禁用重复点击，失败时保留未完成项目并如实报错。

> **2026-10-20 画布 Agent 对话模型口径（对账 #663；2026-11-12 #1024 修订）**：画布 Agent 的“对话模型”展示项目级全局前端逻辑名，包括内置名与 `category === 'chat'` 的用户自定义模型；不显示或要求用户选择渠道。图片、视频、对话、音频各自只消费对应分类，同一个自定义模型不得跨分类混入。新增自定义模型时默认继承当前模型映射分类，避免在“对话”页新增却被保存为生图。渠道由后台按全局优先度、实测延迟或均衡权重自动选；同一次用户回合里的确认与自动续跑沿用同一条渠道，下一次发送才重新路由。用户切换模型时只改变逻辑模型，不继承上一条渠道绑定。固定显示名或自定义逻辑名命中渠道映射时，请求必须使用该渠道真实上游 ID。

> **2026-10-20 电商对话模型统一画布口径（对账 #651；2026-11-12 #1024 修订）**：电商里的“方案模型”统一改称“对话模型”。下拉显示项目级全局前端逻辑模型名（内置 + 自定义），但只取 `category === 'chat'` 的条目，不显示渠道名；渠道由后台按全局优先度 / 权重 / 延迟策略自动选择。已选模型的能力分类必须随最新模型目录刷新，生图模型不得因旧缓存或站点错误标签混入对话模型。Comfly `Gemini 3.8 Flash` 的实测结果需区分正常热请求（约 2–3 秒）与上游冷请求偶发超过 150 秒的排队；界面文案不得把上游延迟描述成前端故障。

> **2026-10-20 电商并发与 Comfly 全量模型（对账 #649 / #650）**：一次电商生成 N 张时，N 个请求必须同时发起并同时显示“生成中”，不再出现“排队中 / 等待中”。页面重开发现上次任务没有 live 执行时，未完成项显示“上次生成被中断，请重新生成”，不自动重发。Comfly 的“拉取模型”必须同时读取鉴权模型接口与站点公开模型目录，合并去重后保存全部可用模型，并使用公开目录的类型元数据区分对话、图片、视频与音频；桌面端允许通过壳的原生 HTTP 绕开公开目录的 CORS 限制。

> **状态口径说明**：#647 中“排队显示排队中”的描述已由 #649 作废。当前电商结果卡没有等待态，所有已发起任务直接显示“生成中”。

> **2026-10-20 电商方案模型与生成状态（对账 #647）**：方案模型只排除离线 `mock`，用户自己启用并配置了地址、令牌与对话模型的内置渠道同样可选；列表为空时标题右侧的“渠道配置”可直接进入全局设置，不再让用户猜去哪里补配置。电商结果卡的运行态与画布生成节点保持同一视觉语言：排队显示“排队中”，运行显示呼吸轨道、旋转弧线与递增秒数，失败显示错误图标、失败标题和可读原因；重跑已有结果时，新的运行态优先于旧图，不得继续显示“已完成”。失败原因必须可换行、不得横向溢出，并在减少动态效果时停止动画但保留状态文字。

> **2026-10-20 电商工具独立选项（对账 #646）**：每个顶部工具拥有独立的上架平台、语言、比例和商品要求状态。上架平台固定参考图 19 项顺序；商品套图语言为英文/中文/日文/韩文/西班牙文/俄语/泰语/马来语，爆款复刻语言为英文/中文/日文/韩文/俄语/德语/法语/西班牙语/葡萄牙语/泰语/马来语。A+ 图片比例提供高级A+（Web端）/高级A+（移动端）/普通A+/1:1/4:3/16:9/9:16。所有多选优化项在未选时也必须呈现完整卡面与描边，选中用矢量勾选表示。

> **2026-10-20 电商参数交互（对账 #645 / #647 修正）**：电商工作台不再使用原生 `<select>`。所有下拉统一为 `EcommerceSelect`：浮层脱离滚动容器定位，当前项用主题灰底与勾选表示，模型项带厂商矢量图标，支持点外关闭、Esc 与键盘上下/Home/End/Enter。`方案模型` 排除 `mock` 与当前不可路由的渠道；用户自己启用并配好地址、令牌和对话模型的内置渠道可以出现。全屏右栏默认宽度为 `360px`，窄屏在 `1180px` 以下回落 `320px`。商品套图的“自定义配置”采用启用勾选 + 类型说明 + 数量步进的逐项面板；0 表示该类型不参与生成。右栏滚动条属于滚动容器本身，必须贴面板最右沿（右内距给内容，不给滚动容器）；外观只走全局 4px `::-webkit-scrollbar`，不得用标准 `scrollbar-width/color` 覆盖。

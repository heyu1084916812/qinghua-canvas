### 6.8 图片 / 视频生成节点 · ✅ 已实现

#### 状态 A：空状态

占位框，中间是**上传按钮**；按钮**上方是「上传素材」实色胶囊，下方一行小字说明支持的素材类型**
（用户 2026-09-19：`支持音频、视频、图片素材`）。点击它或拖入文件即可上传，自由缩放，默认与最小尺寸统一为 `240 × 192`；说明文字固定单行，不拆成两排。

**小字为什么必要**：按钮只说了「上传素材」这个**动作**，没说**能传什么**。
用户手里可能是音频、可能是 mp4，猜错就得点一次才发现不收——这行小字把可接受的类型直接摆出来，
省掉一次试错。文案里「音频」排在最前，是因为它最容易被误以为不支持。

实际可传类型以 §6.8「导入链路」与 §11 的媒体判定为准（当前图片 `png/jpg/webp`、视频 `mp4/webm/mov`）；
小字是**面向用户的承诺**，两者必须同步——收了却不说、或说了却不收，都是错的。

导入链路与画布级导入**共用一份实现**（`features/canvas/importAsset.ts`）：读文件 → 指纹入库 → 读图片原始像素 → 建节点。区别只在落点——节点 `+` 是**写回当前节点的 `assetHash`**，画布导入是**新建一个素材节点**。素材节点按原始比例定尺寸（最长边上限 320，再兜到生成节点最小 `240 × 192`），极端长条比例（算完会超过 3 倍上限）退回最小尺寸，避免 2000×40 这类图算出一万多像素宽。

| 入口 | 落点 | 说明 |
| --- | --- | --- |
| 节点「上传素材」按钮 | 当前节点 | 只在**无上游素材**时可用；有上游时不显示该按钮 |
| 画布工具条「导入素材」 | 视口中心 | 新建节点并选中 |
| 拖文件到画布空白 | 拖放位置 | 多文件横向排开，一次撤销 |

#### 新建节点的默认渠道 / 模型 / 参数（2026-09-18 定稿：**按渠道记忆 + 面板兜底**）

新建生成 / 批量 / 提示词节点时，默认值**不是空的**。这条规则解决一个每天都在踩的坑：
新建节点的渠道 / 模型默认是空，每建一个都要重选一次；而一个项目通常固定用同一套。

**取值分两种情形**：

| 情形 | 默认值来源 |
| --- | --- |
| **该渠道记过** | 该渠道**上一次生成用的那一套**：模型 + 生成参数 |
| **从没记过** | 渠道配置里**第一个可用渠道 → 它的第一个可用模型**（渠道需已启用） |

**为什么按渠道记忆**（口径对照参考项目「大雄无限画布」）：
大雄把「记住上次设置」按**执行模式**分桶（api 生图 / api 视频 / comfy 文案…），
它必须分桶是因为那几档对应**完全不同的执行引擎**，参数结构不通用。
本项目是**统一走渠道**：一条渠道 = 一个协议 + 一批模型，执行引擎不分叉、参数面板同源。
所以大雄的「模式桶」在本项目里**天然就是渠道这一层**——不需要再额外造一层分类。

**为什么必须补上「面板兜底」**：早期实现只在**新建节点那一刻**算一次默认值，
算不出来（例如渠道已配置但模型只进了 `modelCache`、还没勾选）就写空，且面板侧没有第二道兜底，
于是表现为「明明配好了渠道，新建节点还是空的」——与实测相符。
参考项目的做法是**节点不固化默认值，面板打开时现算**，
解法是保留本项目「创建时写入」的路径，同时在面板侧增加同一条解析链作为兜底，
使「创建那刻算不出」不再等于「永远为空」。

**解析链（单点真源，创建与面板共用）**：

1. 节点自身已有的 `channelId` / `model`
2. 该渠道上次记录（模型失效则回落到该渠道第一个可用模型）
3. 第一个可用渠道的第一个可用模型
4. 都没有 → 留空（用户自己配）

**兜底的边界（只在节点模型为空时生效）**：面板兜底**不覆盖节点已有的模型**——
哪怕它不属于当前类别。节点上已有值是用户自己的状态（或类别切换后的刻意为空），
面板是纯视图，拿解析链去填它等于跟用户抢所有权。具体后果：切「图片 → 视频」时，
若兜底去填新类别的模型，那次清空会立刻被填回，用户看着像切换没生效。

**判「该不该清」用的是节点自己的值**：类别切换要不要清空模型，判据是
节点上存的 `model` 是否属于新类别，而不是面板当前显示的模型——后者可能正是兜底值，
拿它判会永远判成「属于」，于是永远清不掉。

**记录时机 = 用户改了参数的那一刻**（2026-09-23 修订，推翻原口径）。

原口径是「生成成功那一刻才记」，理由是「选了却没生成的那次不该影响默认值」。
用户实测后明确否掉：

> 「只要我改了参数，他也给我记住……后面每次新建的节点参数就来自于上个新建节点时候的参数。」

也就是把「记配方」从**生成行为的副产品**改成**编辑行为的直接结果**：改了就算数，不必先跑一次生成。
规则收成两条：

1. **项目第一次用**：默认取渠道配置的第一个可用渠道的第一个可用模型（没有记录时的兜底）。
2. **此后每次**：谁改了参数，就把那套记下来；下一个新建节点直接继承它。

配套实现：`isRecipeEdit`（`domain/project/generationPreset`）是「哪些改动算改了配方」的**唯一判据**；
`PanelLayer` 在参数类事件里就地写回，`CanvasPage` 新建节点时把落进节点的那套值也记一遍，
让「新建 → 改参数 → 再新建」这条链闭合。

**记哪些参数**：

| 组 | 字段 |
| --- | --- |
| 图片 | 比例 / 画质 / 质量 / 数量 |
| 视频 | 尺寸 / 时长 / 参考模式 |

**不记**：提示词、素材、上游连线——那些是**这一张图的内容**，不该继承给下一个节点
（把上一句提示词带进新节点，用户得先删掉再写，反而是负担）。

**提示词节点**同样享受默认值，只是取**文本类模型**：走同一条解析链，但每一步都按
`chat` 类别过滤；记录里的图片模型不适用于文本节点，故自然跳过、落到「第一个渠道的第一个文本模型」。

**失效处理**：记录里的渠道被删 / 模型被取消勾选 → 自动改用该渠道第一个可用模型；
渠道整个没了 → 退回「第一个可用渠道」；一个可用的都没有 → 留空（用户自己配）。
**解析失败必须可诊断**（不静默）：解析不到任何可用渠道 / 模型时，面板给出「还没配置渠道」或
「该渠道还没勾选模型」的**可点击解释**，而不是留一个空下拉让用户猜。

| 规则 | 说明 |
| --- | --- |
| 基准尺寸 | 桌面端**宽度 840px（保持长度不变）**、**高度固定 360px**，二者之比即 **21:9**（用户 2026-09-19）。宽度是「长度」、不随内容伸缩；多出来的纵向空间由提示词区吸收（素材行与参数行是固定高度），面板底部不留死白 |

**第一部分 — 上游素材**：上游链接图片（小眼睛）+ 节点自身内容（可操作），均可拖动排序。编号角标固定在缩略图左边（显性），小眼睛 / 素材操作按钮隐性。无上游且无内容时显示占位框与中间 `+`。右上角为图片 / 视频功能类别切换（显性边框）。

**节点自身素材的操作（2026-09-18 定稿：落在节点本体上）**

入口在**节点本体那张图的右上角**（不是创作面板的缩略图）——本体才是「这张图属于谁」最直观的对象，换图 / 清图在这里做最顺手。选中节点时才出现（未选中时画布只有内容，不被工具打扰）。

**保存动作只放在生成节点右键菜单**（用户 2026-09-29 定稿）；只在节点确实持有素材时列出「保存到素材库」，避免空节点出现点了没反应的死项。节点右上角菜单继续只负责清空 / 替换。

| 元素 | 行为 |
| --- | --- |
| 圆形实色按钮 | 走项目强调色（`--accent`，与画布工具条主按钮同一套）；hover 出气泡「替换素材」 |
| 菜单「保存到素材库」 | 把当前节点素材主动收藏到 `/assets`；保存当时冻结提示词、模型、比例、画质、渠道与像素信息。之后改节点不回写收藏；同 hash 重复保存只更新同一条收藏 |
| 菜单「清除」 | 清掉这张素材，节点回到空态（本体露出占位框 + 上传按钮）。**媒体本体留在 `assets` 表不动**——它是内容寻址的，别的节点可能还引用同一张图 |
| 菜单「替换」 | 调起文件选择器换一张。与「上传」走同一条路（取文件 → 算哈希 → 落库 → 写回），所以两者的行为永远一致，不会各写一份而分叉 |

菜单形态照参考设计（图标 + 文案、圆角、实底），**配色用本项目 token**：1px 描边 + `--radius-control` 圆角 + 无投影，与 ParamPicker 同属「画布工作区浮层」。

**删除角标（2026-09-21 改）**：**每一张缩略图**的右上角顶点有一个红色 `✕`——中心**骑在角顶点上**（与左上编号角标同一套「骑角」几何），默认隐藏、悬停显形。点击后按来源分两种动作：

| 来源 | 点击行为 | 理由 |
| --- | --- | --- |
| **自身素材** | 清空本节点的素材，节点回到「没上传图片」状态 | 图是节点自己的内容 |
| **上游素材** | **删掉那条连线**，上游节点与其素材都保留 | 上游的图不属于本节点——改它的数据等于越权删别人的内容；「这条素材不再进来」的正确表达就是删连线 |

两个动作都进撤销栈，误删可撤回。

> 早先 §6.6 只允许删自身素材（上游只能小眼睛隐藏），理由是「删上游素材语义模糊」。
> 用户把语义定死后两类都能有明确的删除动作。

> 位置教训（连错两版）：① 放进创作面板的缩略图——那是另一个地方；
> ② 靠 `hover` 才浮现——用户根本不知道要悬停；③ 塞进 30×30 的缩略图内部，
> 被压成 8×8 的一个点（实测 boundingBox）。**入口要放在用户会去找的地方，且看得见。**

首行排版（§6.8）：**素材条在左、「图片 / 视频」功能类别切换在右，同一行**（行高 60px，两者垂直居中）。空态时左边是「拖入素材」虚线空态框（吃掉首行剩余宽度，文字居中）；有素材时左边是缩略图条——缩略图为 **40×40 方块**（2026-09-21 由 60 缩小），集合卡（§6.12）收窄为同高的横向小胶囊（数量 + 「集合/素材」两行小字）；素材多时在条内换行，切换保持垂直居中、始终贴最右。

> **缩略图几何三条**（用户 2026-09-21）：
> ① **尺寸 40px**：`--thumb-size` 与首行高度 `--assets-row-h` **拆成两个变量**，缩略图可单独调；
> ② **圆角与外框同心**：外层 `.thumb` 8px 只负责定位与「允许子元素探出」，内层 `.thumbFrame`
>   取 `8 − 1 = 7px`（减去 1px 描边）并 `overflow:hidden` 负责裁切——与 §3.2 的
>   `--radius-node-inner` 同一条口径，否则角上会出现两条不同弧；
> ③ **编号角标移到左上角外沿**（`-18px`）：原先贴在容器内 (1,1)，数字直接压在素材上。
>
> ⚠️ ②③ 是**同一个根因**：圆角裁图要 `overflow:hidden`，而右上角素材按钮与角标要「探出边框」
> 需要 `overflow:visible`。放在同一个盒子上只能二选一——旧版选了 visible，于是**图片变成方的**、
> 角标也只能待在容器内压住素材。现在把裁切下沉到内层，外层保持 visible，两个需求各得其所。

> **素材行与参数行是固定内容**，不允许被 flex 压缩（`flex: 0 0 auto`）——面板钉死 360px，
> 若它们可收缩，尺寸调整会被 `flex-shrink` 悄悄抵消。可伸缩的只有中间的提示词区。

**参数 chip 的形态（2026-09-19 定稿）**

| 规则 | 说明 |
| --- | --- |
| 无箭头 | chip 上**不画下拉箭头**，点击即弹出参数面板（弹层本身就是「可展开」的说明） |
| 文字更大 | chip 文案从 11px 提到 **13px**（与正文同级）——它是面板里被反复读写的主要信息，不该小于正文 |
| 张数也是 chip | 张数**不再是一排固定按钮**，与画质 / 质量同形（横排胶囊弹层），四项为 1 / 2 / 4 / 9 张 |
| **四样收成一枚胶囊**（2026-10-02） | 图片模式下，**比例 / 画质 / 质量 / 张数不再各占一枚 chip**，而是并成**一枚**：chip 上是四段串成的一行摘要（「1:1 · 1K · 中 · 1 张」），点开是**一个多段参数面板**（比例用图形化网格、其余三段用横排胶囊）。用户 2026-10-02 给的参考产品就是这么做的：「把比例，质量，画质，张数变成一个胶囊显示，而且点击显示的面板……把所有的参数都放上去，用我现在有的参数」。四段的名字与档位表**一点没改**（`ratio` / `resolution` / `quality` / `count`），只是从「四枚 chip」变成「一枚 chip 里的四段」；选完**不关**（一次调两三样是常态）。视频模式仍是各自一枚 + 尺寸 / 时长 / 参考模式 |

**张数上限的两处口径必须一致（2026-09-19 修）**：模型**未声明** `maxCount` = 不设限，
可选项取满四项；**只有模型明确上报更小的上限**时才置灰够不到的档位。
此前面板层已按这条改对，但 `clampCount`（领域层，渠道适配器也在用）仍是 `maxCount ?? 1`——
于是面板能选 9 张、请求发出去却被夹回 1 张，表现为「选了 9 张实际只出 1 张」。
**两处口径不一致是一种静默失败**：界面显示成功、结果不对，故必须由同一条语义锁定。

**第二部分 — 提示词**：输入区无框。上游连了提示词节点时不自动带入文本，只多一个胶囊容器「上游已链接提示词节点 {变量数字}」，提示词框仍可手动输入。

**提示词框里的 `@` 引用（用户 2026-10-05 第 15 条）**

提示词框是**带引用的富文本框**：打 `@`（或点这一行右上那枚 `@` 按钮）会列出**本节点上游**的图片 / 视频素材，选中后落成一颗**小框 = 素材缩略图 + 省略的名字**，它是这句话文本的一部分（与对话窗里 @ 画布节点同一套 `MentionEditor`）。

范围**只有本节点的直接上游**（候选 = 上游里带 `assetHash` 的节点）。对话窗那个 @ 是「整张画布」，这里是「这次要拿哪张参考图」，两者不要混。没有画面的上游（提示词节点、批量集合卡）不进候选：引用出来只能是个空框。上游节点没标题的也不进候选 —— 下面那条「存储里只有纯文本」需要名字才能还原。

> **存储里只留纯文本 `@名字`**（这条是地基，改之前先读）。`data.prompt` / `data.text` 不只是输入框里的字：它**直接就是发给模型的提示词**，还被下游节点读、被反推 / 优化 / 翻译读、被节点本体正文渲染。夹带 `@[名字](node:id)` 这种给机器看的形态，就会顺着这些路漏进请求里。
>
> 所以引用形态只活在编辑器那一层：打开面板时把纯文本展开成引用框（`expandMentions`），用户一改就把引用形态还原成 `@名字` 存回去（`collapseMentions`），两个方向都在 `text/mentionValue.ts` 一处实现。
>
> **代价（有意）**：引用的**节点 id 不进存储**，所以节点改名 / 断线之后那颗小框会退回普通文字 `@旧名字`。字不会丢，只是不再是一个引用框 —— 拿这个换「提示词永远是干净的纯文本」，划算。

**第三部分 — 参数与生成**（随功能类别变化）

图片模式：

```
[生图模型 ▾] [1:1 · 1K · 中 · 1 张 ▾]      [↑]
```

> 那一枚「1:1 · 1K · 中 · 1 张」就是上面说的**生成参数胶囊**：四段一行读完，
> 想改哪一段点开改哪一段。判据在冒烟 G46：点开后必须能看到
> `quality,resolution,background,ratio,count` 五段（「背景」那段由模型能力表决定，
> 见 §11），且面板上**不再有**单独的比例 chip。

| 选中 | 行为 |
| --- | --- |
| 「跟随素材」 | 出图比例 = **参考图 1** 的原始比例（不裁剪、不统一） |

**语义定稿：跟随「参考图 1」**（2026-09-24）。判据是**第一张参考图**，
不是「随便找一张有尺寸信息的」——

- **批量场景**：集合展开后每次调用只带一项素材，「参考图 1」天然就是那一次的那张，
  于是多张不同比例各自自适应（这正是它当初的用途）；
- **普通图生图一次带多张参考图**：必须有确定的含义 ——
  「参考图 1」是用户能看见（面板缩略图第 1 张）、也能靠拖动排序控制的那张；
- 参考图 1 **没有尺寸信息**（老数据 / 未解码）时**如实不指定比例**，
  **不许**跳到参考图 2 —— 那不叫跟随，叫偷换。

> **「参考图 1」= 请求里实际发出的第一张图**（2026-10-17 / 对账 #556）。
> 这句话以前只是注释，实现上踩过两个坑，两个都必须记住：
>
> 1. **节点自带的图被注入请求时，必须连 `naturalSize` 一起带上。** 画布在
>    「上游一张图都没有、但节点自己有一张」时会把它作为参考图补进请求
>    （`buildRunPlan` 的 `withSourceImage`）——这是**局部图 / 裁剪图唯一的进图通道**，
>    因为它们是**浮动节点**（「提取选区」只建节点、不建边），没有上游可收集。
>    漏了尺寸 ⇒ 这一档退化成"不指定比例" ⇒ 模型按自己的默认比例出图（多半 1:1）。
> 2. **解析「跟随素材」要在"真正发出去的那份 inputs"里找参考图**，不能在上游收集的那份里找 ——
>    上面那种情况下两者**不是同一个数组**，于是"图明明在请求里、却找不到它的尺寸"。
>
> 这两条合起来的后果不是"比例差一点"：它让「提取选区 → 生成改图 → 融合」这条主链路
> 每一步都对不上，最后卡在融合的**比例校验**上，而提示只说得出一句"比例不一致"。

#### 融合拒绝时，「为什么」必须量着图说（2026-10-17 / 对账 #557）

一句写死原因的提示会把用户带到错的方向。原句是
「第 N 张局部图没有选区上下文（用「裁剪」得到的不带上下文，融不回去）」——
**它把原因断言成了裁剪**，而真实原因至少三种，全都写在图上：

| 图上实际是什么样 | 该说的话 |
| --- | --- |
| 这张补丁**自己标着完整图边界**（「裁剪」得到的、或融合产物） | 它自己是完整图边界，不会继承任何选区 —— 请在**原图**上重新用「提取选区」 |
| 这张补丁**没有上游** | 它没有上游 —— 请把「提取选区」得到的那张局部图连到它上面 |
| 有上游，但**不是那张局部图**（例如接的是原图） | 它的上游是「×××」，里面没有「提取选区」得到的局部图 —— 请把上游改成那张图 |

这三句由 `domain/canvas/fusion/cropContext.ts` 的 `missingContextReason` **量着图**算出来，
**执行侧与视图侧共用同一句**：点「开始融合」被拒时是 toast（并落进日志，对账 #554），
按钮被禁用时是 tooltip（视图层经 `InputPortAsset.missingContextReason` 把同一句话带过去）。

> **纪律**：错误提示**只描述观测到的事实，不断言原因**。写死原因的那种句子，在
> "用户的操作和提示里写的不一样"时会把他引向一个不存在的 bug（本条就是这么来的）。

名字取「跟随素材」而不是「适应素材」——「适应」容易被读成「裁剪来适配」，
而这里的语义恰恰是**不裁剪、按素材原本的比例出图**。

> **为什么从「批量专属」放开**（2026-09-24）：真正的用法是「批量当上游 →
> 下游生成节点」，而用户是**在下游生成节点面板**改比例的 —— 那一档却只在
> 批量节点自己的面板里。于是这个能力在实际主路径上够不着。
> 放开后的判据是「有没有参考图」，不再看节点类型。

**通用规则**

| 元素 | 规则 |
| --- | --- |
| 参数触发器（chip） | 圆角 10px、高 38px、padding `0 10px`、字号 11px / 字重 600、颜色 `--text-1`、透明底；hover / focus / is-open 时浮现 `var(--bg-hover)`；`V` 形 chevron 展开时旋转 180° |
| 参数选择面板 | 浮在 chip 正上方（顶部空间不足时翻转到下方）；`width: max-content`；`1px solid var(--stroke)` 边框 + 10px 圆角 + 无投影。**内距 12px、段间距 12px**（用户 2026-10-03：「太挤了，距边界的位置要适合」）；**字号分层**：段标题 12px / 弱色，档位与比例数字 15px / 14px —— 两者原先同为 12px，谁主谁次只能靠猜。竖版列表每行 46px；横排胶囊圆角 999px、内边距 `0 14px`、flex-wrap、水平居中于所点参数。同一时刻只允许一个面板打开，开新关旧；`Esc` / 点击面板外 / 点击其他 chip 关闭。**滚轮归浮层**：选项装不下时它自己滚，**不许穿到底下的画布去缩放**（见下条） |
| 参数浮层高度 | **按锚点剩余空间算，不在 CSS 里写死**（用户 2026-10-03：「参数面板里面的内容能完全显示吗？我不想要内容超出边界」）。原先写死 `max-height: 420px`，13 档比例网格本身就有 5 行 ⇒ 后几行**在边框内被切掉**，用户看到的是「选项到一半就没了」。现在 `ParamPicker` 在绘制前量一次：可用高度 =（上方或下方更宽裕的那侧 − 6px 贴边 − 12px 视口留白），换算成浮层自己的单位后挂成内联 `max-height`。于是 **装得下 → `scrollHeight === clientHeight`（完整显示）**；**装不下 → 在边框内滚**（滚动容器就是浮层本身，`overscroll-behavior: contain`）。⚠️ 单位同样要小心：浮层住在挂着 `zoom` 的创作面板里，量出来的矩形是屏幕像素、`max-height` 要的是面板内部单位 —— 缩放比由「chip 的屏幕高 ÷ 它的 offsetHeight」当场量出来，不复制常量 |
| 参数浮层的**宽度与分段对齐** | 多段浮层的内容宽度固定为 **316px**（= 4 档比例 × 73 + 3 条 8px 缝），上限 342 边框盒。三条互相咬合的规则：① **比例一排 4 个**（用户 2026-10-03：「把比例替换成 4 个比例一排，当前是三个」）—— 13 档排成 4/4/4/1 四行，比原来的五行矮一整行；② **每一段都撑满内容宽度**（`width: 100%`），于是画质 / 清晰度 / 背景 / 比例 / 数量的**左右边距逐段完全一致**（用户：「三个部分的参数和面板左右的边距要一样」）；③ 胶囊按行 **`flex-grow` 平分**，每行都从同样的左内距铺到同样的右内距（否则画质那 5 枚会折成「3 + 2」，两行右边缘一长一短）|
| 参数浮层**不出横向滚动条** | 用户 2026-10-03：「面板还是有左右的滚轮」。根因是 CSS 规范的一条暗礁：**`overflow-y: auto` 且另一轴是 `visible` 时，那一轴会被算成 `auto`** —— 于是内容比内容盒宽一点点（实测多 15px）就冒出一条横向滚动条。两处一起修：内容侧让每一段都撑满内容宽度（上面那条），浮层侧显式 `overflow-x: hidden`，把「左右不可滚」变成一条不随内容漂移的硬约束 |
| 滚轮归属 | **可滚动区域优先于画布缩放**（用户 2026-10-03：「面板如果有多余的地方的话用滚轮无法下拉，而是缩放画布了」）。画布的滚轮监听器原先无条件 `preventDefault()`，恰好取消了「滚到最近的滚动容器」这个默认行为 —— 于是浮层里放不下的选项一个都滚不动、画布反倒缩放了。现在按祖先链判定：**链上有一处真能滚**（`overflow-y: auto/scroll` 且内容超出）就把滚轮让给它；参数浮层这类**菜单**另用 `data-wheel-owner` 声明「我吃滚轮」，哪怕当前没得滚也不把事件穿给画布。滚动容器一律 `overscroll-behavior: contain`，滚到头不再往外串 |
| 面板高度与视口 | 面板挂在节点下方，可用高度 = 视口高 − 锚点位置 − 底部留白（由 `PanelLayer` 算好，见 `--panel-available-h`）。⚠️ 两个坑都踩过：① `min-height` **不能**写成无条件的 360px —— 可用高度比它小时面板照样长到 360px，**底部那一行（参数 + 生成按钮）被顶出屏幕**，用户既看不到也点不到；现在取 `min(360px, 可用高度)`。② 这个变量是**屏幕像素**，而面板挂着 `zoom`、内部长度单位都被缩小 —— 必须换算成面板内部单位再挂上去（`PanelLayer` 的 `PANEL_ZOOM`，同一份值通过 `--panel-zoom` 回传给 CSS），否则给 256px 只渲染成 192px、白丢三成空间 |
| 视频参数（比例 / 尺寸 / 参考模式） | 竖版列表选择器 |
| 图片参数（画质 / 质量 / 数量） | 横排胶囊选择器，紧贴参数行排列 |
| 参数间距 | 底部参数行 `gap` 8px，列间隙 10px |
| 参数项 | 随模型能力动态渲染，模型不支持的项直接隐藏 |
| 功能类别切换 | 「图片 / 视频」是**同一个生成节点**的 `mode`，不是两种节点（模板「图生视频」即 `mode:'video'`）。切换时若当前模型不属于新类别则清空模型（由面板判定——它持有模型列表，装配层照做）；分组 / 批量共用本面板但不给切换 |
| 生成按钮 | 圆形 38 × 38，实色填充 `--accent` + ArrowUp 图标，无边框，高度与参数行齐平；本节点运行时变 `X`（取消）。**并发已打开：其他节点在跑不再禁用本节点的生成按钮**——各节点的运行互不阻塞，可同时提交多条计划；按钮禁用只与本节点自己的运行状态有关 |

#### 生成行为

| 条件 | 结果落位 |
| --- | --- |
| N = 1（默认） | 结果落到**一个承载节点**：源节点自己是空槽就落在它身上（并按产物真实比例调整尺寸），否则在其右侧新建一个（命名 `原节点名的输出N`） |
| N ≥ 2 | 在原节点右侧并列新建 **N 个承载节点**（命名 `原节点名的输出1..N`），N 张图各落一个，每个都按产物真实比例调整尺寸；**原节点与其已有的旧结果都不动** —— 用户要的是「出一份新的、旧的留着对比」 |
| 批量 / 分组运行 | 每次执行各自的产物**铺并列承载节点并挂进容器内**（即便该次只出 1 张），保持容器内外的连线边界一致 |
| 用户选择「替换本节点内容」且 N = 1 | 用户主动确认后用结果替换本节点内容，替换可撤销 |

> **产出永远落在空槽上**（2026-09-16 用户口径，详见 §6.19.3）：生成节点**自身为空**时它就是空槽，结果落在它身上（首次文生图即此情形）；它**已有素材**时，本体是**输入 / 参考**而不再是槽位——此时复用下游现成的空生成节点，没有空槽才**新建承载节点**（命名「原节点名的输出N」），与旧节点并列、不覆盖也不挪动旧的。

**产物尺寸跟着产物走（§6.16）**：写回时把产物真实像素记在节点上（`naturalSize`），承载节点直接按它定尺寸。（~~进结果组的产物统一用组内格位 200 × 200~~ 已随结果组下线，2026-09-17。）

点击生成后，对应数量的承载节点与来源连线在 100ms 内先行出现并显示排队 / 生成中状态；模型响应返回后在节点内回填内容。

生成失败时在节点中心显示报错原因，仅展示，不影响重试与再次生成；再次生成成功时报错自动消失。

### 6.10 对比节点 · ✅ 已实现

- 输入：接收上游图片，取前 2 张做 A/B 对比；超过 2 张取前两张并弱提示
- **上游是「跑 N 张」的生成节点时，取其 N 个承载节点取前 2 张**：N 张结果各占一个
  并列承载节点（§6.19.3），只按节点自身 `assetHash` 读会让批量出图 → 对比永远只有 A 没有 B。
  取图仅限对比节点（生成节点的上游缩略图仍按「每个上游 1 张」，避免面板显示与实际请求口径割裂）
- 展示：两张图叠放，中间一条可竖向拖动的分割线
- 分割线：1px 白线 + 中央圆形手柄，拖动热区覆盖整条线
- 最小尺寸 `240 × 192`，按内容比例锁定；与生成、批量节点共用同一默认尺寸
- 空态中央显示「拖入两张图片素材」与「左右叠放对比，拖动分割线查看细节」，与批量节点的空态信息层级一致

### 6.11 分组节点 · ✅ 已实现

分组节点相当于一个生成节点：把内部收纳的素材打包起来，作为一次请求的输入。

| 内部收纳物 | 在分组中扮演的角色 |
| --- | --- |
| 图片 / 视频素材 | 素材（本次生成的输入图） |
| 提示词节点 | 提示词（本次生成的提示词） |

| 规则 | 说明 |
| --- | --- |
| 拖入 / 拖出 | 自由拖入拖出，按 3 × 3 行优先网格重新排列，节点间保留 16px 间距且不重叠；进入或离开分组时清理该节点的全部旧连线 |
| 内部拖动 | 直接拖动内部节点改变顺序，位置由排序吸附决定；缩略图排序与节点顺序双向同步 |
| 端点与面板 | 组内节点**端点隐藏**、屏蔽自带创作面板（提示词节点只保留文本输入）；**同一个容器内**的子节点之间不渲染连线（这类边建不出来，见下） |
| 对外连接 | **组的右端点拉出来 = 组内每个成员各连一条到目标**（用户 2026-10-06 第 13 批第 5 条：「拉端点后是把组内的下游都拉一条线出来，就和多选节点的拉线功能一样」）。落边时容器**自己不出边**（组不做生成、没有产物），连的是它的成员 —— 展开在 `useEdgeDrag.expandContainers`，拖拽过程中每个成员各画一条草稿线。⚠️ 这类边（一端是容器子节点）**RF 画不出来**（子节点不是 RF 节点，RF 按 id 找不到端点、边会静默消失）⇒ 由 `FlowChildEdgeLayer` 用屏幕空间 SVG 补画（`data-child-edge`）；`canConnect` 的规则 4 也据此**放宽**：子节点**可以对外**连，只有"同一个容器内的两个子节点之间"仍然不连 |
| 尺寸 | **贴住内容**（2026-10-06 第 13 批第 7 条）：尺寸 = 内容包围盒 + **四边等距 20px**（空容器 `240 × 192`），不再归一 5:4；子节点增删时容器跟着收放，「装得下就不动」——手工拖大的框与打组的包装框都留住。向内拖缩放手柄时停在"内容 + 四边留白"上 ⇒ **不会遮住子节点** |
| 缩放手柄 | **四角可缩放**（用户 2026-10-06 第 13 批第 5 条，参考图二）：`se` / `sw` / `ne` / `nw` 各一只，**对角固定、被拖的那角跟手**（`freeResize`，四角通用）；点哪一角都能点到（`data-node-resize-corner`）。其它节点类型仍只有右下那一只（比例锁 / 高度归内容的节点只按右下角推导，多给角会给出没验证过的矩形） |
| 标题 | 浮在节点框外左上方（§6.6 通用规则），**常显**（不是 hover 才出现） |
| 组的动作栏 | 组选中时的跟随栏**不是**生成节点那套（用户 2026-10-06：「就不是把他当成生成节点了」），而是五件事：**背景色**（六档，默认 `slate`）/ **整理节点** / **整组执行** / **解组** / **下载**。逐条口径：**整理节点** = 把组框贴回「内容 + 四边等距 20px」——组内位置本来就由 3×3 网格自动整理（用户 2026-10-06 答复：「容器内不做吸附 —— 容器本身有自动整理」），而容器内**不建边** ⇒ 没有依赖可排；**整组执行** = 把组内节点裁成子图后交给与普通生成相同的 `buildRunPlan`，先过滤无提示词 / 无可用上游的生成节点，再按拓扑顺序运行（组自己不出图，一个都跑不了时如实提示）；**解组** = 子节点**原地**放回世界层（按网格格位算世界坐标与尺寸，看起来还在原处）+ 删掉组，**一步撤销**；**下载** = 组内每个带素材的节点各下一份（组自身没有产物）。⚠️ 因此栏里**没有**「生成 / 渠道设置」，也不重复摆「重命名 / 复制 / 删除」（那三件在组的右键菜单里各有一份） |
| 边框 / 背景 | **常显背景**（用户 2026-10-06 第 13 批第 5 条：「打组后要有个背景」「背景色给六档」）：默认档 `slate`，可选 **六档** = slate / blue / green / amber / rose / violet —— 色值按明暗两套写在 `ui/tokens.css` 的 `--group-bg-*`，组件侧只认档位名（`data-container-bg`）。虚线边框仍只在 hover / 选中时显形 |

**容器布局（单元固定 5:4）**

- 内部每个节点放入统一 `200 × 160`（5:4）比例单元，图片 / 视频在单元内 `object-fit: cover` 铺满，允许裁切单元边缘；提示词在单元内保持可编辑文本，不拉伸
- 单元按 3 × 3 行优先排列（先填满横排，再换下一行），间距 16px；排序只改变单元顺序
- 内部单元固定 `200 × 160`（5:4）；外部容器尺寸 = 列数 / 行数 × 单元 + `16px` 间距 + **四边 20px 内边距**（2026-10-06 起不再归一为 5:4 —— 那会把两个单元的容器撑成 456×365、下方空 183px）。向内拖动缩放手柄时停在该尺寸上（四边留白相等，再拖就会遮住子节点）
- 拖出容器后恢复为独立节点的尺寸、世界坐标与内容比例；拖动全程不显示创作面板
- 分组节点本体只保留固定比例容器与内部节点，素材增删、隐藏、排序从创作面板完成

**创作参数面板**：**没有**（2026-10-06 第 13 批第 5 条：组不做生成 ⇒ 面板没有存在意义）。组的操作全在它自己的功能栏上（背景色 / 整理节点 / 整组执行 / 解组 / 下载）；「组内素材是否参与本次生成」随生成语义一起下线（想让某个成员不吃上游，就别连它）。

## 4. 通用交互

### 4.1 右键菜单 · 🧩 部分实现

菜单在鼠标位置右下角弹出（偏移 4px），是圆角矩形浮层。菜单始终完整落在画布可视区内：下方空间不足时整体上移使下边缘贴近画布底边，右侧空间不足时右边缘贴近画布右边缘，左侧同理。从菜单新建的节点落位在鼠标处。

| 右键对象 | 菜单项 |
| --- | --- |
| 通用节点 | 复制 / 重命名 / 版本历史 / 禁用 / 删除 |
| 生成节点 | 生成 / 版本历史 / 复制 / 重命名 / 禁用 / 删除 |
| 批量节点 | 生成 / 版本历史 / 复制 / 重命名 / 禁用 / 删除 |
| 提示词节点 | 改写提示词 / 全屏编辑 / 版本历史 / 复制 / 重命名 / 禁用 / 删除 |
| 画布空白 | 新建节点（全部类型）/ 粘贴 / 重置视图 |
**菜单分组约定**：运行类（生成 / 改写提示词）集中在最上方，编辑类（复制 / 重命名 / 全屏编辑）居中，历史与结构类（版本历史）放其后，危险操作（删除）单独一组置于底部，以分隔线区分。

> 只列「禁用」或「启用」，禁用节点带「已禁用」徽标、不进执行计划、已有产物仍可作只读上游，
> 面板写明「本次不会运行，下游会使用这张缓存结果」；**「改写提示词」仍未落地**
> （账本 #11）；后者代码里**刻意不列** —— "列出点了没反应的死项比不列更糟"
> （`domain/canvas/menu/contextMenu.ts` 顶部注释原文）。
>
> **今天真实的菜单**（同一份纯函数，有单测与冒烟钉着）：
> - **节点**：`生成`（仅可运行类型：生成 / 批量 / 循环，后接分隔线）→ `保存到素材库`（生成节点**有产物**时）
>   → `提取选区`（**有素材**时，生成与融合节点都有）→ `复制` → `全屏编辑`（**仅提示词节点**）
>   → `重命名` → `禁用 / 启用`（后接分隔线）→ `删除`；
>   （2026-10-17 / 对账 #553 起，`提取选区` 后面紧跟一项 `裁剪` —— 同条件出现、语义不同，
>   见 §6.23「裁剪」。）
> - **画布空白**：`新建节点`（全部类型）/ `粘贴`（剪贴板非空时）/ `从素材文件夹加载`（选了素材目录时）/ `重置视图`。
> - 菜单项**随条件增减**是刻意的：只列当下真能做的那几件（与 `hasRunnableDownstream` 同一条口径）。
> - **每一项都带内联 SVG 图标**（2026-10-16 / 对账 #550）：图标按菜单项 id 在
>   `workbenches/canvas/menu/ContextMenu.tsx` 的 `MENU_ICON` 里登记，组件本体一律取自
>   `workbenches/canvas/toolbar/icons`（与节点功能栏、左侧「＋」菜单**同一份**）。
>   **新增菜单项必须同时登记图标** —— 未登记时渲染处不占位，那一行会空一档
>   （`生成` / `复制` / `重命名` / `删除` 四项就这么漏过一次）。

### 4.2 复制与粘贴 · ✅ 已实现

| 操作 | 行为 |
| --- | --- |
| `Ctrl/Cmd + C` | 复制选中节点及其全部内容 |
| `Ctrl/Cmd + V` | 粘贴，落位在当前鼠标位置 |
| `Ctrl/Cmd + V`（剪贴板里是**图片 / 视频**） | 从**系统剪贴板**导入成新的素材节点（2026-10-16 / 对账 #551）。两个剪贴板是**两条独立的路**：应用内的 `Ctrl+C/V` 走节点快照，系统剪贴板里真有媒体文件时走导入 |
| `Alt` + 拖动节点 | 原地复制出新节点，保留上下游连线 |
| `Ctrl/Cmd` + 空白处拖拽 | 自由框选 |

**剪贴板存的是快照，不是一组 id**（`domain/canvas/clipboard.ts`）：`Ctrl+C` 的那一刻就把节点连内容拍下来，之后与原图再无关系——所以「复制 → 删掉原件 → 粘贴」照样成立，也能跨项目粘贴（素材按 hash 引用，不必搬字节）。

三条口径：

| 事项 | 口径 | 理由 |
| --- | --- | --- |
| 连线的复制范围 | 只复制**两端都在选中集合内**的连线；连到外部的连线不带 | 粘贴是把这段内容搬到别处，接上外部会在原处牵一根长线、且常因成环被拒；`Alt` 拖动是**原地**复制，语义不同，那边才重连（`rewire`） |
| 落点 | 围盒**中心**对齐光标；纯键盘（未动过鼠标）时退回可视区中心 | 对着哪儿按 V 就以哪儿为中心冒出来，比左上角对齐更贴直觉 |
| 文本框内 | `Ctrl+C` / `V` 一律放行给浏览器 | 节点里常驻输入框，用户在那是想复制自己写的字 |

容器连同后代一起复制：顶层归一化到包围盒原点，后代保持 `parentId` 与 local 坐标（跟着父走，单独加偏移会散架）；`childIds` 这类 id 列表字段重映射到新 id，集合外的引用丢弃（与外部连线同口径）。

右键空白菜单的「粘贴」**仅剪贴板非空时列出**（列出点了没反应的死项比不列更糟）。

### 4.3 单击与双击 · 🧩 部分实现

| 操作对象 | 操作 | 行为 |
| --- | --- | --- |
| 节点标题 | 单击 | 进入重命名；点击其他区域确认，`Esc` 取消 |
| 连接线 | 双击 | 删除该连接线 |
| 有素材的节点 | 双击素材 | 进入灯箱 |
| 提示词节点正文 | 双击 | 进入编辑态，自动 focus + 选中全文 |
| 提示词节点正文 | 单击（普通态） | 拖动节点 |
| 提示词节点 | 右键「全屏编辑」 | 打开灯箱编辑 |

### 4.4 保存 · ✅ 已实现

变更后 800ms 防抖写入本机 shared-store，画布提示条显示「已保存」微标，1.5s 后淡出。离开页面前强制 flush。

### 4.5 无障碍 · 🧩 部分实现

| 能力 | 规格 |
| --- | --- |
| 基线 | WCAG 2.2 AA；正文对比度 ≥ 4.5:1，非文本状态与焦点 ≥ 3:1 |
| 焦点 | 可操作控件使用可见的 2px 焦点环，颜色 `--focus-ring` |
| 悬停替代 | hover 才显形的操作在 `:focus-visible`、节点选中与触控模式下同样可见 |
| 拖拽替代 | 节点移动提供方向键微移，排序提供「上移 / 下移」，连线菜单提供「新建并连接」；连到已有节点仍可直接拖到目标节点 |
| 键盘顺序 | 首页按视觉顺序；画布采用 roving tabindex，方向键在临近节点间移动焦点 |
| 动态播报 | 保存、生成、重试、失败、取消与导入完成用 `aria-live` 播报；错误 `role=alert`，状态 `role=status` |
| 触控目标 | 主要控件命中区 ≥ 44 × 44px，视觉图标可小于命中区 |
| 文本缩放 | Windows 文本缩放 200% 时功能完整，面板允许滚动 |

> **2026-10-12 三补记（对账 #448 / #10 状态行）**：上面那句"仍然没做"**已经做掉了，而且不用动系统设置** ——
> WebView2/Chromium 只认**显示缩放（DPI）**，Windows 那个"文本大小"滑块对它不生效，所以
> "200% 能不能用"在工程上等价于 **960×540 逻辑视口**能不能用（1920×1080 @200%）；
> 加上本应用窗口**最小 1024×700**，两档一起量。**三档实测**（首页 / 画布 / 设置各一遍）：
> 1440×900、1024×700、960×540 **横竖溢全是 `false`**，960 那档工作区仍有 **881** 宽、
> 侧栏自动收成图标条、渠道列表与两枚按钮都在可视区内；判据取"**页面级不溢出 + 主要容器不越界**"
> ，**没有**走"每一块都必须塞得下"（§4.5 自己写着"面板允许滚动"）。
> **#10 现在是 3/4**：① aria-live ✅（#444 / #445）② 44×44 ✅ 记例外（#446）③ 200% ✅（#448）
> **④ 仍未做**：`Alt + 方向键` 微移 / `Ctrl + Alt + 方向键` 改尺寸（§4.5「拖拽替代」与 §6.20 现状框里的
> 那两项 —— `useCanvasKeyboard.ts` 的方向键分支目前只管邻近节点切换，没有 `altKey` 分支）。

> **2026-10-12 四补记（对账 #449）**：上面那句"仍未做"**已经做掉了**，`#10` 到此 **4/4**。
> **落地**：`useCanvasKeyboard.ts` 的方向键分支前面加了一档 `altKey` ——
> `Alt + 方向键` = 把**选中的顶层节点**整体微移 **1px**（`Shift` ×10），
> `Ctrl/⌘ + Alt + 方向键` = 改**最后选中那个**顶层节点的尺寸（同样两档步长）。
> 尺寸那条**复用缩放手柄那三条数学**（`freeResize` / `lockedResize` / `aspectLockedResize`，
> 见 `domain/canvas/nodeSpecs/boxKeys.ts`）⇒ 最小尺寸、产物比例锁、高度归内容（循环节点）、
> 批量网格比例四条与拖拽**逐条一致**；到边界**不派发空命令**（否则撤销栈里会攒空操作）。
> ⚠️ 这一档**一律 `preventDefault`**：Chromium 把 `Alt + ←/→` 当**后退 / 前进**，
> 不吞就会把整个应用导航走（而且不报错）。
> **顺带修掉一个既有缺陷**（不是新键带来的）：React Flow 自带的键盘无障碍在"有选中节点"时
> 会自动 focus 它自己的选择框，那个框的 `onKeyDown` 里有**另一套**方向键移动
> （`useMoveSelectedNodes`：每次 **5px**、`Shift` ×4 = 20px，且**不看 Alt / Ctrl**）⇒
> 按一下**普通**方向键（产品口径是"切换选中"）节点就被挪 **5px**；`Alt + →` 实测 **+6px**；
> `Ctrl + Alt + →` 宽度对、位置被挪 5px。修法是给它 `disableKeyboardA11y`
> （本项目的键盘一直是自己那一套：窗口级监听 + 选中集合当 roving focus + 自己的 aria-live）。
> **另一条真缺陷一并修掉**：撤销/重做落库时 `toPersistPlan` 把补丁的**旧值**又叠了回去，
> 于是"内存已退回、库里停在改动后" —— 刷新一次那次撤销就白做（细节见对账 #449）。

> **2026-10-13 补记（对账 #472）：拖拽的最后一条键盘替代也补上了 —— 连接**。
> 本表 3748 行那条「所有拖拽提供可见替代操作」此前**只兑现了一半**：移动/改尺寸早就有
> `Alt + 方向键` 两档，而**连边**只有指针一条路（实测：端点是 `tabIndex=-1`、`Shift+F10` 不开菜单、
> 菜单里也没有"连接"项；`setLinkMenu` 全仓唯一调用方在 `useEdgeDrag` 里）。现在：
> **选中节点按 `L`** ⇒ 打开与拖线**同一个**「可连接菜单」（`LinkMenu`，候选 / 落位 / 连边语义
> 全部复用 `linkMenuSections` + `wireAll`），菜单**把焦点收进去**（方向键移动、`Home/End` 到首末、
> `Esc` 关掉并把焦点**还回原处**）。指针那条路一字未动：不带 `keyboard` 标记时不抢焦点。

## 8. 数据模型

业务主库由本机 `shared-store` 提供：生产默认 SQLite V2，JSON V1 目录库负责旧数据与隔离探针兼容。表以逻辑名统一，由 `StoragePort` 访问；前端不再按 origin 各自维护 IndexedDB 业务库。旧 Dexie 库只作一次迁移来源或回滚备份。

| 表 | 主键 | 内容 |
| --- | --- | --- |
| `projects` | `id` | 项目元数据 + 视口 + `workbench` |
| `nodes` | `id` | `{projectId, type, parentId?, x, y, w, h, title, data}` |
| `edges` | `id` | `{projectId, source, target}` |
| `channels` | `id` | 渠道、协议与模型配置 |
| `tasks` | `id` | 任务日志（持久化，按项目 500 条，超出滚动裁剪） |
| `runRecords` | `id` | 节点版本历史：每次执行的输入快照、输出哈希、指纹、耗时与成本（**永不删除**） |
| `assets` | `hash` | 按内容哈希去重的图片与视频媒体 |
| `assetLibrary` | `hash` | 用户主动收藏关系 + 保存当时的冻结元数据（提示词 / 模型 / 比例 / 画质 / 渠道 / 像素）。取消收藏只删本表行，不动 `assets` 与画布节点 |
| `credentials` | `ref` | WebCrypto `AES-GCM` 加密后的密文与派生盐 |
| `presets` | `id` | **UI 偏好**：生成预设（新建节点默认带上的渠道 + 模型）。与业务数据分开，业务表保持「只有业务」 |
| `customProtocols` | `id` | 用户自建协议（`ProtocolDefinition`，见 §7.3）；与内置目录合并成 `ProtocolCatalog` 供界面、注册表、探测共用 |
| `builtinSkills` | `id` | 随应用内置的技能默认正文；只读，用户修改不写回本表（✅ 2026-10-01） |
| `skills` | `id` | 用户技能：新建、导入、从内置复制而来；功能预设词覆盖值仍走 `presets`（✅ 2026-10-01） |

> **内置技能与用户技能分表**（用户 2026-09-27）：内置技能是系统行为依赖的稳定正文，
> 用户技能是用户内容。分表后，用户编辑 / 删除不会改动功能节点所依赖的内置版本；
> 「恢复默认」只需重新读取内置行或清除用户副本，不存在“把内置行改坏”的路径。
> `presets` 中的功能预设词覆盖值仍按原口径保存，本次只迁 UI 入口。

**产物的 id 一律是内容哈希**（`assets.hash`）：对**产物字节**取 SHA-1 前 16 hex，与用户上传的图同口径（`domain/shared/hash.ts` 的 `fingerprintBytes` / `fingerprintBytesSync`）。

> 为什么必须是内容哈希、不能按请求取（`model|prompt|序号`）：序号在**每一次生成里各自从 0 重新数**，于是「先生成 4 张、再生成 2 张」这两批的 0/1 会撞成同一个 id —— 不同的图共用一个 hash，而灯箱、刷新、去重全都**按 hash 取图**，表现就是「点开是另一张图」「前两张跟后面的一模一样」（用户 2026-09-17 实测）。内容哈希下，字节不同 ⇒ id 必然不同；同一张图重复生成 ⇒ id 稳定（幂等 upsert，不占两份空间）。
>
> 例外：mock 渠道的**视频**产物仍是请求哈希（它的产物是文本假字节，且既有断言依赖该口径）。

`comics` 是**工作台私有表**：画布工作台的表以 `nodes`/`edges` 的图和补丁模型组织，漫画剧的数据是一个树状聚合对象（项目 → 话 → 页 → 分镜），形态未定时不拆表，先整对象存一行，等 comic 形态固化后再决定是否拆列。写库走"防抖 + 整体覆盖"，连续操作合并为一次写；读回用 `hydrate` 整体替换（是读回而非用户操作，不触发回写）。

**comic 聚合对象内部结构（M6-2 v2）**：

- **项目级**：`readingDirection`（`'ltr' | 'rtl'`，默认 LTR）+ `characters`（角色卡库：`{id, name, description, referenceHashes[]}`，跨格复用外观保 AI 生成一致性）。
- **话级**：`ComicEpisode { id, index, title, pages[] }`。
- **页级**：`nodes`/`edges` 之外的另一套结构——版式 = **切割树** `layout`（`LayoutCut` / `LayoutLeaf`），叶子**只持 `panelId`**；格内容另存**内容池** `panels[]`。二者解耦 ⇒ 改版式不动内容、删格不丢内容（可回收）。阅读顺序是**派生量**（`h` 切恒「上→下」，`v` 切在 RTL 下翻转列序），不单独存。
- **格级**：**三层分离**——① `scene`（画面描述，喂生图）② `shot`（镜头语言字段化：景别/机位/转场）③ `balloons`（对白贴纸，格内 **0..1 相对坐标**，**不烘进图**，重生成不丢对白）。④（M6-15）`runs`（**生成留痕**：每次生成的快照与产物指针，只增不减，见 §6.21.1）。

**读回迁移**：模型升级后旧行缺字段，读回时经 `normalizeComicProject` 补齐默认值（**只补不删**，未知字段忽略），不设 `schemaVersion`、不改 Dexie 表结构——等首次出现「有真实数据需要差异化迁移」时再引入版本号。

M5 起 `comic` 以**骨架**形态落地：新建漫画剧项目可创建、可进入其独立工作台页面、可返回首页，共享渠道 / 日志 / 任务运行时等基础设施，但不修改画布工作台任何代码（架构 §5.10）。漫画剧的分镜编辑能力在后续里程碑于该骨架内填充。

M6-0 补齐 comic 的**数据持久化**：M5 骨架阶段 comic 数据是纯内存的（刷新即失）。现在新建一话等私有命令产生的数据会经防抖写入 `comics` 表，刷新页面或从首页重新进入项目都能读回；画布工作台的表与读写路径零改动。

M6-2 把 comic 数据模型升到 **v2**（如上四点），并在 `ComicSurface` 上落**最小可见 UI**：阅读方向切换 + 角色卡「新建/改名/描述/删除」。这两项是 v2 新增的**项目级**字段，与版式/分镜无关，恰好证明「模型升级已被 UI 消费、并端到端持久化往返」。分镜版式编辑器、格编辑、对白层留 M6-3 / M6-4。

M6-3 落地**页版式编辑器**（项目内「话 → 页」下钻 + 直接编辑某页版式）：

- **页的进入**：一话下可加页（`＋ 新建一页`），页以胶囊行选择；选中页后在页面预览区编辑其版式。
- **版式操作**（工具栏驱动，先不做拖拽切割）：空版式时显示「整页排版」按钮，一键实例化为**满页单格**；选中某格后可**横切 / 竖切**（把该格一分为二）、可**删格**（并自动回收只含单子的退化切割）；「清空版式」回**未排版**态。
- **阅读序号印章**：每格左上角显示该格的阅读序号（派生自切割树 + 阅读方向）。**切换阅读方向（LTR/RTL）只改变序号排列，不移动格子的几何位置**——「右起」是顺序的镜像，不是布局的重排。
- **持久化**：版式与方向一并走既有防抖落库，刷新页面后读回，无需新增表或字段迁移。

> 推迟项（如实记账）：**悬停拖拽切割**（草案里的「鼠标划过即切」）、`skew` 微倾、单格转自由形状的逃生舱，均推后——先把树编辑语义用按钮跑通、单测锁死，输入方式与版式美学后置。

M6-4 落地**格编辑 + 对白层**（选中一格后编辑其内容；版式预览与格属性面板**双栏并排**）：

- **格属性面板（右栏三段式，与画布生成节点同构）**：① **画面描述**（喂生图的 prompt，对应画布生成节点）；② **镜头语言**（**字段化**的景别 / 机位 / 转场三下拉——不塞进提示词，转场取 McCloud 六类，首页可「无」）；③ **出场角色多选**（勾选角色卡；生成时把外观描述与参考图并入请求）。
- **对白层（左侧预览内叠加贴纸层）**：选中格上叠加对白贴纸，**可拖动位置**（松手提交，不逐帧写库）、**四类型可切**（speech 语音 / thought 心理 / narration 旁白 / sfx 音效）；类型靠**形状**区分而非颜色（圆角气泡 / 云朵 / 方框 / 斜体），只有语音与心理带**尾巴**。对白**不烘进图**——文本层独立于图，重生成画面不丢对白。
- **分工**：**属性在右栏改、位置在左预览拖**。右栏对白列表管类型 / 文本 / 说话人 / 删除；左侧贴纸只管位置。
- **持久化**：画面描述、镜头语言、出场角色、对白（类型 / 文本 / 说话人 / 坐标）一并走既有防抖落库，刷新后逐项读回，无需新增表或字段迁移。

> 推迟项（如实记账）：~~**拖尾巴改指向**、贴纸**尺寸手柄微调**~~ → **已于 M6-14 落地**。M6-4 判据只要求「贴纸可拖 + 四类型可切」，尾巴当时只维护锚点坐标、指向与尺寸微调后置。

M6-5 落地**格 → 生成**（AI 接线），并借 comic 这个「第二个消费者」把执行引擎做成**真共享**（调研稿 §5.5 路径 B）：

- **格能出图**：格属性面板末尾新增**生成块**（平台 / 模型下拉 + 生成按钮）。点「生成」→ 把 **画面描述 + 景别 + 机位 + 角色描述**组装成提示词发给渠道 → 产物铺满该格底（序号印章与对白贴纸叠其上）。按钮三态：**生成 → 生成中（可取消）→ 重生成**；未配齐平台/模型/画面描述时禁用并在下方提示；失败显示原因。
- **重生成不丢对白**：生成只写回格的 `assetHash`（底图），**绝不触碰 `balloons`（对白）与 `scene`（画面描述）**——对白与画面分层，重生成时贴纸原样保留。
- **三态按钮与生成配置**：平台 = 启用的渠道（与画布生成节点同一口径）；模型 = 该渠道 `modelCache` 中 `category === 'image'` 的模型；切渠道清空已选模型避免脏值。
- **执行引擎真解耦（内部，架构 §5.5）**：`RunRecord`/`RunRequest`/`RunTask` 等执行类型上移共享 domain；`RunPlan<TTask>` 泛型化；落位/写回抽成注入式 `ExecutionPlacement`，画布提供 `CanvasPlacement`、comic 提供 `ComicPlacement`。comic 与画布**复用同一个 `runEngine`**，差异只在注入的适配器。comic 侧新增纯函数 `domain/comic/panel/panelRun.ts`（格 → `RunRequest`/`RunPlan`）与命令 `panel.setAsset`。

> 推迟项（如实记账）：~~comic 的**版本历史 / 生成留痕**（适配器 `record` 暂返回 null）~~ → **已于 M6-15 落地**（留痕落格内 `runs`，见 §6.21.1）；~~**角色参考图作为渠道实际输入**~~ → **已于 M6-12 落地**（渠道层开始消费 `inputs`）；~~**角色卡参考图的上传入口**~~ → **已于 M6-13 落地**（角色卡内可直接上传 / 移除参考图）。**comic 侧已无推迟项。**

M6-6 落地**一话总览 + 翻页预览**（把一话当成品来读）：

- **一话总览**：版式区新增「**编辑 / 总览**」视图切换。切到**总览**后，本话**所有页**铺成缩略网格，一眼看全版式；点选任一缩略即回到该页编辑。页序恒为**叙事序**（不随阅读方向倒序）。
  - M6-6 时缩略**只画版式几何**（切割树算出的格子方框），**M6-9 起已升级为「方框 + 生成底图 + 右下页码角标」**（见下）：不显示底图的总览在产品上不成立——切到总览最想一眼看出的是「哪几页画完了、画成什么样」，而不只是「怎么切的」。
  - **对白贴纸仍不渲染**：缩略只有百来像素宽，贴纸文字缩到不可读，是噪声。未排版的页显示「未排版」占位（角标照旧——页码与是否排版无关）。
- **翻页预览**：点「**▶ 预览**」进入**全屏只读阅读器**——`← 上一页` / `下一页 →`（箭头朝向随阅读方向镜像）、键盘 `←`/`→` 翻页（语义同源）、`Esc` 关闭、顶部显示「第 X / N 页」；到首页 / 末页时对应按钮**禁用**。阅读器**复用页版式编辑器的渲染**（同一套几何 + 生成底图 + 对白贴纸），但不含工具条与序号印章、也不可编辑——**「预览里看到的」就是「编辑器里看到的」**。
- **翻页手感随阅读方向**：「左 → 右」时按 `→`（右）翻下一页；「右 ← 左」时按 `←`（左）才是下一页（日漫手感）。**页序本身不变**——阅读方向影响的是「怎么翻」，不是「页怎么排」。
- **不改数据**：视图切换与翻页都是纯界面状态，不产生新的持久化字段。

M6-7 落地**双页跨页阅读**（把「一次翻动」从一页变成一组页）：

- **单页 / 双页切换**：阅读器顶部新增「**单页 / 双页**」分段，默认单页。切到**双页**后一次显示两页：**第 1 页按封面惯例单独成页**，其后两页一组，**末尾落单也单独成页**（5 页 = 封面 + (2,3) + (4,5)；4 页 = 封面 + (2,3) + 末页）。
- **孤页站在它本来的位置**：单页那一侧留空占位，孤页**落在先读到的一侧**——「左 → 右」靠左、「右 ← 左」靠右；并排时「左 → 右」较早页在左、「右 ← 左」镜像到右。**镜像只改左右，不改内容与页序**。
- **翻的是「一组」不是「一页」**：双页模式下按钮与方向键按**跨页步进**（一次一组），页码文案显示区间（如「第 2-3 / 4 页」）；到首页 / 末页对应按钮**禁用**（与单页同一口径：到边界是无动作）。**页序仍是叙事序**，双页只是换了一种呈现。
- **翻页动效**：翻动时有一段短促的位移淡入，**进场方向随阅读方向镜像**（「左 → 右」下一页自右入、「右 ← 左」自左入）；系统「减少动态效果」开启时自动关闭。
- **仍不改数据**：阅读版式与翻页都是纯界面状态，**刷新后回到单页**；要记住偏好是另一个决定（新增项目级字段 + 读回迁移），不在本组做。

> 推迟项（如实记账）：~~缩略里的生成底图与页码角标~~ → **已于 M6-9 落地**（见下）；~~**翻页动效深化**（真实翻页 / 拖拽翻页）~~ → **已于 M6-10 落地**（见下；「卷页 / 3D 翻折」式真实翻页**刻意不做**，见调研稿 §7）；~~**导出时给画面打页码**~~ → **已于 M6-11 落地**（见下）；**条漫（竖屏无限滚动）经决策不纳入**（调研稿 §9 开放问题 #4 采纳「只做翻页漫画」——条漫没有「页」概念，是另一套排版模型，将来要做须另立形态）。~~整套导出~~ → **已于 M6-8 落地**（见下）。

M6-8 落地**整套导出**（一话 / 项目 → 图片包）：

- **入口**：项目页新增「**导出图片包**」区——选择**版式**（单页 / 跨页）与**范围**（导出本话 / 导出整个项目），下方状态行如实播报结果（如「已导出 3 张 PNG（共 3 页，其中 1 页未排版）」）。
- **产物是一个 ZIP**：**单页版式**每页一张 PNG（`001.png`、`002.png`…）；**跨页版式**两页并作一张，文件名就是页区间（`001.png` 封面、`002-003.png`…）。一话导出以话名为目录；导出整个项目时多一层项目名目录（`项目名/第 1 话/001.png`），多话解压后不会混作一团。
- **跨页导出与跨页阅读同一口径**：封面单页、两页一组、末尾落单，用的就是阅读器那一套分组规则——**不会出现「读的时候是一组、导出时又是另一组」**。并排时的左右同样随阅读方向镜像。
- **看不全也有整包**：还没生成底图的格**不阻塞导出**（该格导出为白底 + 细描边），未排版的页如实计入提示——「有 3 张没生成完」不该挡住「把这 12 页导出来」。
- **画质与版面**：单页 1080×1620（2:3 竖版），格子几何、对白贴纸形状与编辑器所见一致；跨页为两页并排 + 中缝。
- **不改数据**：导出只读既有数据，不新增字段、不写库；产物走与画布 `.flow.json` 同一条文件出口（浏览器另存为 / Tauri 落盘）。

M6-9 落地**缩略里的底图与页码角标**（一眼看出哪几页画完了）：

- **缩略不再只是方框**：每格方框内叠该格的**生成底图**（铺满格子），右下角带**页码角标**。切到总览最想一眼看出的是「哪几页画完了、画成什么样」，而不只是「分了几页、怎么切的」。
- **没生成就是没生成**：只有**真的生成过**的格才有底图；未生成的格留白底 + 细描边，不会用占位图假装画过了。
- **页码是叙事序**：角标为「第 1 / 2 / 3 页」的**叙事序号**，**不随阅读方向翻转**——角标是「页码」而不是阅读引导，固定右下、不镜像（「左 → 右」与「右 ← 左」下都是 1、2、3）。未排版的页也带角标。
- **格的排列跟着读法**：缩略里**格**的顺序按阅读顺序（「右 ← 左」时整体镜像），页的顺序不变。
- **对白不进缩略**：贴纸是格内的精细层，缩到百来像素宽只剩噪声。

M6-10 落地**翻页动效深化：拖拽翻页**（直接上手翻，而不只是点按钮）：

- **按住往旁边拖，页跟着手走**：拖过一定距离松手就翻页，没拖够就**弹回原位**。
- **拖到头就是拖到头**：首页还想往前翻时，页只会被拖动一点点（阻尼明显更小），松手也不翻——与按钮禁用的是同一件事：**到边界是无动作**。
- **拖的方向跟着读法**：「左 → 右」时往左拖是下一页；「右 ← 左」时往**右**拖才是下一页（与日漫翻页手感一致）。**拖不出第二种翻法**——它和按钮、方向键走的是同一套换算。
- **纵向拖动不翻页**：上下拖是滚动，不会被翻页抢走。
- **按钮与键盘照旧**：拖拽是增强，不是替代；系统开启「减少动态效果」时关掉翻页动画与回弹，但**拖拽跟手保留**（那是手的实际反馈，不是装饰）。

M6-11 落地**导出时给画面打页码**（可选，默认不打）：

- **打在「页脚带」里，不压画面**：勾选「页码」后，每张导出图在**页下方多出一条留白带**（页高的 4.5%），页码落在带子里——画面本身**一个像素都不被遮挡**。带子与页面同底色，视觉上就是书的页边。
- **默认不打**：导出的 PNG 常直接投稿 / 印刷，页码属「阅读辅助」而非画面内容，误开会让整批成品带上去不掉的号——**错了要重导**。想要时点一下「页码」即可。
- **跨页版式照常成立**：两页并排时**各有一条页脚带**（被中缝断开，像摊开的书），页码还是各自的；页码落在**外侧**——左页左下、右页右下；单页时落在阅读终点侧（「左 → 右」右下、「右 ← 左」左下）。
- **页码是每话内的叙事序**：从 1 起、不跨话累加（单行本也是分话编号），且**与总览缩略的角标是同一个数**——总览看到的第 3 页，导出图上写的就是 3。未排版的页也打（页存在就有号）。
- **不改数据**：开关是导出参数（界面态，刷新回落默认不打），导出仍只读既有数据。

M6-12 落地**渠道层真正消费 `inputs`**（图生图 / 角色参考图从此生效）：

- **此前是「接好了但没通电」**：画布的分组/批量节点、comic 的角色参考图早已把图像素材组装进 `RunRequest.inputs`，但渠道适配器只把提示词发出去——参考图在数据模型里存在、在真实链路里从未生效。
- **现在的规则**：一次请求**带图像输入**时走图生图端点（multipart 上传图片），**不带**时与原来完全一致（纯提示词）。最多上传 4 张（按内容去重），超出的丢弃后面的。
- **画布**：生成节点连着上游生成节点时，上游的产物自动作为本次的参考图——即**图生图**（同理「图生视频」）。上游重新生成后，下游会自动被判定为「过期」，重跑即带新底图。首页新增**「图生图」模板**（底图 → 图生图）。
- **comic**：角色卡上的参考图会成为该格生成的图像输入（**参考图的上传入口见 M6-13**，本组先把渠道侧打通）。
- **不静默降级**：渠道不支持图生图端点时**如实报错**，不悄悄退回纯提示词生成——否则用户会以为参考图生效了，实际被丢掉。只有「素材本身读不到（还没落库 / 已清理）」才退回纯提示词，因为那时确实无图可传。
- **不改数据**：全部是调用期行为。

M6-13 落地**角色卡参考图上传**（补上「有模型、没入口」的最后一格）：

- **此前是「字段齐全但填不进去」**：`referenceHashes` 自 M6-2 就在角色卡模型里、命令层也支持改它，M6-12 更让渠道真的会读它——但界面上没有任何地方能把一张图放进角色卡。等于这条链路只差用户能碰的那一下。
- **一次上传 = 选图 → 按内容取哈希 → 存进素材库**：上传的图与 AI 生成的产物**共用同一份素材库、同一套「id 就是内容哈希」的规则**。所以同一张图重复上传只会覆盖同一行（不占两份空间），换个文件名再传也**不会被当成新图**。
- **参考图可见、可删**：角色卡里直接显示缩略图，每张带一个移除按钮；点「＋ 上传」选图，选完即生效。
- **从此整条路可走通**：给角色卡传参考图 → 在格上勾选这个角色 → 生成时该图作为图像输入发给模型（M6-12 的渠道侧兑现）。
- **不改数据**：`character.update` 早已支持参考图字段，本组只加界面。

M6-14 落地**对白贴纸的尺寸手柄与拖尾巴改指向**（补齐 M6-4 欠下的两条直接操作）：

- **此前对白只有一半可操作**：贴纸的**位置**从 M6-4 起就能拖，但**尺寸**从建出来那一刻就定死了（默认占格宽 60%、格高 16%），文字一长就溢出且没有办法；尾巴也只能跟着气泡平移，**指不了说话人**。本组把这两条补齐。
- **尺寸手柄**：选中格内每张贴纸右下角一个小方块，拖它改尺寸——**左上角固定**（像是把右下角往外拽），尺寸夹在「不能小到读不出」与「不能超出格」之间，拖到格子外也不会把贴纸拖出格。
- **拖尾巴改指向**：语音与心理两类贴纸的尾巴**本身就能拖**，拖到哪就指向哪（命中区比看上去的尖角大，好抓）。旁白与拟声**没有尾巴**，也就不长这个手柄——「面版 / 音效」本来就没有指向。
- **一条规则收住所有「尾巴掉队」的坏手感**：气泡与尾巴**作为一体**一起平移、一起缩放，所以**只有**拖尾巴能改变尾巴相对气泡的位置。不然会同时出现「拖走气泡、尾巴留在原地」和「放大气泡、尾巴被吞进气泡里」两种坏结果。
- **只在选中格里出现**：手柄只画在**当前选中格**的贴纸上，其余格与翻页预览里依旧是干净的只读贴纸。
- **不改数据**：位置 / 尺寸 / 尾巴指向都是 M6-4 就有的字段，本组只是终于能从界面上改它们。

M6-15 落地**生成留痕与版本回退**（补上「点一下重生成就丢一版图」这个**不可逆**的洞，详见 §6.21.1）：

- **补的是什么**：M6-5 让格能生成图，但引擎产出的记录在 comic 侧被整个丢弃，旧的 `assetHash` 一被覆盖，画过的画面**再也回不去**（素材字节还在 `assets` 表里，却再没有指针指向它）。这是数据丢失，不是缺功能。
- **留痕住在格内**（`ComicPanel.runs`），随项目文档一起读写：comic 是单聚合对象、单写通道（整对象防抖落一行），不为留痕另开表；画布因是「图 + 补丁流」双存储，才必须分表。**持久化形态按数据形态选**，这一条与 comic / canvas 的整体差异同源。
- **三条不变量**：① **只增不减**（删一条 = 那一版产物变孤儿）；② **版本号由历史自身推出**（取 max+1），载荷类型刻意不含 `version`，从类型上堵死「两条 v3 / 跳号」这类**界面上看不出来**的错误；③ **回退本身追加为新版本**，历史永远只增，因此不需要 undo 栈兜底。
- **快照只记影响画面的字段**（画面描述 / 景别 / 机位 / 出场角色 / 渠道 / 模型 / 参考图 / 产物），**不含对白贴纸**（不烘进图，回退画面不该动对白）与**转场**（叙事关系，回退画面没理由改）——回退时保留面板当前的转场。
- **失败也留痕但不可回退**：只有「成功且有产物」的版本能回退——「恢复画面」与「恢复配置」是两件事，不能共用同一个按钮。
- **入口**：格属性面板新增第 ⑥ 段「版本历史」，倒序列表 + 缩略图 + 状态徽标 + 「当前」黑描边标记 + 回退按钮，点缩略图看大图浮层。


`projects.workbench` 决定该项目属于哪个工作台：

```ts
type WorkbenchId = 'canvas' | 'comic' // 后续工作台按需追加
```

`canvas` 为无限画布工作台，卡片进 `/canvas/:id`；`comic` 为漫画剧工作台，卡片进 `/comic/:id`。增加新工作台时增加联合字面量并写一次 Dexie schema 迁移；新项目按创建时选择的工作台写入 `workbench`，既有项目维持原值。首页不按工作台分类展示，所有项目统一一张网格，卡片上的工作台标识（文案标签）区分类型。

`channels` 只保存 `credentialRef`，明文令牌不出现在业务表里。

`nodes.data` 按类型：

`parentId` 是归属与坐标系的唯一真源（本次修订，消除三轨并行）：

| 归属 | `parentId` | 坐标含义 |
| --- | --- | --- |
| 画布根 | `null` | world 坐标 |

> **2026-11-11 节点标题旧参数与批量标题带**
>
> `FlowNodeHeaderLayer` 的普通节点标题排必须保留历史横向参数：相对节点左右各
> `8px`，行高 `22px`，标题排自身 `padding:0 2px`，间距 `2px`。标题字号继续读
> `--node-title-size`，像素读 `--fs-chip`；不要为了视觉上不越界改成与节点同宽。
>
> 批量容器的标题带只在 `packContainerChildren(..., reserveTitleRow=true)` 时生效：
> 每行先留 `22px` 标题带，再放 `200×160` 图片单元和 `16px` 行间距。分组的打包
> 仍走 `reserveTitleRow=false`，不得因批量标题带增加分组高度。`ContainerBody`
> 按容器 `kind` 传开关，批量的 `nodeHeaders` 与格位计算始终保留标题带。
>
> 老批量节点加载后若尺寸小于新网格要求，只允许 transient 地“长高/长宽”到
> `containerMinSize('batch', childCount)`；手工放大过的框不能被自动缩回。

> **2026-11-11 执行 prompt、循环分发与结果投影**
>
> 最终发送文案的唯一计算入口是 `features/shared/execution/runPrompt.ts` 的
> `applyCallOrdinal` / `actualPromptOf`。渠道请求、RunRecord、日志和结果节点只消费
> 同一个结果；禁止 UI 或渠道再自行拼一次序号。
>
> 循环节点的上游提示词是每轮共享上下文，本节点 `prompts` 才是按轮轮换的变量指令。
> `generationSpec.collectInputs` 必须按最终文本去重：循环文本已经包含某条直连提示词时，
> 直连项不再重复发送。循环节点用 `lastRoundIndex / lastRoundPrompt / lastRoundAssets`
> 保留最近一轮事实，不把运行期 `__round*` 字段当成持久数据。
>
> 批量产物仍落在历史承载节点；内部生成子项只写展示态
> `batchResultHash`，批量和嵌套批量容器另存 `batchResultHashes`。不得用生成结果覆盖
> 子项自己的 `assetHash`，因为它可能同时是下一次生成的输入。展示字段全部排除在指纹外。
>
> 65535 对话网关 502/503/504 是上游瞬时全失败，不是协议切换信号；同步和流式入口都只做
> 两次退避重试，仍失败就如实报错。只有服务端明确返回 Gemini native migration 错误时，
> 才改走 `/v1beta/models/{id}:generateContent`。官方 `/v1/pricing` 的 `endpoints`
> 不能证明当前账号的上游健康，不能据此把普通 5xx 自动改成另一协议。

>

> `pin.file.key`。这是页面自身 API 调用，不读取、导出或持久化 Cookie；失败时只回退到 DOM 候选。

>

> 2000 万像素上限；两侧都小于 64 的图标/占位图拒绝。`validateClipperImageCandidates` 只做批量编排，
> `captureClipperPage` 在写收藏前逐图校验，不能盲信 `og:image`。
> `isKnownClipperPlaceholderImageUrl` 是领域级共享判定，`normalizeClipperItems` 用它清理历史坏条目。
>
> 站点适配、单图校验、批量校验分别登记在模块治理中；不要再把 Huaban DOM/API 猜图逻辑散落到后台、
> Rust 队列或 React 面板。浏览器更新最后一步仍受 Chrome 安全边界约束，文件复制成功后必须由用户
> 在扩展页重新加载，应用不能静默写入浏览器 User Data。

> `autoCurateReferences` 自动分析本轮显式参考；分析结果写入参考台账的 What / usage /
> HowToUse，再进入正常任务筛选。分析失败只写 warning、提示用户并继续使用显式 chip，
> 不阻断整轮 Agent。`curateReferences` 工具仍保留，供模型对指定参考重新分析。
>
> “参考分析完成”的折叠标题保持短句，展开 detail 会列出每条参考的 What 与本轮 HowToUse；
> 这些内容来自真实台账和自动分析结果，不伪造模型思考。
>
> 联网调研在 Openverse、Wikipedia、SearXNG 之外新增 Internet Archive 与
> Art Institute of Chicago 两个免密钥开放 API。公共 SearXNG 实例可能返回 429/403，
> 因此各来源独立 `Promise.allSettled`，单个来源失败只产生分源警告；开放馆藏来源仍能返回
> 图片、作者和来源链接。候选加入项目参考后继续遵守统一素材落库、许可说明和 Agent 挂载路径。

> **2026-11-11 Clipper 主图候选与多地址回退**
>
> 扩展侧的图片选择边界只在 `drop-target.js`：拖拽事件先看实际命中的图片，再用
> `elementsFromPoint` 和最近的 `a/picture/card/pin/item` 容器收集同卡图片；候选按
> 指针覆盖、可见面积、自然像素和 UI 标记评分。最终只为得分最高的那张图生成 URL 链，
> 不会把所有页面图片混在一起传给桌面端。
>
> URL 链先取 `data-original/data-src/data-zoom-image` 等原图属性，再取
> `<picture><source srcset>`、`img[srcset]`、`currentSrc/src`，并应用站点级升级：
> 花瓣 CDN 的 `_fw*` 缩略后缀、Pinterest 的 `236x/474x/736x/1200x` 预览路径。
> 同一张图最多保留 8 个候选，源顺序由页面语义决定，而不是随机排列。
>
> `background.js`、`clipper_receiver.rs`、`clipperQueueClient.ts` 和
> `capturePendingClipperClip` 都保留 `imageUrls`；桌面导入逐个校验 HTTP 状态、魔数、
> 尺寸和像素上限，前一个地址得到 403/非图片时继续试下一个。成功条目保存剩余候选链，
> 后续加入 Agent/参考时由 `saveDesignResearchItem` 再重试，避免捕获成功但二次落库失效。
>
> 对照来源只用于确认公开行为：Image Picka（MIT）的 srcset/背景图/拖拽提取，
> Huaban Downloader（MIT）从页面数据拿原图，KellyC（GPL）的预览/原图分类。
> 轻画没有复制 GPL 代码，相关实现按本项目模块边界独立编写。

> **2026-11-11 Clipper 真实图片识别与失败分级**
>
> 扩展内容脚本负责“从拖拽现场提取最可信的图片 URL”：先看拖拽目标或指针命中的
> `img/input[type=image]`，容器节点则选择面积最大的可见图；候选顺序为常见懒加载属性、
> `<picture><source srcset>`、`img[srcset]`、`src/currentSrc`，最后才看 CSS 背景图。
> 页面自身的 URL 不是图片候选，缺少图片时扩展直接报错，不再让应用抓整页分享图。
> `captureClipperImage` 只接收真实图片地址，经 `NetworkPort(publicOnly)` 或桌面壳
> `fetch_text.bodyBase64` 读取字节，再校验图片魔数、头部尺寸和 2000 万像素上限。
> `ClipperCaptureError.retryable` 是失败分级边界：永久格式错误由队列 ack 淘汰，
> 网络异常和 5xx/567 抗爬响应保留重试。UI 测试桩必须实现同一 `fetch_text` 协议，
> 不能再用“收到队列即成功”的假网络绕过真实校验。

> **2026-11-11 Clipper 前后端协议兼容**
>
> WebView 前端可能热更新到比 Tauri 后端更新的版本，因此新增命令必须有显式降级。
> `readClipperPendingQueue` 先调用无副作用 `clipper_pending_snapshot`；仅当错误明确为
> `Command clipper_pending_snapshot not found` 时，回退旧 `clipper_take_pending` 并标记 legacy。
> legacy 模式不调用 ack，只在导入后提示用户重启桌面端；其他权限/传输错误不能落入回退。
>
> GitHub 对照：Image Picka 使用固定全站权限、声明式 content script 和后台集中调度；
> Browserpass 使用固定 host permissions 与 Native Messaging，native host 需系统注册。
> 轻画当前保持 loopback HTTP 接收端；Native Messaging 作为未来在端口稳定性或跨浏览器隔离
> 成为主要矛盾时的替代方案，不在本轮重复实现两套传输。

> **2026-11-11 Clipper 全站权限与待收队列确认**
>
> 浏览器扩展的全站访问是固定 `host_permissions`，不是 optional 权限；用户在安装/升级时确认一次，
> 之后只由 popup 的全局“拖拽收藏”开关控制功能启停。`background.js` 对已打开 HTTP/HTTPS 标签页
> 调用 `executeScript`，同时注册持久 content script 服务后续新标签页；浏览器保护页明确不可注入。
>
> 接收端队列可以重复读取，不能由读取动作本身删除。`clipper_pending_snapshot` 返回副本，
> `clipper_ack_pending(ids)` 只删除成功导入项；`capturePendingClipperQueue` 负责逐条导入并返回
> `importedIds / failed`。失败项保留在原队列，下一轮轮询自动重试。
>
> `useClipperLiveCollection` 必须先完成收藏 `loadState()`，再开始队列轮询，避免旧空快照覆盖刚导入
> 的卡片。它先刷新 `items`，再 ack；ack 失败只影响队列确认，不影响已成功写入的收藏展示。
> `ClipperPanel` 只编排分类、多选和后续 Agent/参考/画布动作。

> **2026-11-10 Clipper 本地安装版版本检测与稳定目录更新**
>
> 浏览器扩展在 `/pair` 请求体上报 `chrome.runtime.getManifest().version`，
> `clipper_receiver.rs` 只把该版本记为“最后连接的已加载版本”，不据此修改扩展。
> `clipper_update.rs` 是唯一的 Tauri 扩展更新边界：从应用资源目录读取内置
> `resources/qinghua-clipper/manifest.json`，与已加载版本比较后，在
> `Documents\QinghuaClipper` 内创建同盘 staging，完整复制并校验 manifest 与必需文件，
> 再以目录 rename 启用新版；失败时恢复旧目录。目标路径只允许
> `QinghuaClipper\extension`，现有目标经 canonicalize 后偏离该位置就拒绝覆盖。
> 对尚未上报版本的旧扩展，`clipper_update.rs` 还读取稳定目录自身的 manifest 作为迁移兜底；
> 已连接版本存在时优先使用已连接版本，避免把刚从稳定目录更新、但浏览器仍运行旧代码的状态误判为完成。
>
> `tauri.conf.json` 直接把仓库里的 `browser-extension/qinghua-clipper/` 映射成应用资源，
> 禁止维护第二份可编辑扩展源码。更新命令不写浏览器 `User Data`，也不尝试静默重载；
> 它只打开浏览器扩展管理页和稳定目录，最后一步必须由用户确认。
> 更新成功后 `reloadRequired` 会保持为真，直到扩展下次 `/pair` 上报的版本达到待重载目标；
> 这个状态与“磁盘文件是否已更新”分开，防止旧扩展不报版本时提示提前消失。
>
> 前端 `useClipperExtensionUpdate.ts` 只消费接收端状态和更新命令，
> `ClipperExtensionUpdateNotice.tsx` 只在已加载版本落后时显示紧凑提示；
> 不恢复安装卡、配对卡或常驻说明。版本一致后面板立即回到普通收藏界面。

> **2026-11-12 调研图片动作生命周期与来源回溯**
>
> `ResearchGalleryOverlay` 只编排展示，逐动作 busy、状态和 `AbortController` 收在
> `useResearchGalleryActions`；add / download / send 共用同一条 `try/catch/finally` 生命周期，
> 任何结束路径都必须清 busy、关确认框，关闭弹层或卸载时 abort 当前动作。按钮的 `aria-busy`、
> 禁用态和 `styles.busySpinner` 必须与同一份动作状态同源。
>
> `useAgentResearchReferenceController` 经 `researchActionAbort` 给图片保存链设置 12 秒总
> deadline，并把同一个 signal 透传给 `saveDesignResearchItem`，不能再用永不取消的新 controller。
> 严格“加入项目参考”失败时仍返回失败；发送到对话由 `researchSourceReference` 降级为同台账的
> text 来源参考，继续追加会话 `referenceIds`，但不得伪造 `assetHash` 或宣称图片已保存。
> 大图预览是弹层内 `position:absolute` 的子层，范围只等于当前 `useResearchOverlay` 的
> canvas bounds；容器 `overflow:hidden`，`img` 的宽高都相对容器收在 100% 内。只限制容器不够，
> 子图不能再用 `92vw` 一类 viewport 尺寸；不得改回覆盖右侧 Agent 的 viewport `fixed`。
>
> 调研图片参考的 `what` 和 `projectAgentTurnReferences` prompt 都应带
> “图源：查看图片搜索结果”与来源页面 URL；这样模型能区分用户图库素材、画布节点和公开图片搜索结果。

> **2026-11-12 创作面板固定高度与 CSS Module 同名键**
>
> 创作面板的固定高度契约由外壳拥有，`promptSection / promptRow / promptBox / editor`
> 整条链统一 `flex:1 1 0; min-height:0`，超长提示词只允许 editor 内部滚动。组件域 CSS
> 拆分后，`creationStyles` 不能再平铺合并共享同名类：参数域的 `.promptBox` 曾覆盖提示词域，
> 使 DOM 实际丢失 `display:flex/position:relative`。跨域后代规则改用稳定的
> `[data-panel-prompt-box]` 锚点，并由结构测试禁止四个域重复导出同名类。

> **2026-11-10 生成历史首屏分页与素材点查**
>
> 生成历史页面不再调用 `AssetHistoryRepository.list()`。首屏统一走
> `listPage({ offset: 0, limit: 30 })`：先按 `createdAt` 倒序取一页 `runRecords`，
> 再按这一页的输出 hash 批量点查 `assets` 元数据；`AssetLibraryStore.loadMoreHistory()`
> 每次继续取 30 条，并只保留同 hash 的最新 `createdAt`。
>
> sqlite-v2 的 `queryPage` 对 `assets` 支持 id 集合、hash 排序和分页，返回
> `bytesLength` 而不读图片字节；其他分页条件明确拒绝，避免和通用 rows 语义混淆。
> `AssetLibraryStore.load()` 必须具备并发幂等性，React StrictMode 不能重复发起整套历史查询。
> 生成历史 chunk 在应用空闲和 `/assets` 导航意图时预取，路由真正打开时只付数据和首屏渲染。
> `assetCardProjection.ts` 只负责历史产物到素材卡片的数据映射和时间格式，不持有查询或渲染状态，
> 避免 `AssetsPage` 再次越过单文件预算。

> **2026-11-10 Agent 媒体 chip 与画布缓存导入边界**
>
> `MentionEditor` 新增 `mentionChipViewOf` 作为唯一媒体引用描述：`node` 与 `reference`
> 共享缩略图、标签和尺寸；内容可编辑区用同一描述构建命令式 DOM，`MentionRichText` 用
> `MentionChipView` 复用 React 视图，禁止再按入口各画一套 chip。

>
> 「生成历史 → 当前画布」不得另建短生命周期 store。`sendToActiveCanvas` 通过

> `flush` 后广播写入，保证 SPA 返回画布立即可见，不依赖刷新。

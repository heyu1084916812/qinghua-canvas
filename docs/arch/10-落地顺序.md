## 10. 落地顺序 · ✅ 已实现

架构在 M0 阶段一次性搭成骨架，后续里程碑只往骨架里填内容。

| 阶段 | 动作 | 完成判据 |
| --- | --- | --- |
| M0-1 | 建目录骨架与空模块，`npm run check` 通过 | 目录存在，依赖检查可运行 |
| M0-2 | 实现 `domain/shared/` 与 `domain/canvas/`：坐标换算、拓扑排序、环检测、容器打包、~~结果组落位~~、空槽位查找、下游遍历、`nodeSpecs` 骨架 | 纯函数单测全绿 |
| M0-3 | 实现 `platform` 端口与内存实现、Web 实现（含 `NetworkPort.stream` 签名） | 状态层可在无浏览器环境跑通 |
| M0-4 | 实现 `state/shared/` + `state/workbenches/canvas/`：切片 + 命令 + 历史 + 持久化；`createStore(workbench, slices)` 工厂 | 命令派发可回滚、可落库；`createStore('canvas', canvasSlices)` 可调用 |
| M0-5 | 实现画布骨架 + `NodeFrame` + 渲染注册表 + `nodeSpecs` 注册（提示词节点两侧都注册完成） | 提示词节点走通全链路 |
| M0-6 | 落 `ui/tokens.css` + `ui/motion.ts` + 样式三条约定 | 组件样式里零字面量颜色 |
| M0-7 | 建 `dev/preview` 陈列室与 `fixtures.ts` | 生产构建产物中不含 `dev/` |
| M0-8 | 落 `NetworkPort.stream` 签名 + `features/shared/agent/types.ts` 与 `scopeGuard.ts` 接口 + `features/canvas/agent/tools.ts` 空文件 | 接口存在且有类型测试，运行时留空 |
| M0-9 | ~~工作台插槽~~ **推迟到第二个工作台立项时**（成本理由仍在 §5.10，但价值只在 comic 落地时兑现，当前属于空转）。**已于 M5 兑现**（见 §5.10 兑现状态） | 立项第二个工作台时一次性完成 ✓ |
| M0-10 | 接入依赖检查与测试门禁 | `npm run check && npm test` 全绿 |
| M0-11 | **mock 渠道出图冒烟**（新增）：渠道配置 → 生成节点 → `buildRunPlan` → `runEngine` → 产物落位 → 日志，不做 UI 打磨 | 用内存平台与 mock 渠道跑通一次完整出图，`RunSummary` 与 `RunRecord` 落库正确 |

M0-5 是**结构验证点**：用提示词节点这一个纵向切片穿过全部层，证明七层的接线方式成立。
M0-11 是**契约验证点**：让真实生成链路第一次压到执行引擎、产物落位与事务合并。原计划这两个契约要等到 M2 才被验证，中间隔了整个 M1，返工面太大——因此把一次 mock 出图前移到 M0。

M0-6 与 M0-8 是两个扩展位的低成本占位（UI 打磨 / Agent 与流式），合计不到半天；M0-9（工作台插槽）已推迟。跳过 M0-6 的代价是后续做一次全局样式重构，跳过 M0-8 的代价是后续做一次网络层改签名——两者都很贵，保留在 M0。

## 7. 依赖治理

### 6.3 模型映射与选路（M7-1..M7-3 已实现，2026-09-26；技术口径）

**不变式**：画布 / 漫画节点只存**逻辑模型名**；渠道配置持有 `modelMap: Record<逻辑名, 上游ID>`。执行计划在 `toRunRequest` 之后、调用渠道之前解析映射；解析不到按 `channel/missingModel` **如实报错**，不静默换模型。

| 关注点 | 结论 |
| --- | --- |
| 数据位置 | `modelMap` 仍是 `channels` 表内字段，不新增表、不改 `models` / `modelCache` 分工 |
| 纯逻辑 | 解析函数放 `domain/project/modelMapping.ts`（纯函数 + 单测），不依赖 platform / React |
| 适配层 | 适配器收到的 `RunRequest.model` 已是**上游 ID**；适配器不需要认识逻辑名 |
| 兼容 | 无映射 = 恒等映射（逻辑名即上游 ID），老项目 / 老渠道零迁移 |
| 界面 | 设置页「模型管理」内加映射编辑（逻辑名 → 上游 ID）；**M7-2 已落地**（优先度 + 权重 + 逐模型映射）。**2026-09-29 第 12 轮**：选路策略移出渠道表单、独立成全局卡，渠道卡改名「渠道权重与模型映射」 |
| 选路 | **M7-1**：逻辑名 → 多渠道候选，按策略挑一条（候选由渠道**现算**，不物化成表）。三档：`priority` / `performance`（实测延迟）/ `balanced`（权重随机）。失败降级 = **降到下一档**（同 new-api 的 retry 语义） |
| 策略归属 | **策略全局唯一**（2026-09-29 第 12 轮）：`resolveRouteFor` 收**显式传入**的 `strategy`，不再读渠道字段 / `governingChannelId`（跨渠道比较只能有一把尺子）。落库在 `presets` 保留行 `routing:strategy`（`presetStore.loadRoutingStrategy` / `saveRoutingStrategy`），缺省 `priority`。渠道旧 `routeStrategy` 仅兼容老数据，不参与选路 |
| 候选门禁 | 候选硬过滤 `enabled && hasToken && upstreamModel`：**未启用渠道绝不入选**（即便优先度 / 权重最高、延迟最低）；全部禁用时返回 `null`，调用方如实报错 |
| 执行 | **M7-3**：在适配器解析**之前**选路并改写 `request.channelId/model`；适配器拿到的已是上游 ID |
| 留痕 | **M7-3**：`RunRecord` 增 `sentChannelId` / `sentModel`，记**实际发出**的那一条；日志面板优先显示它，缺则回落节点意图（老记录零迁移） |
| 失败可见性 | 缺失映射必须进日志与节点错误态，禁止「点生成没反应」 |

**技术栈无新增**：仍为 React 18 + TypeScript + Vite + Zustand + `StoragePort` / 本机 shared-store + Vitest + Playwright；Dexie 只保留旧浏览器库迁移读取。模型映射是纯领域逻辑 + 一个设置页表单，不引入新依赖。

**有意未做**：「价格优先 / 质量优先」两档 —— 需要价格表与质量评分，本项目目前无此数据，
做了只能是假排序。等数据来源就位后，给 `RouteStrategy` 加枚举值即可，解析函数无需改结构。

### 6.4 新建节点的默认渠道 / 模型解析链（已实现）

**要解决的问题**：新建节点时 `channelId` / `model` 为空，每建一个都要重选。
早期实现只在**创建那一刻**算一次，算不出来就写空，且面板侧没有第二道兜底——
于是「渠道已配置、模型只在 `modelCache`、尚未勾选」这条**最常见**的路径下，新节点永远是空的。

**设计口径**：参照参考项目「大雄无限画布」的做法，但保留本项目「创建时写入节点」的现有路径。
参考项目把默认值记忆按**执行模式**分桶（api 生图 / api 视频 / comfy 文案…），
本项目**统一走渠道**、执行引擎不分叉，故其「模式桶」在本项目里天然等价于**渠道这一层**，
不再额外造分类层。默认值按**渠道**记忆（该渠道上次生成用的模型 + 参数）。

| 关注点 | 结论 |
| --- | --- |
| 纯逻辑 | `domain/project/generationPreset.ts`：`resolveRecipe` / `firstUsableChannel` / `rememberRecipe`，纯函数、无副作用、不读 storage |
| 解析链真源 | 节点自身 → 该渠道上次记录 → 第一个可用渠道的首模型 → 留空；**创建路径与面板兜底共用同一函数**，不各写一套 |
| 存储 | 仍在 `presets` 表（`presetStore`，键 `projectId`），不新增表；记忆粒度由「项目一份」收敛为「渠道一份」 |
| 状态层 | `state/channel/channelStore.ts` 的 `defaultForNewNode(projectId, category?)` 是唯一对外入口；`category` 供提示词节点按 `chat` 过滤 |
| 创建层 | `pages/CanvasPage` 现取默认值 → `newNodePreset` 白名单取参 → `node.create`；`newNodePreset` 只做叠加，不含规则 |
| 面板层 | `workbenches/canvas/panels/CreationPanel.tsx` 增加同源兜底：节点未带渠道 / 模型时按解析链现算，而非留空 |
| 兜底边界 | 面板兜底**只在节点模型为空时生效**：节点已有值是用户状态，面板不得覆盖（否则「图片 → 视频」切类别会立刻被填回，看着像没切） |
| 失败可见性 | 解析不到必须可诊断（「还没配置渠道」/「该渠道还没勾选模型」），禁止静默留空 |
| 兼容 | 老项目无记录 → 走「第一个可用渠道的首模型」，零迁移 |

**依赖方向不变**：domain ← state ← pages/panels。解析规则只在 domain，state 只提供渠道列表，
页面与面板只调用，不复制判定——避免「哪套默认值对」随调用点漂移。

### 7.2 dependency-cruiser 规则 · ✅ 已实现

```js
// .dependency-cruiser.js（节选）
module.exports = {
  forbidden: [
    { name: 'domain-pure',
      from: { path: '^src/domain' },
      to:   { pathNot: '^src/(domain|shared)' } },
    { name: 'ui-stateless',
      from: { path: '^src/ui' },
      to:   { pathNot: '^src/(ui|shared)' } },
    { name: 'no-upward',
      from: { path: '^src/state' },
      to:   { path: '^src/(workbenches|pages|features)' } },
    { name: 'no-node-cross-talk',
      from: { path: '^src/workbenches/[^/]+/nodes/[^/]+/.+\\.tsx?$' },
      to:   { path: '^src/workbenches/[^/]+/nodes/[^/]+/.+\\.tsx?$',
              pathNot: '^src/workbenches/[^/]+/nodes/registry\\.tsx?$' } },
    { name: 'agent-only-through-commands',
      from: { path: '^src/features/(shared|canvas)/agent' },
      to:   { path: '^src/state/workbenches/[^/]+/slices',
              pathNot: '^src/state/workbenches/[^/]+/commands' } },
    // 必须拆成两条互斥规则：写成 from (canvas|comic) → to (canvas|comic) 时，
    // 同一工作台内部互引（domain/canvas 内 layout → geometry 等）会被误判为跨工作台引用（实测 34 处误报）
    { name: 'no-workbench-cross-talk-canvas-to-comic',
      comment: '画布 → 漫画剧 互引禁止',
      from: { path: '^src/(workbenches|features|state/workbenches|domain)/canvas' },
      to:   { path: '^src/(workbenches|features|state/workbenches|domain)/comic' } },
    { name: 'no-workbench-cross-talk-comic-to-canvas',
      comment: '漫画剧 → 画布 互引禁止',
      from: { path: '^src/(workbenches|features|state/workbenches|domain)/comic' },
      to:   { path: '^src/(workbenches|features|state/workbenches|domain)/canvas' } },
    // 每新增一个工作台追加一条互斥规则，或改用插件化配置按 workbenches/ 子目录展开成 N×(N-1) 条
    { name: 'no-shared-to-workbench',   // M6-1 新增
      comment: '共享层不得依赖任何工作台私有层（架构 §5.10）',
      from: { path: '^src/(shared|domain/shared|state/shared|features/shared)' },
      to:   { path: '^src/(workbenches|features|state/workbenches|domain)/(canvas|comic)' } },
    { name: 'dev-preview-isolated',
      from: { path: '^src/(workbenches|features|state|domain)' },
      to:   { path: '^src/dev' } },
  ],
}
```

- `no-node-cross-talk`：一个节点类型的实现不引用另一个节点类型的实现，共享部分上浮到 `registry` 或 `ui`
- `agent-only-through-commands`：Agent 只能通过命令层改图数据，绕过命令直接写切片即视为违规
- `no-workbench-cross-talk-{a}-to-{b}`：工作台之间禁止互相引用，**按方向拆成互斥的多条**（合并成一条 `(canvas|comic)` 双向规则会误伤同一工作台内部互引，实测 34 处误报）；新增工作台时增加对应规则，或编写插件按 `workbenches/` 子目录自动展开成 N×(N-1) 条。现共 9 条 forbidden 规则，`npm run check` 实测 216 modules / 796 dependencies
- `no-shared-to-workbench`（M6-1）：共享层（`src/shared`、`src/{domain,state,features}/shared`）不得 import 任何工作台的私有代码。**这条补上了长期缺口**——原先 §5.10 只写了这条不变量却没有工具强制，导致 `features/shared/{execution,useViewport,agent}`、`state/shared/persist` 反向依赖画布无人发现（`tsPreCompilationDeps: true` 下纯 type import 亦计入）。注意现有 `no-workbench-cross-talk-*` 规则**不覆盖**此方向（`features/shared` 不匹配 `features/(canvas|comic)`），故必须单独一条。
- `dev-preview-isolated`：陈列室是单向依赖，业务代码不引用它

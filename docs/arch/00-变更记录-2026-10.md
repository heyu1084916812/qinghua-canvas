> **2026-10-30 画布渲染性能审计（对账 #827，✅ 已由 #832 收口）**

> **2026-10-20 电商方案模型与生成状态边界（对账 #647）**：`userConfiguredChannels()` 只负责剔除离线 `mock`，不得按 `ch_builtin_*` 一刀切；是否可进入方案模型由 `chatTargetOptions()` 继续按 `channelIsRoutable()`、启用状态、地址、令牌和 `chat` 模型能力判定。电商结果状态先经 `domain/ecommerce/tasks.resultDisplayStatus()` 收口：实时 `running / queued / failed` 优先于结果行与旧产物 hash，执行结束后的 `succeeded` 才允许回落到新 hash 的 `done`。工作台只负责把该状态渲染为排队、生成计时、失败原因与 `role=alert`；执行状态仍唯一来自 `exec.nodeStateOf()`，不得在 UI 另造运行状态。

> **2026-10-20 电商工具状态边界（对账 #646）**：`EcommerceFormDraft.modeStates` 按 mode id 保存 `platformId / language / ratio / note`，顶部工具切换先用 `defaultModeFormState()` 补缺，再读取当前项；禁止把这些字段重新收成单份组件 state。A+ 版面值属于领域白名单 `ECOMMERCE_A_PLUS_RATIOS`，生成节点构造前必须调用 `ecommerceAspectRatio()` 转成真实宽高比。语言与平台按用途/参考顺序由领域函数给出，页面不得再维护第二份硬编码数组。

> **2026-10-20 电商选择器边界（对账 #645 / #647 修正）**：电商自有控件 `workbenches/ecommerce/EcommerceSelect` 负责触发器、键盘、点外关闭与 `body` 级 `position: fixed` 浮层，不复用画布私有 `ParamPicker`，避免电商工作台反向依赖画布布局常量。`domain/shared/chatTarget.userConfiguredChannels()` 只排除离线 `mock`，页面装配层再交给 `chatTargetOptions()` / `resolveChatTarget()` 按可路由状态与真实对话模型收口；不得再按 `ch_builtin_*` 一刀切。UI 列表与真实请求因此共用同一渠道来源。套图数量仍存入 `EcommerceModeOptions.setCounts`，0 值保留“未启用”语义，不新增平行状态。右栏 `formScroll` 自身铺到面板右边，内容右内距放在滚动容器内部；滚动条位置属于容器几何，不能靠改 `::-webkit-scrollbar-track` 视觉修补。

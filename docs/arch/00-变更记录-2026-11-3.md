> **2026-11-02 Agent 隐式画布操作分类（对账 #850）**：工具能力存在不等于本轮能调用，`agentToolsForRequestMode()`
> 会按请求分类裁剪工具。`排列成一排 / 排成一行 / 整理到空位置 / 放在空白处` 是明确的画布布局语义，
> 即使句子省略“节点 / 图片 / 画布”也不能落入 `simple_generate`。单次布局识别为 `canvas_operation`，
> 同句同时包含“生成 N 张后再排列”这类前后动作时识别为 `complex_plan`，以同时保留生成和整理工具。
>
> 工具选择采用两层渐进披露：`readCapabilities` 在任何档位都常驻；模型不确定能力时先读取能力索引，
> 返回匹配工具的名称、说明和完整参数 schema，`AgentLoop` 在同一轮后续模型调用中动态加入该工具。
> 如果模型跳过了能力索引、直接准备回复“没有这个能力”，执行层会在收口前自动补查一次并继续同一轮；
> 只有在读取过能力目录之后，才允许模型下“不支持”的结论。
> 动态加载结果会写回本回合工具集，确认卡或轮数检查点续跑仍使用同一份权限，不退回裁剪前的全量工具。
> 权限分类、确认卡、账本和副作用规则仍复用原工具定义，不因动态加载而绕过。系统提示词明确要求：
> 读取能力索引前不得直接断言“做不到”。

> **2026-11-02 Agent 媒体配方、attach 复用与全局选路（对账 #849）**：`attach` 的第一层语义始终是
> “复用画布上已有节点”，不是“再造一个同名生成节点”。只有该 localId 没有作为任何连线起点时，
> 同名新生成节点与参考复用的冲突才允许自动拆成 `__reference` 别名；已经向下游供参考的节点必须保持原样。
>
> 从上游继承生成配方时，只能继承 `generation / batch` 媒体节点的 `RECIPE_TRACKED_KEYS`。提示词节点的
> `channelId / model` 属于对话模型，不得写入图片或视频生成节点；生成计划若误填 chat 模型，
> `alignGenerationMode()` 会移除旧模型与渠道，交给该媒体类别的默认配方，并在落地后再次校验。
> Agent `updateNode` 走同一类型不变量：prompt 只接受 chat，generation / batch 只接受对应 mode 的
> image / video；混合批次只要有一个不兼容就整批拒绝，不能写一半。
>
> 生成路由以“逻辑模型 + 全局渠道优先度”为主，节点里遗留的 `channelId` 不再充当硬白名单。
> 路由配置里的 `allowedCandidates` 仍是硬边界；其余情况下高优先渠道先参与，旧渠道只作无模型时的兜底。
> 画布日志面板只显示生成 / 本地合成记录，`params.kind = text` 的 Agent 与提示词工具调用保留在总审计数据中，
> 不混入用户看到的画布生成日志。

> **2026-11-02 Agent 排队完成态与恢复对账（对账 #848）**：会话活动锁只负责“同一会话同一时刻一个回合”，
> 不能把“领到了队列项”与“知道领到哪一项”拆成两次无关联操作。`pumpQueuedTurn()` 先占锁、再原子领取
> `queuedTurn`，领取成功后必须立即用 `bindQueueTurnToSessionActivity()` 把真实 `turnId` 绑回活动锁；
> 确认、暂停、停止和最终结算都从这把锁取得同一个 ID，才能准确调用 `finishActiveQueuedTurn()`。
>
> `AgentController.refresh()` 对无本地活动但仍有 `activeTurnId` 的旧会话按 `AgentJob` 终态恢复：
> `completed` 表示结果已经落库，只销掉对应队首并清 `activeTurnId`，不得再次发送；`failed / canceled`
> 只清活动阻塞并保留排队消息，由用户决定重试或删除；非终态任务继续走原有 `recoverSession()`，
> 不自动重发未知结果。这样修复的是旧数据恢复路径，而不只是防止新卡死。

> **2026-11-02 协议下载走系统另存为（对账 #847）**：`FilePort` 增加可选

> Web File System Access 也区分用户取消；旧 `saveFile()` 保持兼容。协议模板、站点说明和

> SquareFaceIcon 不需要新增内置适配器：按内置 `openai-compatible` + Base URL 手动建渠道即可。

> **2026-11-01 站点协议下拉内动作与只读导出（对账 #846）**：协议目录继续保留全部内置定义，
> 设置页只对 `kind === 'station'` 的站点项应用用户隐藏集合。`ChoicePicker` 的选项支持可选
> `actions`，在同一行尾渲染下载 / 删除按钮；动作按钮不会触发选项切换。Mock、公开模板和
> 自定义协议的显示规则不变，基础项出现但没有动作，页面不再额外渲染协议管理长列表。
> `channelStore` 从 `presetStore` 的 `presets/protocol:hiddenBuiltins` 行读取和写入 id 列表；
> 删除前必须同时检查内置身份、基础协议保护与 `channels[].protocol` 引用，不能静默改指。
> `protocolExport.ts` 分成两类输出：自定义协议仍投影为可再次导入的 `qinghua.protocol/v1`，
> 内置协议投影为 `qinghua.protocol-reference/v1` 只读说明文件，保留 base URL、能力、凭据槽位

> **2026-11-01 声明式自定义协议与通用 HTTP 适配器（对账 #842）**：
> `ProtocolFamily` 新增 `declarative-http`。用户导入的 `qinghua.protocol/v1` 只保存
> `DeclarativeProtocolRecipe`，不执行任意脚本：请求路径必须以 `/` 开始且只能拼在当前渠道
> 基址后面；模板变量和简化 JSONPath 均有白名单；不支持 OAuth、WebSocket、签名算法或跨域端点。
> recipe 声明四类能力：`models` 固定模型目录，`chat` 非流式对话与工具调用，`image / video`
> 的同步产物或提交 → task id → poll → result。适配器支持 JSON / multipart、Bearer / Header /
> Query / Basic 鉴权、URL / Data URI / Base64 产物和多参考图；本协议不发流的对话由
> `GenerationClient` 回落到 `completeText`。提交阶段的超时继续使用 `execution/accepted`，
> 不因结果未知自动重发付费 POST。自建协议 row 的 `recipe` 随 `customProtocols` 持久化，
> reload、路由组装和备份必须原样保留；没有 recipe 的旧自建协议继续按 `openai-compatible`。
> 设置页的“导入 AI 协议”只做模板下载、文本 / 文件导入、格式校验、摘要预览与保存；
> 接口地址、API Key 和真正无费用试连接仍在渠道层完成。

> **2026-11-01 自定义协议草稿生成与渠道绑定（对账 #841）**：
> 自定义协议只描述接口形态，不重复保存渠道的 `baseUrl` 或凭据。界面输入只有名称和能力；
> `customProtocolDraft` 根据名称确定性生成内部 ID 与最多 8 字的短标签，同名由 UI 在 store
> 返回“已被占用”后继续生成后缀，避免目录快照暂时滞后时失败。接口版本从当前渠道地址识别
> `/v1`、`/api/v3` 等结尾，无法识别回退 `/v1`；版本与文档地址只放在高级设置。
> 创建成功后必须立即把这枚协议写回当前渠道，不能依赖已经取消的整张表单保存按钮。

> **2026-11-01 SoonStudio Gemini 异步内层协议错误（对账 #840）**：
> SoonStudio 图片主路径保持 `POST /v1/images/generations?async=true`，外层可能返回
> `jobId + pollUrl`，轮询响应可能先 `status=completed`，此时必须读取
> `response.body.error`。错误文本明确包含 `gemini_native_request_required`、要求
> `/v1beta/models/...:generateContent` 时才允许补发一次 Gemini 原生请求；这只是上游明确
> 拒绝当前请求形状后的协议兜底，不能重发 `/images/generations` 付费 POST。其他嵌套错误
> 直接按 HTTP 400 原文上抛，不能因缺少内层 `task_id` 归成 `execution/accepted`。
> Gemini 的异步字段只发 `aspect_ratio / image_size`，不混发只属于 GPT Image 像素口径的
> `size`。`nano-banana-pro` 前缀与 `gemini-3-pro-image` 共用同一份能力表。

> **2026-11-12 Agent 设计调研结果层（对账 #1025–#1029）**：`tavilySearch.ts` 的固定设计检索以 `designReferenceSites.ts` 的 12 个域名为 `include_domains`，不再由 `designResearchRunner.ts` 回退到 Openverse/Wikipedia 等非固定来源。`conversation.ts` 最多保留 48 条研究候选；`ResearchResultsPreview.tsx` 只渲染紧凑入口，网页来源由 `ResearchSourcesDrawer.tsx` 以 portal 右侧抽屉呈现，图片由 `ResearchGalleryOverlay.tsx` 以独立瀑布流层呈现。图片下载、发送到对话和会话引用追加由 `useAgentResearchReferenceController.ts` 编排；瀑布流、抽屉和图片结果都不进入 Agent 消息滚动容器，避免撑宽对话流。创作提示词编辑器与 `MentionEditor` 统一 `min-width:0 / overflow-x:hidden / overflow-wrap:anywhere`，长提示词只能纵向滚动。

> **2026-11-24 画布手势快路径清理（perf-audit ①–④）**：删除平移期第二套边渲染器（`FlowViewportEdgeLayer`/`coarseEdges.ts`，平移时一直用 React Flow 原生边）、prompt 节点平移 Canvas 快照（`FlowPromptGestureCanvas`）、手势期 `.react-flow__viewport` 的 `will-change`，以及永远不生效的 coarse 死代码（`FlowCoarseNode`、`QhCoarseEdge`、`FlowCoarseEdgeLayer`、`detailMode.ts`、`useCanvasDetailMode.ts`、`flowGestureWindow.ts`）。保留 content-visibility 剔除、投影复用、4px 平移阈值、滚轮防抖、header 层手势期 will-change、拖动 DOM follower、port 层暂停；手势期背景替换与 `contain` 切换（⑤⑥）未动。

> **2026-11-24 桌面开发壳冷启动看门狗（对账 #1190）**：`start_ui_watchdog()` 的首次检查宽限按构建档位分开。
> debug 构建等待 90 秒，给 WebView2 + Vite 冷转换留出空间；release 继续等待 20 秒。首次宽限之后仍是每 5 秒检查、
> 20 秒无心跳判定、自动 reload（release 第二次失败重启）的原策略。开发日志必须打印实际宽限，诊断白屏先确认看门狗
> 是否真的触发，不要把 `#root=0` 的短暂加载态误判成业务渲染崩溃。

> **2026-11-24 多选拖动与 React Flow 原生组选框（对账 #1191）**：项目使用 `MultiSelectBar` 后，React Flow 自带的
> `.react-flow__nodesselection` 只能隐藏，不能让它接管多选区域。它与单节点拖动不是同一条路径，会绕过 direct-drag
> 与位置批次结算，造成图片、标题、端口和 store 分层。direct-drag follower 还必须单独捕获 `[data-multi-select]`：
> 多选栏和左右共有端点使用屏幕增量，标题 / 端口使用世界增量，松手再由 store 接管最终位置。验证必须从真实
> Ctrl 框选开始，不能只调 store 设置选择。

> **2026-11-24 多选灯箱交叉淡化与中心锚点（对账 #1192）**：灯箱画廊切图必须先保留旧媒体克隆，等新 hash
> 的媒体解码完成后再做 `160ms` 双向 opacity 交叉淡化；新 hash 首帧不得复用旧素材元数据，减少动效时直接替换。
> 未手动操作的视口若仍等于上一张的 fit，下一张必须按自身比例重新 fit，不能继承上一张 zoom；已手动缩放 / 平移后，
> 切图才按 `((next.w - previous.w) / 2, (next.h - previous.h) / 2)` 平移并保持 zoom，使
> `(w / 2 - viewport.x) × zoom` 定义的媒体中心连续。该数学住在 `gallerySwitchViewport()` 纯函数中，
> 手势协调器只负责状态分派。

> **2026-11-24 拖动后跨节点点击的浮层复位（对账 #1193）**：pointerdown 时若点击的是另一个节点，
> React Flow 的最终 selection 尚未落地，禁止提前清除 `panelDismissed`，否则旧节点功能栏 / 创作面板会先复活一帧。
> 只有重复点击当前唯一选中节点才返回 `dismissPanel=true`；跨节点与多选切换保持隐藏，由随后的
> `setSelection` 一次打开新节点浮层。真实点击回归必须拉开 pointerdown / pointerup。

> **2026-11-24 拖动边 DOM 重绑与灯箱源快照统一（对账 #1194 / #1195）**：direct-drag follower 不能永久持有
> 边 path 引用；选中态重渲染替换 path 后要按 edge id 重绑当前线、命中线和删除按钮。灯箱源快照统一走
> `lightboxSourceRectForNode()`，同时携带矩形、圆角、图片 / 视频类型、当前 URL 与 hash；功能栏预览和双击
> 必须使用同一份快照，才能保证首帧与动画一致。

> **2026-11-24 灯箱全部打开入口共用源快照（对账 #1197）**：`LightboxSourceRectSnapshot` 由
> `domain/canvas/model/lightbox.ts` 定义，`CanvasLightboxState` 由 `state/workbenches/canvas/lightboxState.ts`
> 统一拥有。查看、提取选区、裁剪、框脸、旋转、标注、多选画廊与深链打开 API 都必须接收同一份 `sourceRect`；
> 功能栏、右键菜单、创作面板、Agent 工具等节点调用方只允许通过 `lightboxSourceRectForNode()` 取快照；
> 运行日志与 Agent 活动缩略图通过 `lightboxSourceRectForThumbnail()` 取按钮内真实媒体矩形。
> 灯箱不得按入口另造动画分支，首帧连续性统一由源矩形、源媒体 URL 与 hash 决定。

> **2026-11-25 日志灯箱目标框稳定后再演出（对账 #1199 二次修复）**：目标媒体元素已挂载时，
> `lightboxFlipController` 只能使用 `settledMediaRect()` 的 inline 宽高，不得回退到预测框；矩形连续两帧

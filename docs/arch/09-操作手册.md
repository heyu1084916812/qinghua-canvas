**兑现状态（M6-2 comic 数据模型 v2）**：

- **领域层**：`domain/comic/model/comicProject.ts` 升 v2 —— 项目级 `readingDirection` + `characters`（角色卡库，跨格复用外观保 AI 生成一致性）；页级 `layout`（切割树，`LayoutLeaf` **只持 `panelId`**）+ `panels`（内容池，**版式与内容解耦**）；格级**三层分离** `scene`（喂生图）/ `shot`（景别·机位·转场，字段化）/ `balloons`（对白贴纸，**0..1 相对坐标**，不烘进图）。词表常量、工厂、`normalizeComicProject` 读回归一化同处一文件。
- **阅读顺序是派生量**：`domain/comic/layout/readingOrder.ts` 提供 `readingOrderOf(page, direction)` —— `h` 切（上下分行）恒「上→下」不随方向翻转，`v` 切（左右分列）在 RTL 下翻转列序（递归镜像）；**必须显式传方向**（不做默认，避免静默错序）。编辑器因此只需按几何顺序追加 `children`（`[0]` 恒为最左/最上）。这是 comic 领域第一个「纯函数 + 强语义」模块，与画布 `layout/culling.ts` 同级。
- **reducer 形态与画布不同**：comic reducer **返回下一个 `ComicProject`**，不产 `CommandResult`/补丁——comic 是**聚合对象、无补丁模型**（同 §9.4 持久化选型理由）。约定「不可变更新 + 无变化返回原引用」，store 侧靠 `next !== prev` 判断是否落库（避免空写）。删除角色卡会**级联清除引用**（格的 `characterIds` + 对白的 `speakerId`）。
- **读回迁移不做版本号**：`normalizeComicProject` **只补默认、只增不删**、未知字段忽略。等首次出现「有真实数据需要差异化迁移」时再引入 `schemaVersion`，现在不写永远走不到的分支。
- **代价与验证**：门禁全绿（182 modules / 662 deps，`no-shared-to-workbench` 规则仍 0 违规）、单测 54 文件 / 467 通过、冒烟新增 **G27**（角色卡 CRUD + 阅读方向 + 刷新读回）15/15、G26 无回归、构建 `ComicPage` chunk 5.9KB 仍独立。

**兑现状态（M6-3 页版式编辑器）**：

- **领域层新增两个纯函数**：`domain/comic/layout/layoutEdit.ts` 回答「每格占页面哪块」（几何）+「怎么切 / 删」（编辑）——`layoutRects` 由切割树算 0..1 页内相对矩形，`splitLeaf` / `removeLeaf` / `instantiateFullPage` 做树编辑，`divisionRatios` 管分割比。与既有 `readingOrder.ts` 分工明确：**一个管顺序、一个管几何**。
- **「几何」与「顺序」彻底解耦（本组最重要的架构决定）**：`h` 切沿 y 轴分行、`v` 切沿 x 轴分列，`children[0]` 恒为最上 / 最左——几何只看 `children.length`，**不看 `count` 字段**（`count` 仅 `equal` 时参与等分）。**RTL 只重排阅读序号、不移动几何**：位置是画出来的、顺序是读出来的。编辑器因此只需按几何序追加子节点，无需为日漫调换 `children`。

- **从「装饰动效」推进到「直接操作」**：M6-7 的翻页动效只管「翻完之后怎么进场」，输入方式仍是按钮 / 键盘。M6-10 补上**按住拖**——跟手位移 + 阈值判定 + 回弹。判定全在纯函数 `domain/comic/reader/dragNav.ts`：`dragAxis`（**只接管横向手势**，纵向留给滚动）/ `dragIntent`（屏幕方向 → 叙事位移 ±1）/ `dragTurnOffset`（跟手位移，夹 ±72；越界阻尼 0.22 vs 0.55）/ `dragTurnVerdict`（松手：翻 or 回弹，越界 `null`）。
- **与按钮 / 键盘同源是本组的核心约束**：屏幕方向 → 叙事位移的换算与 `readerNav` 是同一套口径（`ltr` 往左拖 = 下一页 ≡ 「`rtl` 下 `←` 才是前进」），所以**拖不出第二种翻法**；边界同样返回「无动作」（阻尼更小 + 松手不翻），而不是夹回或假成功。
- **手势让位**：`dragAxis` 先判主轴，纵向手势一律不接管——阅读器舞台是可滚动的（`overflow: auto`），否则拖页会吃掉滚动。CSS 侧配 `touch-action: pan-y`。
- **过渡只在「没在拖」时加**：拖拽中加 `transition` 会变成「慢半拍地跟手」，故用 `:not([data-comic-reader-dragging])` 限定；`prefers-reduced-motion` 下关掉翻页动画与回弹过渡，但**保留拖拽跟手**——它是直接操作的反馈，不是装饰动效。
- **不加命令、不改数据**：拖拽位移与页序 / 版式同级，都是本地 UI 态。
- **刻意不做「卷页 / 3D 翻折」式真实翻页**：纯装饰，需要离屏渲染或 3D 折面，成本高，且 reduced-motion 下必然退化。
- **代价与验证**：冒烟新增 **G35 27/27**（拖 140 跟手 -72 → 松手翻页；拖 20 跟手 -11 → 回弹不翻；首页往前拖阻尼 31 → 不翻；纵向手势位移恒 0；末页往后拖不翻；按钮 / 键盘仍可用；RTL 下往右拖才是前进）——**跟手位移用 `data-comic-reader-drag-offset` 暴露成数字断言**，不必截图比对。

**兑现状态（M6-11 导出页码）**：

- **页码不进画面**：勾选「页码」（默认关）后，`renderSheetSvg` 在**每页下方延伸一条页脚带**（`pageNumberBand` = 页高 4.5%），页码画在带子里——格子几何、底图、对白层的渲染**一个坐标都不用动**。`sheetDimensions` 同步加高，光栅化尺寸与 SVG 由**同一个布尔**推出，不会出现「SVG 有带子、canvas 却按旧高裁掉」的错位。
- **页码文案不在 `sheetSvg` 里算**：`SheetSvgInput.pageNumbers` 收**现成的文案数组**（接线层用 `pageBadgeText` 从 `pageIndices` 生成），长度不匹配**整体不打**——宁可缺号，也不把号打到错的页上。这使「缩略角标」与「导出页脚」共用 `model/pageNumber` 的**同一个函数**：总览看到的号与导出图上的号从定义上不可能不一致。
- **`pageBadgeText` 上移**：从 `overview/thumbnail` 移到 `model/pageNumber`（叙事页码是模型概念而非缩略概念），`thumbnail.ts` re-export 兼容既有调用点——**既有单测与 G34 零改动通过**。
- **锚点按视觉槽位**：`pageNumberAnchor(slot, pageCount, direction)`——跨页时槽 0 左、槽 1 右（帖切口侧，像摊开的书）；单页无中缝可参照，退化为阅读终点侧（`ltr` 右 / `rtl` 左）。**与页序无关**：`rtl` 下槽 0 放的是较晚的页，页码仍在左。

**兑现状态（M6-12 渠道层消费 `inputs`）**：

- **本质是补一条跨层的洞**：`RunRequest.inputs` 自 M2 起就完整携带文本 / 素材 / 集合三类输入，但**渠道适配层从未读过它**——`openaiImages` 只发 `prompt`。于是「图生图 / 角色参考图」在数据模型里接好了、在真实链路里从未生效。**这类洞最危险**：它不报错、不失败，只是悄悄不生效。
- **规则收口成纯函数**（`domain/shared/execution/inputs.ts`）：`flattenInputs`（摊平集合，含嵌套）/ `imageInputsOf`（只留图像 mime → 按 `assetHash` 去重 → 截断到 `MAX_IMAGE_INPUTS = 4`）。放 domain 的理由与 `readerNav` 相同：渠道层不该各写一套过滤，否则「哪张图会被传」会随渠道漂移。`collectionItemId` **刻意不参与去重**——它区分的是「同一 plan 里的第几次调用」，而这里处理的是单次调用内部。
- **新端口 `AssetPort`**（`platform/assets.ts`）：`hash → { bytes, mime }`。渠道不再直接查 `assets` 表（不用知道「id 即 hash」、不用处理 `Uint8Array` / `ArrayBuffer` / 数组三种克隆形态）。它进 `PlatformKit`，web / memory 两个装配处各加一行，**共用同一份实现**（只依赖 `StoragePort`）。
- **`ChannelDeps` 改成 `Pick<PlatformKit, 'network' \| 'assets'>`**：刻意用 `Pick` 而非新造结构——装配处（两个 ExecutionProvider + channelStore）直接把整个 `platform` 传进去，无需逐个字段搬运，也不会漏传。
- **`NetworkPort` 必须能发 multipart**：此前 `fetchNetwork` 对 `body` 一律 `JSON.stringify`，渠道层**结构上不可能**上传文件。`NetworkRequest.body` 类型不动（仍是 `unknown`），改为识别 `FormData` / `Blob` / `ArrayBuffer` / `URLSearchParams` 并原样透传；**关键细节**：原样体一律清掉调用方自带的 `Content-Type`——`multipart/form-data` 的 boundary 只能由 fetch 依 FormData 生成，手写会让服务端分不出段。
- **端点分叉而非参数分支**：`openaiImages` 拆成 `postEdits`（multipart，重复 `image` 字段）/ `postGenerations`（JSON，与 M6-12 前逐字一致）。**刻意不做的静默降级**：`edits` 返回 404/405 **如实抛错**，不悄悄改回 `generations`——否则用户以为参考图生效了，实际被丢掉（与 M6-9「假字节」是同一类教训）。唯一允许的回落是「素材读不到」（未落库 / 已清理），因为那时确实无图可传。
- **canvas 侧补最后一段**：`generationSpec.collectInputs` 此前只收 `prompt` 文本与 `batch` 集合，**把上游 `generation` 节点的产物漏掉了**——连线合法（`accepts.upstream` 早含 `generation`）却收不到图。补齐后顺带得到一个正确副作用：上游重生成 → `assetHash` 变 → 下游指纹变 → 自动判定陈旧。
- **假数据要能证明「有没有生效」**：mock 渠道在带图像输入时改吐**品红 8×8 真 PNG**（无输入仍是灰度），**hash 规则不变**（既有按 hash 断言的测试零改动）。这样冒烟只要采样像素就能断言「inputs 真的被消费了」——若 mock 无视 inputs 一律出同样的图，这条链路在离线环境下**永远证明不了**。
- **代价与验证**：门禁全绿（**214 modules / 778 deps**、0 违规）、单测 70 文件 / **711 通过**（+30：输入提纯 9、素材读回 4、mock 可观测 5、openai 双端点 7、规格收图 4、模板 1）；冒烟新增 **G37 11/11**——图生图模板两节点已连线 → 底图生成 → 下游生成 → **采样像素：底图 `154,154,154`（灰）、下游 `230,46,139`（品红）**，用产物颜色证明链路真的通了。

**兑现状态（M6-13 角色卡参考图上传）**：

- **补的是「有模型、没入口」**：`referenceHashes` 自 M6-2 就在 `ComicCharacter` 里，命令层 `character.update` 也一直支持 `referenceHashes` patch，M6-12 更让渠道真的会读它——但**没有任何界面能把一张图放进角色卡**。本组只做这个入口，**不动数据模型、不加命令**。
- **上传器与角色卡分属两层，在界面接线**（`surface/characterRefUpload.ts`）：上传器只管「一张图 → 素材库一行」，依赖注入 `pickFile` / `putAsset` 两件口——**因此无需浏览器与 IndexedDB 即可单测**（node 环境注入假实现）。把 hash 追加进 `referenceHashes` 是 surface 经 `character.update` 派发的事。**命令层不认识 `Blob`，素材层也不认识角色卡**，中间靠 hash 这个稳定标识解耦。
- **素材落库不走命令，直写 `assets` 表**：与 `ComicExecutionProvider` 写生成产物**同一条路径**。原因是结构性的——comic 的 reducer 只返回下一个 `ComicProject`（单聚合对象、无补丁流），**没有携带「素材写」的通道**；素材本就与项目文档分离落库（`assets` 表 vs `comics` 表）。所以「上传」不需要也不会给 comic 引入 `asset.put` 命令。
- **内容寻址带来的幂等**：`fingerprintBytes(bytes) = sha1Bytes(bytes).slice(0,16)`——与生成产物同一口径（同截 16 hex），使「用户上传的图」与「AI 生成的图」在 `assets` 表里长得一样：**id 即内容哈希**。于是同图重传是幂等 upsert（不产生第二行），换文件名再传也不会被当成新图。这与 `fingerprintHex(model|prompt|idx)`（**请求**指纹：同参同果）是两件事，注释里写明了区别。
  - **M6-26 起 `fingerprintBytes` 是异步的**：优先走 `crypto.subtle.digest('SHA-1', …)`（原生线程算，7MB 实测 4ms），环境不支持时回落同文件里的纯 JS `sha1Bytes`。纯 JS 版要对**全部字节**跑 80 轮且同步执行，7MB 会阻塞主线程 233ms——连传几张就是肉眼可见的卡死，还会顺带推迟持久化计时器。**两条路径都是标准 SHA-1、哈希值一致**（`hash.test.ts` 用固定向量钉住），否则同一张图会存出两行、内容寻址失效。
- **去重语义收在模型层**：`addCharacterReference` / `removeCharacterReference` 在「已在列表里 / 本来就不在」时**返回原数组引用**。这不是省内存的小技巧——comic 的 `updateCharacter` 正是靠 `next.referenceHashes !== prev.referenceHashes`（**引用比较**）判断「是否要重写项目文档」；若此处无条件新建数组，重复添加同一张图会被当成真改动、白写一次库。
- **渲染复用同一条读素材路径**：缩略用 `useAsset(hash)`（与格底图、一话总览相同），因此「这张图从哪来」不影响「怎么读它」；未落库时先占位、退避重试到位后自动补上（与格底图同款竞态窗口）。
- **代价与验证**：门禁全绿（**215 modules / 783 deps**、0 违规）、单测 71 文件 / **726 通过**（+15：参考图列表语义 7、上传器 8——含 `sha1("abc")` 固定向量）；冒烟新增 **G38 16/16**——`filechooser` 注入一张真灰度 PNG → 缩略 `naturalWidth = 8` 且采样 `154,154,154`（字节确实经素材表回到 UI）→ 刷新后参考图与素材行都在 → 勾角色生成出**品红 `230,46,139`**（参考图真的成了渠道图像输入）→ **A/B 对照**：取消勾选角色再生成即回落 `154,154,154`（证明变色确由参考图引起）→ 移除后归零。

**兑现状态（M6-14 对白贴纸的尺寸手柄与拖尾巴改指向）**：

- **补的是 M6-4 的两条直接操作**：`ComicBalloon` 的 `x/y/w/h/tail` 一直都在模型里，但界面只能改 `x/y`（拖位置）——**尺寸建出来就定死**，`tail` 只能跟着平移。本组把「尺寸」与「尾巴指向」也变成可改，**模型与持久化一个字段都没动**。
- **三条直接操作 = 三条命令**：`balloon.move`（位置）/ `balloon.resize`（尺寸，`w/h`）/ `balloon.moveTail`（尾巴锚点）。**刻意不合并成一个 `patch`**：「位置 / 尺寸 / 尾巴」是一组**正交自由度**，各自的调用时机（哪个手柄被按住）与几何规则都不同，合并只会让 reducer 里长出 `if (patch.w !== undefined && patch.x === undefined)` 式的分支。三条都保持「无变化返回原引用」。
- **几何规则收在 domain 纯函数**（`domain/comic/panel/balloonLayout.ts`）：`resizedBalloonRect(balloon, w, h)`（**左上角固定**，尺寸夹 `[BALLOON_MIN_W/H, 1]`、位置随之夹回格内，尾巴按**相对比例**跟随）与 `movedTail(balloon, x, y)`（夹进 `[0,1]`；**无尾巴返 `null`** —— 让「不可拖」与「拖了但没动」在类型上就分得开）。reducer 侧抽 `withBalloonRect` 供 `move` / `resize` 共用，几何写回只有一处。
- **一条不变量、两个变换**：气泡与尾巴**作为一体**参与平移与缩放——平移保持尾巴的*相对偏移*（M6-4 的 `movedBalloonRect`），缩放保持尾巴的*相对比例*（新的 `resizedBalloonRect`）。于是**唯一**能改变尾巴相对位置的操作就是 `moveTail`。这条不变量不是美学偏好：少了它，`move` 会让尾巴留在原地、`resize` 会把尾巴甩进气泡里，两个 bug 会各自冒出来。
- **UI 侧：拖拽状态机从「一种」变成「三种」，且预览与提交同源**（`BalloonLayer.tsx`）：`Drag` 记录 `mode: 'move'|'resize'|'tail'` + **起点快照** `base` + 抓取偏移，指针移动时调的就是 domain 的那三个纯函数，松手时 `endDrag` 把**同一份结果**抛给对应的回调。于是不可能出现「手指底下是一个样、松手落库是另一个样」——**预览与提交共用一条代码路径**，而不是两套近似实现。仍保持「松手才提交一次」（拖动不逐帧写库）。
- **只在可交互时渲染手柄、且尾巴的堆叠分两态**：手柄只画在**选中格**的贴纸上（`interactive`），只读态（其余格 / 翻页预览）保持原有的干净贴纸。尾巴只读时画在气泡**下面**（只露尖角，与原视觉一致），可交互时改画在**上面**并把命中区放大到 13px——否则尾巴一旦被拖进气泡里就再也没法抓回来；同一原因，可交互态尾巴底色换深一档（白底白框在气泡上等于隐身）。
- **尺寸手柄贴内摆放**：手柄用 `transform: translate(-100%,-100%)` **完全落在贴纸内侧**。格子上有 `overflow:hidden`，骑在角上的手柄会被裁掉一半、按不稳（15px 的舞台边缘问题在 10px 手柄上更致命）。
- **代价与验证**：门禁全绿（**215 modules / 783 deps**、0 违规——只改既有文件，未新增模块）、单测 71 文件 / **741 通过**（+15：几何 9、reducer 6）；冒烟新增 **G39 17/17**——拖右下角手柄后 `w/h` 变大且**左上角不动**、尾巴跟到新的下缘中点（一体变换不变量），拖尾巴后**锚点变而尺寸与位置一个都不动**（A/B 对照），旁白不长尾巴手柄但仍有尺寸手柄，刷新读回尺寸与尾巴锚点。

**兑现状态（M6-15 生成留痕与版本回退）**：

- **补的是 `record` 返 `null` 的洞**：M6-5 把落位/写回抽成 `ExecutionPlacement` 时，comic 侧 `record` 直接返回 `null`（文档写明「尚未引入版本历史」）。后果不是「少个功能」而是**不可逆数据丢失**——重生成覆盖 `assetHash` 后，上一版画面再没有指针指向它（字节仍在 `assets` 表，成为孤儿）。本组把它补上，并给出回退入口。
- **留痕的存储位置由数据形态决定**（延续 §9.4 的选型通则）：画布是「图 + 补丁流」双存储 → 留痕另落 `runRecords` 表；comic 是**单聚合对象、单写通道**（整对象防抖落 `comics` 一行）→ 留痕作为格的内部字段 `ComicPanel.runs`，随项目文档一起读回 / 导出 / 归一化。**不为留痕给 comic 另开表**：那会在同一份聚合体内制造第二条写通道，「整对象覆盖写」的简单性立刻消失。
- **三条不变量**（写在 `panelRunRecord.ts` 头部，测试逐条落锁）：
  1. **只增不减**——任何操作不删留痕（产品文档 §6.21）。删一条 = 那一版产物成孤儿。
  2. **版本号由历史自身推出**（`nextPanelRunVersion` 取 max+1），**不由调用方给**。这条用**类型**强制：载荷类型 `PanelRunInput = Omit<ComicPanelRun,'version'>`，调用方**拿不到**指定版本号的途径，因而构造不出「两条 v3」或跳号——这类错误**界面上看不出来**（行数对得上），只在「回退到 v3 却回到另一版」时暴露。
  3. **回退本身追加为新版本**——`restorePanelRun` 写回目标版本的输入与产物后**追加一条新留痕**，而不是把面板指针拨回去。于是历史永远是一条只增的时间线，没有「重写历史」这种状态，也就不需要 undo 栈兜底（comic `canUndo()` 恒 false）。
- **纯度处理**：留痕是纯函数（无 IO / 时间 / 随机），**时间与 id 由调用方传**（`PanelRunStart { newRunId, createdAt }`）；`append` 的时间来自引擎 `RunRecord.createdAt`，`restore` 的由 UI 派发时给（`createId('run')` + `Date.now()`）。因此 comic reducer 保持纯函数，单测能直接断言版本号序列。
- **快照口径 = 影响画面的字段**：`scene` / `framing` / `angle` / `characterIds` / `channelId` / `model` / `referenceHashes` / `fingerprint` / `outputHashes`。**刻意不含** `balloons`（不烘进图——与 `panel.setAsset` 只动 `assetHash` 同一原则）与 `transition`（「与上一格的叙事关系」，不是画面输入；回退时**保留面板当前转场**）。
- **回退守门 `canRestorePanelRun`**：只放行 `succeeded && outputHashes.length > 0`。失败 / 取消那次没有画面，写回 `assetHash` 等于「回退到一张不存在的图」；而「恢复配置 ≠ 恢复画面」又是另一种语义——混进同一条路径会让「回退」一次表示两件事。故失败版本**如实留痕但界面灰掉**并写明原因。
- **两条命令、零数据迁移**：`panel.runRecord.append`（载荷**不含 version**）与 `panel.runRecord.restore`（`runId` + `newRunId` + `createdAt`）。两者在「不可回退 / 未命中 panelId」时**返回原引用**——`mapPanel` 整树短路，store 靠 `next !== prev` 判出「无变化」，既不产生假留痕也不空写库。`normalizePanelRun` **只补不删**（缺 `runs` 补空数组、`version` 缺省 1、`status` 不在词表回落 `succeeded`），旧项目读回即成形。
- **共享词表上收**：`RUN_STATUSES` 加到 `domain/shared/execution/types.ts`，comic 的 `PanelRunStatus` 直接别名共享 `RunStatus`（**不复制联合**），中文标签 `PANEL_RUN_STATUS_LABELS` 配 `assertComplete(RUN_STATUSES, …)` 完备性断言——新增状态忘了配标签会被单测拦住。
- **`assetHash` 与 `livePanelRun` 的分工**：前者是**画面**的真相（渲染只看它），后者是**历史**的真相（列表给哪行打「当前」）。正常一致；唯一分叉是「某次成功但渠道没回图」——画面为空而历史仍指向上一个真正出过图的版本。这个分工让「当前」标记不依赖渲染层推断。
- **代价与验证**：门禁全绿（**216 modules / 796 deps**、0 违规，新增 1 模块 `domain/comic/panel/panelRunRecord.ts`——只 import 同域 `../model/comicProject` 与共享域 `../../shared/execution/*`，`domain-pure` 与 `no-shared-to-workbench` 均满足）、单测 72 文件 / **779 通过**（+38：域 30 + reducer 7 + 端到端扩断言）、构建 `ComicPage` chunk 54.55 kB 仍独立；冒烟新增 **G40 32/32**——生成后历史 1 条 v1「当前」→ 改描述再生成历史 2 条且当前移到 v2、v1 可回退 → 点缩略开 / 关大图浮层 → **点 v1 回退：描述回到 v1、底图仍渲染、历史变 3 条（v1/v2 都还在）** → 刷新后 3 条与当前指向均读回。
- **一处测试陷阱（值得记住）**：构造「画面已被改过、但历史还在」的面板夹具时，`{ ...p, ...base }` 会让 `base` 的空 `runs` **覆盖掉历史**——正确写法是 `{ ...base, runs: p.runs }`。展开顺序错在这类「同一对象的两个来源」夹具上极容易埋雷，且症状是「被测函数看着没生效」，很容易误判为生产代码 bug。
- **推迟项（如实记账）**：留痕**裁剪 / 删除**（历史只增，长项目文档会持续变大；真要做须先回答「删了之后的产物怎么办」）、**两版并排对比**、**从留痕一键复制输入到别的格**、回退时的**产物缩略图缓存策略**。

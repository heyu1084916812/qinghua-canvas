## 6. 事件与错误

### 6.1 事件流 · ✅ 已实现

| 来源 | 去向 | 通道 |
| --- | --- | --- |
| 节点视图 | 页面容器 | `emit(event)` 回调 prop |
| 页面容器 | 状态 | `dispatch(command)` |
| 交互控制器 | 状态 | `dispatch(command)` / `setSelection()` / `setViewport()`（瞬态走独立 API） |
| 状态 | 渲染 | store 订阅 |
| 状态 | 持久化 | `persistenceService` 订阅 |
| 执行引擎 | 状态 | `writeBack(commands[])` 由页面装配层传入的 dispatch 包装器（runEngine 不依赖 dispatch） |
| 陈旧订阅 | 状态 | `stale.mark` / `stale.clear`（走 dispatch 但不入 undo 栈） |

跨模块的直接函数调用保持在同层内；跨层一律走上述通道。

### 6.1.1 并发生成（已实现）

**一条计划 = 一条独立链路**。`useExecution` 不再只持有单个 `runningPlanId` / `AbortController`，而是按 planId 建表（`features/shared/execution/runRegistry.ts`，纯数据 + 单测）：

| 层 | 职责 |
| --- | --- |
| `useExecution` | `controllers: RunRegistry<AbortController>`；`startRun` 各自登记、各自清理，`isRunning` = 表非空 |
| `CanvasExecutionProvider` | `adapterMaps: planId → (channelId → adapter)`、`taskToNodeMaps: planId → (taskId → nodeId)`；`channelResolver(request, planId)` 按**本计划**取适配器，互不覆盖 |
| `CreationPanel` | 本节点运行才禁用/变取消；**其他节点在跑不再禁用本节点按钮**（`globalRunning` 不再作为禁用理由） |

这样「一个节点生成时另一个节点无法生成」的三个成因（单槽位 controller、单一适配器表、界面全局禁用）被逐一拆掉，且每层的契约都能脱离 React 断言。

### 6.2 错误分类 · ✅ 已实现

```ts
// shared/result.ts
export type AppError =
  | { kind: 'network'; detail: 'dns' | 'tls' | 'cors' | 'timeout' | 'aborted' }
  | { kind: 'http'; status: number; body?: string }
  | { kind: 'parse'; raw: string }
  | { kind: 'storage'; detail: 'quota' | 'corrupt' | 'permission' }
  | { kind: 'validation'; field: string; reason: string }
  | { kind: 'channel'; detail: 'missingKey' | 'missingModel' | 'unsupported' }
```

错误在产生处分类，在展示处映射文案。网络层不抛裸 Error，UI 不做 HTTP 状态码判断。
